# 可读性与排版指南（三速读者设计）

报告的可读性不是装饰，是分发效果的一半。同一份报告会被三种速度的读者打开，
排版的任务是让每种读者都在自己的时间预算内拿到完整主干。

## 设计目标：一份报告服务三种读速

| 读者 | 场景 | 只看什么 | 对写作的要求 |
|---|---|---|---|
| 10 秒读者 | 领导手机上刷到 | 彩色 callout 块 + 图表 + 章节标题 | 每章核心结论必须进 callout；图注直接写结论 |
| 3 分钟读者 | 评审/讨论前过一遍 | 上述 + 表格 + 加粗锚点 + 判读块 | 表格三列动作导向；加粗短语连起来能复述报告 |
| 15 分钟读者 | 要承接方案的人 | 全文 + 用户原声 + 附录数据 | 原声可回查、数字可复算 |

交付前自检：**只看彩色块、图表和标题，能否拿到全部主干结论？** 不能，就说明有结论埋在正文段落里，把它提炼进 callout。

## Callout 语义体系

用引用块 + 固定 emoji 开头，让每类信息有稳定的视觉身份。写入 Lark 时升级为对应底色的高亮块（callout）：

| 标记 | 用途 | 典型位置 | Lark 底色 |
|---|---|---|---|
| 🎯 | 核心结论 / 产品含义 | 报告开头一句话结论；每条洞察后的"产品含义" | 黄 |
| 🔍 | 判读（数据之后的人工判断） | 每张表、每组原声之后 | 灰 |
| 💡 | 关联与提醒 | 与现有 roadmap 的重合；数据折损警示 | 蓝（关联）/ 红（警示） |
| 📐 | 口径与方法说明 | 双口径声明、统计口径注记 | 蓝 |
| 🏆 | 全文最高优先级的判断 | 最值得投入的主题判读 | 黄 |
| 🚫 | 明确不建议做 | 机会点章节末尾 | 红 |
| 📌 | 来源与附录信息 | 文末数据源说明 | 灰 |

写法纪律：callout 内部要**完整成句、可被单独截图引用**（它就是会被单独截图的）；
一章最多 2–3 个——callout 的效力来自稀缺，满屏彩色块等于没有彩色块。

## 三张标配图表

图表在这套方法论里不是配饰，是"10 秒读者的正文"。每张图必须**携带观点**：
用高亮表达立场，用图注写出结论。纯中性的统计图是浪费版面。

**1. 样本构成图**（放 §2 样本体检）
- 形式：华夫点阵图（一个点 = 一条数据，按"模板复制 / 灌水 / 有效原创"着色）或堆叠条形图
- 为什么点阵：读者能"数出来"每 5 条里有 1 条是复制——比例变成了体感
- 图注写结论："去掉模板与灌水后，最终得到 N 条有效独立想法（占 X%）"

**2. 分布条形图**（放 §3 主题全景与原语排行）
- 形式：横向条形，按占比降序，条末标注 `X% · N 条`
- **高亮即立场**：后文列为 P0 方向的条目涂主色，被判为"被低估"的用强调色，其余一律置灰；
  图例写明高亮含义（如"蓝色 = 第 7 节列为 P0 的主题"）
- 这样图表自己就在讲"声量 ≠ 优先级"——不需要读者读到第 7 节才明白

**3. 结构流程图**（放核心主题的深读小节）
- 触发条件：当一个发现的本质是"链条"（触发 → 中间物 → 动作）且多位用户重复描述同一结构时
- 文字描述结构永远不如一张图；这张图往往会成为整份报告被引用最多的资产

数量纪律：全文图表 3–4 张封顶。图多了和 callout 多了一样，稀释注意力。
绘图工具不限（脚本出图、画板、Lark 画板皆可），风格保持同一套配色。

## 用户原声排版

```
> "原文保留原语言，**关键短语加粗**，让扫读者只读加粗也能抓住点。"
> —— @作者handle（一句点评，斜体：为什么挑这条 / 它妙在哪）
```

- 每主题 2–4 条；挑选标准是"最具体、最有情绪、表述最巧"，不是最长
- 点评括号是研究者的声音，和用户的声音用格式区分开
- 多人同表述时署名可写"多人同表述"，并在其后注明代表账号

## 标题与加粗纪律

- **章节标题结论化**：不写"主题 D 分析"，写"D. 可验证战绩——唯一带情绪的需求"。
  标题连起来读就是报告目录版的摘要。
- **洞察标题 = 判断句**："'AI' 在这批用户嘴里是形容词，不是名词"。
- **正文加粗每段不超过 1–2 处**，且加粗的必须是"只读加粗也能懂"的完整短语，
  不加粗孤立的形容词。
- **数字格式统一**：`54 条 · 21.2%`（间隔号分隔），口径随表标注，全文一致。

## 表格纪律

表格是 3 分钟读者的主干道。动作导向的三列式最好用：

| 场景 | 三列 |
|---|---|
| 机会点 | 机会点 \| 依据 \| 落地要点（或风险） |
| 精华条目 | 作者 \| 核心想法（起名 + 加粗）\| 为什么值得 |
| 方法交代 | 项目 \| 说明 \| （备注） |

"核心想法"列先给想法**起一个名字并加粗**（如 "Proof Mode"、"Market Replay"），
名字是想法的把手——被记住、被讨论、被采纳的都是有名字的想法。

## 写入 Lark 的映射备忘

- Markdown 引用块 → Lark callout 高亮块，按上表配底色；emoji 保留为块图标
- 加粗、表格、编号列表原样保留；避免依赖 Lark 不支持的 md 语法（脚注、任务列表）
- 图表以图片插入，图注作为图片下方的说明行
- 如环境有 lark 文档写入工具链，遵循其块级编辑规范，勿整文重导（会冲掉他人手动添加的内容）
