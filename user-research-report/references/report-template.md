# 用户研究报告 · 章节骨架与写法要点

骨架来自实战验证过的报告结构。标注了必选/可选：可选模块按数据类型和读者取舍。
章节编号仅示意，按实际内容增删。**排版元素（callout 语义、图表规格、加粗纪律）的细则
见 `style-guide.md`，本文只标注每节的"标配元素"。**

---

## 报告标题

`[产品/项目名] [数据源] 用户研究报告`。让读者 3 秒知道研究对象和数据来源。

## 0. 一句话结论（必选，放第一屏）

结构：🎯 总判断 callout → 2–4 条最强信号 → 📐 口径说明 → 💡 数据折损提醒。

- **总判断**：放进 🎯 callout，回答"用户到底在要什么"，最好带一个反直觉的转折
  （例："用户没有在要一个更好的社交产品，他们在要一个能解释行情、能验证战绩的交易辅助层"）。
  这个块会被单独截图转发，务必完整成句。
- **最强信号**：编号列表，每条 = 「短语命名」（书名号/引号包裹，方便被引用传播）+
  支撑数据（`N 条 · X%`）+ 一句判读。信号按强度排序，不按声量排序。
- **口径说明**：如全文使用两套口径，用 📐 callout 一次说清，正文各表随表标注。
- **折损提醒**：💡 callout 一句话交代噪音比例，防止读者把全量条数当有效声量。

## 1. 方法与数据可信度（必选）

一张两列表交代：抓取方式、抓取字段、覆盖率（抓到/平台显示）、打标方式、去噪方式。

**局限写在这一节，不藏在文末。** 常见必写项：
- 样本代表性（激励型样本偏任务党；语言/地区偏斜；参与者未必是产品真实用户）
- 数据时点（活动是否还在进行、数据是否还在增长）
- 结论定位声明：本报告适合做什么（机会发散/假设生成），不适合做什么（直接排优先级）

## 2. 样本体检（开放征集/评论区数据必选；访谈类可省）

标配元素：**样本构成图**（华夫点阵，见 style-guide）+ 构成数据行 + 集群表 + 🔍 判读。

- 构成数据行：`模板化 N 条 · X% ｜ 灌水 N 条 · Y% ｜ 有效独立想法 N 条 · Z%`
- 模板集群 Top N 表：复制次数 + 母版内容摘要
- 🔍 判读：能被大量复制说明文案好懂、诱人——是传播信号，但不是需求票数
- 身份异常明细（如有）：**默认只进内部档案版**，对外分发版删除，改为私下同步给活动主办团队

## 3. 需求主题全景（必选）

标配元素：**分布条形图**（高亮即立场：P0 方向涂主色、被低估的用强调色，图例说明含义）。

- 主题分布表：主题名 | 主标签数 | 提及数 | 占比 | 一句话概括（用用户的口吻写，带引号）
- 关键词原语排行（可选）：同样用高亮条形图。原语比主题更细，能暴露"横向诉求"
  （跨主题反复出现的词，如"新手也能看懂"）——发现横向诉求时加一个 🔍 判读点破它
- 所有表格注明口径（全量/去噪）

## 4. 主题深读 · 用户原声（必选，报告的肉）

每个重要主题一小节，结构：

- **小节标题带判断**：不写"主题A分析"，写"A——描述最一致、最可直接立项的需求"、
  "B——声量最大，但最'空'"。标题连起来读就是摘要。
- **用户原声 2–4 条**：引用块 + 关键短语加粗 + 斜体署名与点评（格式见 style-guide）。
  挑选标准：最具体、最有情绪、表述最巧，而不是最长。
- **结构流程图**（条件触发）：当该主题的核心是多位用户重复描述的同一条
  "触发 → 中间物 → 动作"链时，画成流程图。这张图会成为报告被引用最多的资产。
- **🔍 判读**：信号强度四要素评定；真需求还是许愿；落地分几档、成本差异。
- **💡 与现有工作的关联**（强烈建议）："这与我们已有的 X 能力/规划的关系"——
  这是报告从"外部声音"变成"内部行动"的桥。注意分发纪律：不主动关联敏感产品线。
- **🏆 判读**（全文最多一处）：留给最值得投入的主题，理由分点列出。

## 5. 精华回帖 Top N（可选，强烈建议）

表格：作者 | 核心想法 | 为什么值得。给每个想法**起名并加粗**（"Proof Mode"、"Market Replay"）——
有名字的想法才会被记住和采纳。筛选标准写在导语里（质量而非互动量）。
这份名单同时是种子用户名单。

## 6. 核心洞察（必选，报告的差异化价值）

功能清单之外的判断，常见类型：
- **心智定位**：用户把这个产品当成什么（决定北极星指标该是什么）
- **许愿词解构**：声量最大的词背后真正的动作是什么
- **横向诉求**：跨主题反复出现的隐性需求
- **能力复用**：用户想要的东西与内部已有能力的映射（哪些不用重造）

每条洞察的结构固定：**判断句标题 → 一段证据 → 🎯 产品含义 callout**。
产品含义必须是动作导向的（"指标应该是 X 而不是 Y"、"不要做 A，要做 B"）。
洞察数量 3–6 条，宁缺毋滥——洞察是"读完数据才能说出的话"，不是常识复述。

## 7. 机会点与优先级建议（必选）

- 分级标题格式：`P0 ｜ 确定性最高，建议直接立项`
- P0 / P1 用三列表：机会点 | 依据 | 落地要点（P1 第三列换成风险）
- P2（观察/品牌向）：加粗短语 + 括号一句话即可
- **明确不建议做**：用 🚫 callout，每条给理由（伪需求/成本/合规/时机）。
  与 P0 同等重要——它证明研究有判断力，也替读者省掉一轮争论。

分级依据是信号强度四要素 + 落地成本，不是声量。

## 8. 风险提示（必选）

编号列表，至少覆盖：数据代表性风险、声量陷阱（哪个高声量主题可能是伪需求）、
合规风险（用户诉求中触及监管边界的部分，如投资建议、真金对赌）。

## 附录（必选）

- **数据文件清单**：两列表——文件 | 内容（原始结构化数据、打标结果、可读全文清单）
- **数据源与抓取说明**：📌 callout——数据源链接、抓取时间、样本量与覆盖率、原帖数据、分析方法。
  **放文末，不放开头**——开头的黄金位置留给结论。

# 交付前双检

1. **数字回查**：报告引用的每个数字对数据重算一遍（详见 analysis-toolbox.md §7）。
2. **三速自检**：只看彩色 callout、图表和章节标题，能否拿到全部主干结论？
   不能，就把埋在正文里的结论提炼出来。

# 对外分发版的裁剪清单

从内部档案版生成对外版时，逐项检查：

1. 身份异常/刷量明细模块 → 删除（私下同步给相关团队）
2. 对活动机制、运营策略的批评与建议 → 删除
3. "建议的下一步"中涉及其他团队动作的条目 → 删除或改为本团队动作
4. 与敏感/边缘产品线的主动关联（复用建议、打通建议）→ 删除或降为中性事实描述
5. 最强信号的命名与条数 → 与群同步消息完全对齐
6. 全文搜索检查：确认没有残留"内部才该出现的词"（版本号、迭代过程、针对特定读者的表述）

# 群同步消息模板（三点式）

```
各位[项目名]的股东们，同步一个用户侧的好消息～

[一句话交代数据来源与规模，顺带把功劳记给发起方]，[一句正向肯定：用户对我们在做的事的热情/验证]。
[N] 条我们逐条精读完了，三个最重要的发现：

1. [短语A]：[一句发现]
2. [短语B]：[一句发现]。[一句承接：已在X期规划]
3. [短语C]：[一句发现]。[一句承接：作为Y的参考]

下一步：[发现A的承接——谁在调研、做什么、何时有产出]。[对当前开发节奏的保护性声明]

完整报告：[链接]
cc [需要知晓的领导]
```

要点：短语放冒号前方便高亮；每条发现都有去处；口吻是同步不是汇报；
正在赶工的团队要能从消息里读到"我们做的事被验证了"，而不是"又有新需求来了"。
消息里的短语命名必须与报告 §0 最强信号的命名一字不差。
