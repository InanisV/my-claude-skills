# 分析工具箱：程序化去噪、统计与校验

这些是 Phase 1–3 的程序化套路。原则：**程序做统计，人做判断**——聚类和计数交给脚本，
打标、判读、挑原声必须人工。所有阈值都是起点，按数据分布调整并人工抽查边界样本。

## 1. 取数字段清单

每条记录尽量拿到：

```
id / 作者 handle / 显示名 / 发布时间 / 全文（注意长文展开）/
点赞 / 曝光 / 回复数 / 是否带媒体 / 层级（一级回复 or 楼中楼）
```

平台无关的优先级：官方 API / 导出 > 页面数据接口（浏览器登录态下的 XHR/GraphQL 分页，
注意展开被折叠的低质量层）> 页面滚动截取（最后手段，虚拟滚动经常拿不全）。
无论哪种方式，最后都要对照平台显示的总数计算覆盖率。

## 2. 模板复制检测

```
规范化：小写 → 去链接/@提及/#话题/数字 → 去标点 → 分词（保留长度>2的词）
特征：4-gram shingle 集合
相似度：Jaccard = |A∩B| / |A∪B|
聚类：相似度 > 0.55 的对合并（并查集），得到复制集群
```

- 阈值 0.55 是经验起点：太高漏掉小改动的洗稿，太低把同类想法误判为复制。
  调整后人工抽查每个集群的边界成员。
- 输出：集群数、每集群条数与母版摘要、模板化总条数与占比。
- 统计"有效独立想法"时每个集群只计 1 条。

## 3. 身份异常检测（激励型征集）

- 从文本提取自报身份标识（UID、邮箱、钱包地址、订单号等，按活动要求定正则）。
- 同一标识出现在多个不同账号名下 → 批量参与信号。输出：复用标识数、涉及账号与条数。
- 辅助信号：发帖时间高度聚集、账号名相似模式、互动数据异常（高曝光零互动）。
- 此类明细默认只进内部档案版。

## 4. 关键词原语词表

主题标签之下再做一层更细的"需求原语"统计，暴露横向诉求：

- 先人工裸读一批（30–50 条）归纳候选词，再写正则词表（含同义变体），全量匹配算出现率。
- 词表必须按业务重建，不要照抄。举例（交易类产品曾用的一部分，仅示意结构）：
  `为什么在涨/在动`、`情绪/热度分`、`副驾/助手/教练`、`个性化信息流`、`一键下单/跟单`、
  `战绩可验证`、`新手/大白话`、`去噪`。
- 高频原语若跨多个主题出现（如"新手也能看懂"），标记为横向诉求，单独写进洞察。

## 5. 双口径统计

所有分布统计输出两版：

| 口径 | 含义 | 用途 |
|---|---|---|
| 全量口径 | 含模板与灌水 | 反映声量、传播面、活动效果 |
| 去噪口径 | 每个模板集群计 1 条，剔除无效 | 反映真实想法分布，用于产品判断 |

报告正文以去噪口径为主，关键词出现率可用全量口径（并标注）。任何表格都注明口径。

## 6. 排序找重点

- **高共鸣**：按互动加权排序（如 `likes*10 + views`，权重按平台调整），找被社区顶起来的条目。
- **高投入**：按文本长度排序，长文通常是最用心的原创（也要人工确认不是复制长文）。
- 两个榜单与"信号强度四要素"交叉，人工挑出精华 Top N。互动高≠质量高，最终以人工判断为准。

## 7. 数字回查（交付前必做）

报告引用的每一个数字，交付前写一小段脚本对着原始数据重算：

- 总条数、覆盖率、各主题条数与占比
- 每条被引用原声的作者、互动数、文本是否与原文一致
- 具名比例类数字（"近两成用户强调X"）对应的匹配条数

一个对不上的数字会让整份报告被打折扣。回查脚本保留在数据目录里，别人质疑时直接跑给他看。

## 8. 数据交付物

随报告归档：原始结构化数据（json/csv）、打标结果、人类可读的扁平化全文清单
（`[序号] @作者 互动数 :: 全文`格式，供不写代码的同事交叉复核）、数字回查脚本。
