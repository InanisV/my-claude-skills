# 用户研究报告方法论（VOC 文本研究）

## 这个 skill 解决什么问题

一批用户原声摆在面前时，最常见的失败不是"分析得不够深"，而是四个更基础的错误：
把声量当需求、把许愿当痛点、把噪音当样本、把报告当成没有读者风险的纯技术文档。
这套方法论提炼自真实项目实践（一次对 255 条社媒征集回帖的全量研究），
目标是让每一份用户研究报告都经得起三个追问：**数字从哪来的？结论凭什么？发出去安全吗？**

## 核心信条

动手前先接受四个判断，后面所有流程都是它们的展开：

1. **信号强度 > 声量。** 条数最多的主题往往是"许愿"——谁都会说想要 AI、想要智能、想要个性化。
   最值钱的信号经常藏在占比 10% 的低声量主题里。判定强弱看四要素（见 Phase 3），不数票。
2. **不体检的样本会说谎。** 带激励的征集（抽奖、积分、空投）必然混入模板复制、灌水和批量账号。
   不先扣噪音，后面所有统计都被污染，而且污染方向恰好偏向"最没价值的声音"。
3. **结论必须可复核。** 逐条精读、附原始清单、每个数字能回查到数据。
   这是研究者的信誉资产：报告敢被人拿放大镜看，结论才有分量。
4. **报告是会被转发的。** 它既是决策输入，也是组织里的社交文本。
   两条纪律：只评价用户和需求，不评价任何内部团队的工作；
   每个发现都要有去处（谁承接、什么时候），否则读者会自行脑补一个去处。

## 流程五阶段

### Phase 0 · 对齐（动手前想清楚，必要时用一轮提问确认）

四件事：**研究问题**是什么（开放探索还是验证假设）；**数据源**与可得性；
**读者是谁**（只有研究团队自己看，还是会发到有领导、有跨团队成员的群——这直接决定 Phase 5 怎么裁）；
**交付物形态**（完整报告 / 群同步短消息 / 两者都要）。

### Phase 1 · 取数

**能全量就全量。** 全量精读是这套方法论的地基——抽样会漏掉低频高价值信号，
而"逐条读完"本身就是报告可信度的来源之一。取数时：

- 优先结构化途径（API、导出、页面数据接口），页面滚动截取是最后手段且经常拿不全。
- 每条记录至少保留：作者、时间、全文（含长文展开）、互动数据（赞/曝光/回复）、媒体有无、层级关系。
- **交代覆盖率与缺口**：抓到多少条 / 平台显示多少条，缺口是什么（删除、限流、不可见）。
  覆盖率是报告第一个被挑战的数字，主动交代比被动解释体面得多。
- 数据量大到读不完时：先程序化聚类压缩再人工精读代表条目，但必须在报告里声明抽样/压缩方式，
  且所有被引用的原声必须人工回看过原文。

### Phase 2 · 体检与打标

分析之前先给样本做体检（程序化手段见 `references/analysis-toolbox.md`）：

- **模板复制检测**：文本规范化后做相似度聚类。能被大量复制的文案本身也是信号
  （说明它好懂、诱人），但复制次数绝不能当票数。
- **无效内容**：纯灌水、纯表态、广告、与主题无关。
- **身份异常**（激励型征集必查）：同一自报 ID 跨多账号出现、发帖时间高度聚集等批量参与特征。

然后建立**双口径**并全程并行使用：全量口径（反映声量与传播面）和去噪口径（反映真实想法分布）。
报告里所有统计都要标明用的是哪套口径。

**打标**：多标签体系（主标签 + 次标签），标签从数据里长出来——先裸读一批（如 50 条）再定标签表，
不要带着预设分类进场。打标是人工判断，程序只做统计。

### Phase 3 · 分析

按四层递进：主题全景表 → 主题深读 → 信号强度评定 → 精华 Top N。

**信号强度四要素**（本方法论的灵魂，逐主题评定）：

| 要素 | 看什么 | 强信号的样子 |
|---|---|---|
| 情绪强度 | 用户是"希望有"还是"受够了" | 防御性用词、抱怨具体对象 |
| 描述具体度 | 有场景有结构，还是形容词堆砌 | 能画出交互流程的描述 |
| 跨用户一致性 | 互不相识的人是否用同一结构描述 | 不同账号、相同的"触发→期待→动作"链 |
| 自发性 | 是否非模板、非引导产物 | 出现在模板集群之外、措辞各异 |

四要素齐的低声量信号，价值高于四要素缺的高声量信号。报告里要敢于把 20% 声量的主题排在第一位，
把 40% 声量的主题标记为"可能是伪需求"——但每个判断都给出四要素层面的理由。

**警惕许愿词**：AI、智能、个性化、一站式、更好用。这些是用户的"默认许愿"，
出现率高但信息密度低。处理方式是往下追一层：用户拿它做什么动作？
把"我要个 AI 助手"拆成"帮我读懂 / 帮我筛掉 / 帮我判断"，需求才开始可执行。

**原声即证据**：每个主题带 2–4 条用户原声（保留原文或忠实翻译，不改写、不美化），
每条注明作者。没有原声支撑的判读，读者有权当作者的臆测。

### Phase 4 · 成文

按 `references/report-template.md` 的骨架写，排版按 `references/style-guide.md` 执行。四条铁律：

1. **结论先行**：第一屏就是一句话结论 + 2–4 条最强信号。数据源、方法、附录全部放文末。
2. **每个数字回查**：交付前把报告里引用的每个数字（条数、占比、互动数）对着数据重算一遍。
   一个对不上的数字会让整份报告的可信度归零。
3. **局限自己先写**：样本偏差（激励吸引任务党、语言/地区偏斜、受访者未必是真实用户）、
   声量陷阱、合规红线——自己写出来是严谨，被读者指出来是事故。
   并明确结论的定位：探索型样本适合"机会发散与假设生成"，不适合直接排产品优先级。
4. **为三种读速设计**：报告会被 10 秒（手机上刷到的领导）、3 分钟（评审前扫读）、
   15 分钟（承接方案的人）三种读者打开。核心结论进带语义的 callout 块（🎯 结论、🔍 判读、
   💡 关联提醒），统计配"带观点"的图表（高亮即立场、图注写结论），标题写成判断句。
   交付前自检：只看彩色块、图表和标题，能否拿到全部主干结论？可读性细则见 style-guide.md。

### Phase 5 · 分发（两版制）

**内部档案版**：研究完整性优先。噪音审计明细、对运营/活动机制的观察、边缘产品线的关联分析都保留。

**对外分发版**：从档案版裁剪，遵守分发纪律——

- 删除指向兄弟团队的操作建议（活动机制批评、奖励发放建议等）。那些话应当私下同步给对方团队，
  写进广发的报告里就从"帮忙"变成了"当众纠错"。
- 去除与敏感、边缘或战略上想保持距离的产品线的主动关联。研究上成立的联想，
  组织上可能是给自己招事。
- 模块命名与同步消息的口径对齐，避免"消息说三点、报告是另外三点"。

**群同步消息**（如需要）：三点式短语化。每条 = 高亮短语 + 冒号 + 一句发现 + 一句承接；
2–4 条之后给"下一步"（谁在做、何时有产出）；口吻是向团队同步发现，不是向领导汇报。
开头可以先肯定数据里对团队现有工作的正向验证——研究结论同时是团队的弹药。

## 发现的去处（承接矩阵）

每条重要发现，在报告或同步里必须落到四类之一：

| 去处 | 写法 |
|---|---|
| 已在规划 | 指明在哪一期/哪个 roadmap 条目 |
| 进行中 | 谁在做、当前进展 |
| 新机会 | 谁去调研、预计何时有产出 |
| 明确不做 | 给出理由（伪需求/成本/合规/时机） |

"明确不建议做"清单与建议做的清单同样重要：它证明研究有判断力而不是许愿清单的搬运工，
也替读者省掉一轮争论。

## 反过拟合：不同场景怎么裁剪这套流程

这套流程完整跑一遍最适合"一次性的开放征集/评论区研究"。其他场景按需裁剪：

- **干净数据源**（访谈逐字稿、无激励问卷）：身份异常检查可省；模板检测保留——问卷开放题同样有复制粘贴。
- **小样本**（< 50 条）：跳过程序化聚类，直接人工全读；双口径可简化为一次性说明。
- **连续监测型**（周度/月度评论回顾）:固定标签表后做增量对比，重点看新增主题与情绪迁移，而非每次重建全景。
- **访谈/焦点小组**：信号四要素中"跨用户一致性"改为跨受访者比对；"互动数据"维度不适用。
- 数字与结构不要照抄任何示例：最强信号可以是 2 条也可以是 4 条，Top N 可以是 5 也可以是 12，
  主题可以是 6 类也可以是 13 类。结构服务于数据，不是数据服从结构。
