# 清单：开工确认 · 还原走查 · 交付验收

## 一、开工前（AskUserQuestion，材料读完再问）

1. **受众与场合**：老板/管理层宣讲｜团队评审｜外部展示？→ 决定详略、
   画饼章有无、界面语言（界面语言跟设计稿，讲解语言跟汇报对象）。
2. **章节范围**：从 PRD 提炼候选场景清单给用户勾选（multiSelect），
   推荐 6–8 章 =「核心功能 + 1–2 条亮点线 + 增长闭环（+ 画饼章）」。
3. **亮点线**：哪条线是本次汇报的"主菜"（AI 供给/AI 回应/增长归因/数据壁垒），
   主菜要单独成章并在旁白里点题。
4. **演示方式**：默认一键自动播放（展示型）；用户明确要"给人上手玩"才做
   交互优先（体验型）。两者引擎相同，差别在默认入口与提示文案。
5. **材料缺口**：缺哪类输入就点名要（PRD 后台链路 / 某几屏真机截图 /
   对话结论），说明用途；要不到就基于可得材料做并把假设写进交付说明。

## 二、界面还原走查（对照设计稿逐屏过）

- [ ] 底色、卡片分隔（纯黑 + hairline？）、圆角半径
- [ ] 每个图标都是 SVG（状态栏/导航/动作行/宫格，无 emoji 混入）
- [ ] 动作行元素**顺序**与计数规则（999+ 封顶、缺失显 "--"）
- [ ] 按钮形态：主按钮色、白底胶囊（关注）、禁用态
- [ ] 页签形态：下划线 vs 胶囊；选中字重/字号变化
- [ ] cashtag/链接蓝、涨跌红绿跟站点、数字 tabular-nums
- [ ] 时间口径：列表相对时间、详情绝对时间（按设计稿）
- [ ] 键盘/弹层/海报等氛围组件到位
- [ ] 设计稿未覆盖的页面：按 PRD + 已有风格补，**交付时列出补画清单**
- [ ] 状态覆盖：加载骨架、空态、失败/兜底文案（PRD 有定义就要有）

## 三、剧本走查

- [ ] 章节连读是一条故事线（入口→基础→亮点→闭环→画饼），不是功能罗列
- [ ] 每步旁白是"能念的讲稿"，关键词加粗；自己通读一遍不磕绊
- [ ] 日志用 PRD 里的真实机制词（快照/游标/request_id/乐观更新/审核态），
      不编造接口行为；AI/审核/接口三色分明
- [ ] Demo 压缩处已在旁白或页脚标注（审核时长、插卡频率等）
- [ ] 画饼章：概念角标 + 页脚"非本期范围"声明 + 每张卡有数据背书
- [ ] 标准速总时长 2–3.5 分钟；加速档可用；空格暂停可用；单章重放幂等

## 四、验证（交付前必做）

- [ ] Playwright 全程跑 master：console error + pageerror = 0
- [ ] 终章旁白出现（未出现 = 卡死，查 wait/元素 id）
- [ ] 每 5s 采样截图 + 关键态定向截图（弹层/空态/完成态）
- [ ] 截图拼图后**人眼**对照设计稿核对（零报错 ≠ 界面对）
- [ ] 手动模式抽查：随便点卡片/页签/返回不报错、不破状态

## 五、交付

- [ ] SendUserFile（display: render）+ 一句话 caption
- [ ] 可持久化则建/更新桌面 artifact；通道不可用就说明并跳过
- [ ] 版本纪律：大改动新建 vN 独立文件；用户点名保护旧版时绝不覆盖
- [ ] 项目档案更新：版本、章节表、依据材料、**待用户核对的假设**
- [ ] 交付信息附"怎么讲"：建议播放顺序、哪几处值得按空格停下细讲、
      每章对应老板关心的哪个指标/口径

## 六、已知坑速查

| 坑 | 处置 |
|---|---|
| Figma MCP View 席位限额，一次就锁 | 第一发调用拉总览板；失败即改要真机截图 |
| .fig 源文件 | 解析不了，请用户在 Figma 里导出 PNG |
| emoji 当图标 | 玩具感元凶，全部换 SVG |
| 暂停后动作丢失 | 引擎里 idx 在 go() 内前进（见 engine.md §2） |
| 旧章计时器穿越 | 所有 setTimeout 收进 AP.timer + AP.on 守卫 |
| 翻译态不一致 | Feed/详情/海报/端外共用一份 S.trans；端外与海报永远原文 |
| 单章重放状态残留 | 每章第一步 do 里做本章前置重置 |
| 大文件一次写超限 | 骨架 Write + 标记位 Edit 分段拼装 |
| PDF 版 PRD 太大 | 分页读；先读前 12 页拿结构，再按需补读 |
| 用户说"没还原" | 不辩解，要截图逐屏重做界面层，剧本层保留 |
