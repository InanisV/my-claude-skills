# 反面教材：这一役被打回的版本和原话

按时间顺序，每条一句原话、一句原因、一句改法。下次做高管方案先扫一遍，大半能提前躲掉。

| 版本 | 原话 | 原因 | 改法 |
|---|---|---|---|
| 四阶段生命周期页 | "整体体系化这个生命周期的思考没有在这一图流里体现出来" | 只画了用户看到的四段，系统在哪、单位怎么切、AI 干什么没落 | 加系统层 |
| 五层矩阵文字版 | "都是文字了，没有体现出 AI 的作用，以及它如何成为一个系统" | 满屏 chips 没有画面 | 做成管线，AI 引擎居中 |
| 前中后矩阵 | "没有体现出我们体系化的产品 owner 和产品思维、架构思维"（后被认可为对的方向） | 矩阵可以，但沉淀列是量化复盘 | 沉淀改社交逻辑，后整列删除 |
| 沉淀列「早知道榜」 | Yoki："给用户背书，用户亏了谁负责" | 点名个人 = 平台背书 | 删除 |
| 三阶段规划页 | "故事讲的还是不够大" | 只是"广场管三件事" | 立对手、接公司的牌、算账 |
| 「热点第一站」+ 飞轮 + PONS 案例 | "飞轮证据底线都不行" | 飞轮一半不在我们手里；案例日期是编的；底线是免责声明 | 换成凭什么是 MEXC、怎么验证、节奏 |

| 盘前联动、多空指数、全端分发 | "盘前能力不是你想的那样；给 Marvin 汇报要聚焦热点，不要偏离" | 发散 | 删 |
| 「怎么验证」一章 | "怎么验证没必要说" | 认可方向的方案不写验收 | 改成观察口径一段 |
| 封面「广场的差异化」 | "Marvin 根本不关心我们广场的差异化定位是什么" | 从我们的起点进，不是从他的 | 从他要的专区进 |
| 文档出现「老板的问题」「请 Marvin 看的」 | "当着他的面谈论他" | 读者视角错位 | 删读者名字 |

| 第一版整合长图 | "空旷的地方太多了，好多细小的文字" | 四段塞一页，字数十倍 | 压紧、字放大、小字删 |
| 圆形图标网格 | "一圈一圈的，底下都是圈" | 行内数量不齐、一圈一圈没画面 | 管线 |
| 十秒版 | "搞得很简单，老板就会以为这东西很好做" | 删过头，产品力没了 | 恢复系统块 |
| 用户诉求四列 | "有点发散了，像用户问卷，不像产品架构" | 只站了用户声音一个来源 | 故事线 + 架构脚注 |
| 文档「可能的追问」 | "写在文档里面是不是很奇怪" | 方案不该有问答 | 风险与边界 |
| 文档标题带 emoji、callout 五色 | "整体乱糟糟的，一点都不专业" | 节奏不一致 | 一种节奏九条版式 |

## 几个反复出现的根因

1. 顺着最新意见放大，丢了之前的要求 → 要求表
2. 为了衬托我们硬编对比 → 每句问"谁能反驳"
3. 在同一骨架上打磨 → 反馈说"不是一个事"就换骨架
4. 把功能说明书当规划 → 按 leader 的阶段做列
5. 一个块只站一个来源 → 四来源自检
