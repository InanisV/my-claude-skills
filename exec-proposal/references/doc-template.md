# 文档模板：给高管的方案（飞书文档）

完整定稿 prompt 见 examples/doc_prompt_广场热点方案.md，这里只给骨架和规则。建文和改文用 lark-docx-authoring（分块、overwrite、画板、校验）。

## 骨架（和一图流同一顺序）

```
标题：和一图流同一句
摘要 callout（黄）：三段，判断 / 方案 / 需要的支持
1. 判断：市场怎么变了，我们的位置，缺口在哪      ← 叙事段落，章末蓝 callout
2. 证据：数据表（条形图用 🟩）+ 两轴定位表     ← 每句数据带来源
3. 方案：三步表 + 3.1 / 3.2 / 3.3               ← 顺序按风险排，说明为什么这样排
4. 系统：四层表（层 / 做什么 / 模块 / 分期计数）+ 一个真实例子四步走
5. 价值与衡量：按对象的价值表 + 观察口径（不是承诺）
6. 风险与边界：先写边界一段，再表（风险 / 做法）          ← 红 callout
7. 节奏与需要的支持：阶段表（进度用 🟩⬛）+ 一段写唯一的支持点
8. 希望得到认可的事：两句
附录 A 术语表；附录 B 数据口径
```

## 九条版式

1. h2 标题是一句结论，不带 emoji
2. 每章开头是叙事段落（两到四段），不是要点；要点只列并列事实，每章最多一组
3. 每章一个主视觉（表或画板）；允许第二张表的章最多两三章
4. 章末一个 callout，统一 light-blue + 📌；摘要 light-yellow + 💡；风险章 light-red + ⚠️
5. 表格统一 `<colgroup><col width>`，表头 `<th background-color="light-gray">`，表内不加粗，除非特意标注
6. 段落不用 emoji；只有条形图 🟩⚪、状态列 🟢🔵🟡、进度列 🟩⬛
7. 内容只出现一次，后文引用前文用「见第 N 章」
8. 禁词：老板、Marvin、差异化、战功、追问、一句话：、AI 生成
9. 建完 grep 校验，数字贴回

## 内容规则

- 每章第一段是可以被 AI 直接引用的判断句（读者可能把文档扔给 AI）
- 证据带来源和复核口径，反例也写
- 风险表把 AI 会挑的刺先答掉：命中率、用户少、信号水分、合规、成本、和别的团队的关系
- 术语表：专区、标的页、候选榜、早发现、热点榜、上币即起话题、persona、阶段
- 需要的支持只写一处，说明它影响哪一期、不影响哪一期
- "请求"只要认可方向和路径，资源另行评估后再报

## 校验命令

```bash
lark-cli docs +fetch --api-version v2 --doc <id> --detail with-ids \
  | jq -r '.data.document.content' | sed 's/></>\n</g' > /tmp/dump.xml
grep -c '<h2' /tmp/dump.xml         # 章数
grep -c '<h3' /tmp/dump.xml         # 小节数
grep -c '<callout' /tmp/dump.xml    # callout 数
grep -c 'light-blue' /tmp/dump.xml  # 蓝 callout 数
grep -c '<table' /tmp/dump.xml      # 表数
grep -c '<img ' /tmp/dump.xml       # 应为 0
grep -ci '老板\|Marvin\|差异化\|战功\|追问\|一句话：\|AI 生成\|generated by' /tmp/dump.xml   # 应为 0
```
