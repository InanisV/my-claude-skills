# 直属 leader 的审稿标准

## 通用：leader 看方案时在看什么

| 他问的 | 背后的意思 | 我们怎么过 |
|---|---|---|
| 这是事实吗 | 不是事实的因果链、编的日期、硬凑的对比，一句就塌 | 每句对比问"谁能反驳"，没数的删 |
| 重点在哪 | 平铺的几步等于没重点 | 重点那步高亮，其余缩成底座 |
| 这是规划还是说明书 | 功能怎么运转不等于方案 | 列按阶段排，不按功能排 |
| 你想把它做成什么 | 在问野心 | 方案定在能力，不定在页面 |
| 有没有风险 | 背书、回顾、点名个人 | 这类块整列删除 |
| 一句话能说清吗 | 看似叙事实则堆砌 | 五格压成一句 |

## 案例：Yoki（广场热点方案，2026-09 到 10 月）

她抓老板的思路比我们准，她的否决比用户的否决更硬。每一版发给用户之前，先用她的标准过一遍。

## 她的原话和含义

| 原话 | 含义 | 我们改了什么 |
|---|---|---|
| 「第一部分，这不一定是事实，不知道我们可以不说」 | 不是事实的因果链不上图，哪怕看起来合理 | 删掉"上得早但用户晚看到"的时间线，只留能核的上币日期 |
| 「第二部分看似在叙事，但是有一种堆砌的感觉，还不如写成一句话」 | 五格流程图讲的是功能，不是叙事 | 五格压成一句 |
| 「规划里面把重点高亮出来；铺一个专区入口、整理一些内容，哪怕是新币推广，肯定不是重点」 | 三步不是平铺的，前两步是底座，第三步才是产品 | 早发现金框，其余两步缩小 |
| 「其实我们要做的重点是早发现，早发现可以让用户愿意来我们这里，也可以推动早上币」 | 老板听得进的是用户为什么来、公司为什么赢 | 标题改成"让用户为早一步来 MEXC" |
| 「在高度同质化的今天，核心竞争力都是有价值差异化，不然就是红海里卷」 | 差异化是她的论证，不是老板的词 | 论证保留，"差异化"三个字从图和文档里删掉 |
| 「你这个只是你现在整理数据的逻辑，跟我们昨天讨论的不是一个事」「只能叫你现在设计的哪个功能怎么做，跟这个功能有几个阶段没有关系」 | 规划 ≠ 功能说明书；把功能画得再体系化也只是第一阶段 | 按她的三阶段重搭骨架 |
| 「这个板块对平台来说没有什么价值，反而会给用户背书」「都已经结束了写回顾给谁看」「你去点名早发现的人，早发现的人是稳定的吗，一旦用户跟他亏了谁负责」 | 回顾没读者，点名个人是平台背书 | 沉淀、回顾、早知道榜全部删除 |
| 「主要还是看你想把你的这个地方做成什么，如果只是做一个信息聚合，按现在这个也没什么问题」 | 她在问野心 | 方案定在"能力"不是"页面" |
| 「哈哈哈 你的 AI 进入惯性了」 | 在同一骨架上连改三版 | 换标题、换骨架再画 |
| 「这个写成一份汇报，要给 M 哥看」 | 交付物是文档，图是封面 | 两件套 |

## 她给的三阶段（方案的脊柱）

1. 把广场上已有的内容归类到专区（现在在做）
2. 官方运营新币，起话题
3. 寻找新币，去外面找热币，反向 push 平台上这个币；让用户觉得来这里能早一步

第三阶段的转化问题（没上币的讨论没承接）她的回答是"所以我们有几个阶段"：顾虑成立，但它是第三阶段内部怎么做的问题，不能拿它把第三阶段砍掉。

## 用户和 leader 冲突时

- 用户压事实、压承接、压不要花哨；leader 压野心、压重点、压故事
- 两边都对：事实和承接决定方案能不能立住，野心和重点决定方案值不值得看
- 做法：leader 的三阶段做骨架，用户的承接顾虑放进第三阶段内部写成"候选 → 关注 → 上币那一刻推送 → 首日交易"
