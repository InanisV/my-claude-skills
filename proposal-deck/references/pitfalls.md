# 反面教材：三份方案里被打回的每一条

按根因分组，每条一句原话、一句原因、一句改法。新方案开工先扫一遍，大半能提前躲掉。来源标注：A = 广场 1.5 一图流（9 月中），B = 股票 Meme 专区（9 月下），C = 广场热点方案（9 月末到 10 月）。

## 根因一：从我们的起点进，不从读者的起点进

| 原话 | 原因 | 改法 | 来源 |
|---|---|---|---|
| "请你一定要记住，我们要抓住老板真正的核心诉求，并且满足他" | 方案回答的是我们想做什么 | 第一块回应他要的 | A |
| "你是 ealy，看我们这样呈现，你高兴吗？感觉就像是无脑的照抄" | 学竞品学成了抄功能 | 展现"为什么这么做" | A |
| "yoki 说了要有逻辑，页面是怎么进来的，具体我们加这些有什么价值，要让老板一眼就看出来。不然老板就感觉我们在堆功能而已" | 功能清单没有逻辑和价值 | 入口、跳转、价值一眼可见 | A |
| "Marvin 根本不关心我们广场的差异化定位是什么" | 用我们的论证词当标题 | 从他要的专区进，"差异化"从图和文档删掉 | C |
| 文档出现"老板的问题""请 Marvin 看的" | 当着他的面谈论他 | 删读者名字 | C |
| "我们的目标是让老板一眼就能了解到我们的想法，我们是要在老板们面前展示我们的思考" | 把方案当功能说明 | 方案 = 价值 + 思考 | A |

## 根因二：没依据的对比和编的事实

| 原话 | 原因 | 改法 | 来源 |
|---|---|---|---|
| "你对股票秘密的了解不对，请你先做一下搜索和了解吧" | 对象理解错 | 不熟的先搜再写 | B |
| "上币信息只有我们最先知道，上币都是有公告的，这一点就站不住脚" | 为衬托我们硬编 | 删，不找替代 | C |
| "'社区和资讯产品看到了买不到，链上钱包只能买链上'说的不准确" | 同上 | 删 | C |
| "'X 和 FOMO 靠截图和钱包，验不了'，这个有链上数据啊" | 同上 | 删 | C |
| "'合约加美股，热点不限于币'这个也很牵强" | 硬凑第三张牌 | 只留一张真牌 | C |
| Yoki："第一部分不一定是事实，不知道我们可以不说" | 合理的因果链也不是事实 | 只留能核的日期 | C |
| "'打到金狗'的故事感觉不太好，它很多是热点，也不一定是金狗" | 承诺式用词 | 改"提前发现热点" | C |

## 根因三：删过头或堆过头

| 原话 | 原因 | 改法 | 来源 |
|---|---|---|---|
| "老板不喜欢看文字，文字太多了" | 满屏说明 | 主体是图，字到标签级 | A |
| "字要少，一眼看到的都是价值！原型的呈现要大，且要有逻辑" | 同上 | 原型大，路径标出来 | A |
| "空旷的地方太多了，好多细小的文字，老板根本不会仔细看" | 一页塞四段，字数十倍 | 压紧、字放大、小字删 | C |
| "搞得很简单，老板就会以为这东西很好做" | 十秒版删到只剩界面 | 产品力块不能删，压成故事线 + 脚注 | C |
| "整体体系化的生命周期思考没有在一图流里体现出来" | 只画了用户看到的四段 | 系统层补上 | C |
| "都是文字了，没有体现出 AI 的作用，以及它如何成为一个系统" | 满屏 chips 没画面 | 管线，AI 引擎居中 | C |
| "方案的专业度与价值传递：要专业的、详实的，有独到的分析和见解" | 文档太简略，分发出去显得没准备 | 每章叙事段落加判断句 | C |

## 根因四：骨架不对却在同一张图上打磨

| 原话 | 原因 | 改法 | 来源 |
|---|---|---|---|
| Yoki："你这个只是你现在整理数据的逻辑，跟我们昨天讨论的不是一个事""你的 AI 进入惯性了" | 把功能说明书当规划，连改三版不换骨架 | 按 leader 的阶段做列，换标题换骨架 | C |
| "故事讲的还是不够大""没有给我眼前一亮的感觉" | 只是"管三件事" | 立对手、接公司的牌 | C |
| "飞轮、证据、底线，我觉得不行" | 飞轮一半不在我们手里、案例日期是编的、底线是免责声明 | 换成凭什么是我们、节奏 | C |
| "怎么验证没必要说" | 认可方向的方案不写验收 | 改成观察口径一段 | C |
| "不要搞多个方向发散，要聚焦在热点上，不然显得没有章法" | 指数、全端分发、盘前 | 删 | C |
| "方案 B 更好，但有一个核心问题……" | 方向对了细节错 | 只在选定方向上改 | C |

## 根因五：呈现乱

| 原话 | 原因 | 改法 | 来源 |
|---|---|---|---|
| "乱七八糟的，真的不行，完全没有重点" | 学习对象不明显，图文混 | 一页一个被学对象，图文分开 | A |
| "说明文字和图片混在了一起，不太清晰我们要做什么" | 同上 | 说明和图分区 | A |
| "不要长条形的，最好在一个页面里给 ealy 讲清楚" | 长图 | 单屏 | A |
| "分成两张图很不合理，老板没有心思看两张比较相近的图" | 相近的事拆两张 | 融合成一张 | B |
| "一圈一圈的，底下都是圈" | 圆形图标网格没画面 | 管线或故事线 | C |
| "一眼看上去乱糟糟的" | 行内图标数量不齐 | 固定列数网格 | C |
| "像用户问卷，不像产品架构，有点发散" | 系统块只站了用户声音一个来源 | 用户数据只在证据块出现 | C |
| "搞得更乱了"（用户诉求做架构表头） | 两套东西硬挤一块 | 故事线 + 架构脚注 | C |
| "不是让你去把风格也改成他们的，我们那个风格很好" | 整套换成同事的亮色版式 | 学做法不学样子 | C |
| "'可能的追问'写在文档里面是不是很奇怪" | 方案里出现问答 | 风险与边界 | C |
| "整体乱糟糟的，一点都不专业"（文档） | 标题带 emoji、callout 五色、内容重复、表格塞满 | 一种节奏九条版式 | C |

## 根因六：忘了之前的要求

| 原话 | 原因 | 改法 | 来源 |
|---|---|---|---|
| "你又把我之前提的很多点忘了，你自己读一读我们的聊天记录" | 顺着最新意见放大 | 要求表，每版贴对照 | C |
| "不要我说什么就是什么；你得有一套思维方式和方法论" | 每版只反映最新一条 | 一页三问四来源 | C |
| "这些在我和 yoki 的对话里都有啊，你到底有没有认真看我们的对话" | 没读 leader 的原话 | 先读全对话，列 leader 的要求 | A |

## 根因九：公开场合的姿态（D = 2026-11 产品创新工作坊广场议题）

| 原话 | 原因 | 改法 | 来源 |
|---|---|---|---|
| "没有必要自己爆短呀，这么血淋淋的数据写在那里打自己的脸呀" | 把日均 9 条评论当痛点写在开头 | 只放日期和增长率，痛点藏进题目 | D |
| "当你作为主产品，你对你的产品无能为力并在公开场合寻求帮助，你的人设会是另一种了" | 全篇是"我有问题你们帮我想"的结构，题目在问"资源从哪来" | 判断 + 势能 + 邀请放大，题目开放但答案落在自己产品里 | D |
| "我都还没有找到我们可以吹嘘的创新" | 一页纸里只有痛点和空白 | 给一个判断句当格局，方案留到产出后 | D |
