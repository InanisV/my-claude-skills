# 证据怎么拿：上币领先天数（公开接口，可复核）

"交易所里最早"这类词必须有数。广场那次用公开接口拉了近三个月热点币的上币时间，口径写进附录，每月可复核。

## 数据源（2026-09 实测可用）

| 交易所 | 接口 | 字段 | 备注 |
|---|---|---|---|
| MEXC 合约 | `GET https://contract.mexc.com/api/v1/contract/detail` | `data[].symbol`、`data[].openingTime`（毫秒，UTC） | 一次返回全部合约，1179 个；按 baseCoin 过滤 |
| 币安 | `GET https://www.binance.com/bapi/composite/v1/public/cms/article/list/query?type=1&pageNo=N&pageSize=20&catalogId=48` | `articles[].title`、`releaseDate` | catalogId=48 是「新币上线」；标题里写明合约/现货和上线日 |
| OKX | `GET https://www.okx.com/api/v5/support/announcements?annType=announcements-new-listings&page=N` | `details[].title`、`pTime` | 现货上新少，合约可能在别的 annType |
| Bybit | `api.bybit.com/v5/announcements/index` | | 沙箱里被地理限制，拉不到 |

## 口径

- MEXC 合约上线时间：openingTime，UTC
- 币安上线：公告标题所示上线日；合约与现货分别记录，领先天数取币安最早的那个
- OKX 上线：公告发布日
- 领先天数 = 币安最早上线日 − MEXC 合约上线日
- 同日写同日，反例也写；不画入的（领先 11 个月之类）在注里说明

## 写进方案的方式

- 一图流：柱状图四到五根加一个大数「平均早 2 周+」，注一行来源
- 文档：全表 + 🟩 条形（每格 5 天）+ 来源 + 一句解读（"热点在 MEXC 先上是常态不是个案；两周够一个热点从候选走到置顶"）
- 不写"用户什么时候看到"，这个没数据；只写"领先期里站内没有讨论阵地"，这个是事实

## 档案层通用规范（2026-10-19 加，来自链上业务汇报的证据附录）

汇报层只放大数和结论，档案层放全表和口径。E 哥的"不要读了 10 本书就讲 10 本书"落在这里：书读了，放附录和 Lark 档案，会上只讲三件事。任何方案、一图流、deck 的证据都按这一节记。

### 四态标记

| 标记 | 含义 | 不是什么 |
|---|---|---|
| ✓ | 界面或官方资料已确认 | 不代表各链各币可用，不代表成交已测 |
| △ | 范围或证据有限 | 不是"有一点"，是"证据不够下结论" |
| ? | 本轮未确认 | 不表示对方没有，只表示我们没核到 |
| ✕ | 确认没有 | 写明确认方式和日期（如"用户内部确认，2026-10-15"） |

竞品矩阵里 MEXC 一列全 ✕ 是最强的反差页，前提是每个 ✕ 都经得起"谁能反驳"。

### 来源与日期依据

- 每个事件标注来源类型：官方公告 / 官方教程 / 媒体报道 / 转载线索 / 本轮实测，写清哪些原帖未回读
- 日期的来源单独写：公告发布日不是上线日，总结帖的发布日不是功能上线日，链本身的上线日不是竞品接入日。写不清楚依据的日期不进图，只进附录并标"不参与计算"
- App 截图、官方资料、网页实测不混作同一端的成交验证；截图标产品、端（App / Web）、日期

### 计算口径

- 任何"回落 X%""领先 N 天""N 倍"都写公式和两个端点（哪个月到哪个月、哪天到哪天）
- 跨缺口只比较可用端点，不把缺口补零；负值和异常值保留并注明
- 数据截止日和复核方式写一行（"复用已审核数据截至 2026-10-10 UTC，仅画完整月"）

### 同期对照不写因果

- 事件和数据放在同一张图里只做描述性对照，附一句"不代表已验证因果"
- 收入、交易量这类指标同时受行情、费率、返佣、产品范围影响，不把同期变化全归给一个功能
- 没有做过的分析不填估算值：没有用户级关联数据就不写重合率、转化率，写"如要量化需要什么数据、怎么算"

### 进汇报层的方式

- 大数进页：一个数、一个来源小字、一个对照（基线或竞品）
- 全表、口径、免责进附录页或 Lark 档案，deck 末页放档案链接
- 老板追问时翻附录，不在正文里预答
