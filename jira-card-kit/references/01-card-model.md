# 卡片模型：一个需求建哪几张卡

依据：2025-09~2026-08 近一年 creator=noah 的 598 张卡实测（iOS/Android 故事 115/115 严格成对）。

## APP 标准包（最常见）

一个 APP 双端需求 = **4 张卡 + 3 条链接**，全部由本 kit 创建：

```
【iOS】【业务线】需求名        故事（主卡）─┬─ 挂 Epic(史诗链接)
【Android】【业务线】需求名    故事        │   description = PRD lark 链接
                                          │
  ├ 子任务挂在 iOS 主卡下：               │
  │   【UI设计】【业务线】需求名   UI设计任务  assignee=设计师
  │   【国际化】【业务线】需求名   国际化任务  assignee=建卡人自己
  │
  └ 链接：
      Android 故事 ─Cloners(clones)→ iOS 故事      （复刻 Jira 界面克隆的效果）
      Android 故事 ─Relates→ UI设计任务
      Android 故事 ─Relates→ 国际化任务
```

- Android 故事的字段 = iOS 故事完整复制，仅换：summary 前缀、components（iOS-xxx → 安卓-xxx）、fixVersions（iOS_待评审 & 待排期 → 安卓_待评审 & 待排期）。
- 单端需求（如 AB 实验代码下线）只建对应端一张故事，视需要配 UI/国际化子任务。
- Flutter 需求（多见资产模块）：summary 前缀【Flutter】，components 用 Flutter-xxx。
- 不需要 UI → 不建 UI设计任务，且故事的 是否需要UI=否；国际化同理。

## WEB/H5 故事（只建 1 张卡）

WEB 项目的自动化会在建卡后几秒内**按字段答案**自动生成子任务（需要UI=是→UI设计任务；需要埋点=是→埋点四件套；国际化同理；全否的卡一张都不长，2026-08 实测），**kit 只建故事主卡本身**。summary 前缀【H5】或【WEB/H5】或【WEB】。

## 拆分单场景（把已有大卡拆成模块卡）

研发要分批交付/测试时，会要求把已有故事卡拆成 N 张模块卡（实例：广场1.0 H5 拆 7 卡，2026-08-13）：

- 每模块 1 张故事卡，summary=`【H5】原需求名-模块名`；Epic/优先级/派生需求/组件等字段**跟随主卡实际值**（不是 kit 通用默认）；**受益方是唯一例外——不许跟随主卡，必须独立问用户**（主卡自己就可能填错，见 02 红线的广场案例）；description=主卡的 PRD 链接 +「拆分自 <主卡key>」+ 本卡范围一行
- 每张模块卡 Relates→主卡；不重复补主卡已表达的跨端依赖链接
- **UI设计/国际化不按模块重复建，集中在主卡**（Noah 2026-08-13 裁决）：模块卡填 是否需要UI=否、是否需要国际化=不需要，以抑制自动化生成；再把**主卡的** UI设计/国际化子任务 Relates 到各内容模块卡（纯技术卡如 SDK 不挂）
- 埋点按模块真实情况填（=是会自动长埋点四件套，实现分模块验收，这是拆分的目的之一）
- 若自动化已长出不该有的子任务：每张先评论说明去向再转**废弃**（团队惯例，如 WEB-19135；不删卡）

## 跨端大需求（APP + H5 + 后端）

在上面基础上叠加 Blocks 链接表达依赖（from blocks to = from 不完成 to 没法做）：

```
AIL 后端故事 ─Blocks→ iOS 故事 / Android 故事 / H5 故事
H5 故事      ─Blocks→ iOS 故事 / Android 故事      （H5 嵌 APP 场景）
```

AIL 卡 v1 不由 kit 创建；链接可以连到已有卡 key（`"from": "AIL-140"`）。
多篇 PRD 时 description 用多行链接（总则 + 分端），见 02-field-model 的 description 规范。

## 机器人边界（千万别建、别填）

| 谁 | 自动做什么 | 触发时机 |
|----|-----------|---------|
| `testting` | 建【开发任务_xx】【测试任务_xx】子任务；填 前端工作量/AI提效人天；传 xmind 用例 | 研发接卡后 |
| `PMO` | 填 开发者、测试负责人 | 建卡后约 2 分钟 |
| `autotask` | 填 UI负责人、期望设计完成、排优日期、assignee | 建卡后陆续 |
| 项目自动化 | 埋点=是 → 每张故事下自动建【埋点方案审核任务】(icey.l)+【埋点验收任务】(adela.l)；WEB/XHHD/OPT 还会自动建 UI设计任务+国际化任务 | 建卡后 <15 秒 |

推论：**故事卡建好后子任务马上"自己长出来"是正常现象**；执行器已把机器人字段列入黑名单，plan 里出现会校验失败。

## summary 命名

格式：`【端/任务类型】【业务线】需求名`（部分场景一层前缀也可，validate 只强制至少一层【】）。

- 端：iOS / Android / Flutter / H5 / WEB/H5 / WEB
- 任务类型（子任务用）：UI设计 / 国际化 / 新页面 / UI视觉
- 业务线：AI / 公共 / 合约 / 现货 / 行情… 与团队沟通口径一致
- 需求名与 PRD 标题保持一致，别自由发挥
