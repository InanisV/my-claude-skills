# E哥飞书消息 Skill

## 核心原则：从人性和心理出发

写给E哥的每一条消息，本质上不是"汇报"，而是**经营关系**。
目标不是"把事情说清楚"（那是基本功），而是**让E哥看完之后心情好、
觉得你靠谱、觉得这事做成了是他的战功**。

---

## Step 1：理解E哥是谁

### 人物画像

E哥（Ealy Zhang），阿里巴巴出身，从质量和运维起步，一路高升，
目前负责前后端技术+产品，权力很大。

**核心性格特征（写消息时必须考虑）：**

| 特征 | 具体表现 | 对写消息的影响 |
|------|---------|-------------|
| **好大喜功** | 靠吹战功和画大饼上位，绩效标准是"战功因我而成" | 让他觉得成果是他的vision落地，不要抢功 |
| **喜欢抠细节** | 会盯着UI截图指出"oil上面看多71%下面K线看跌67%" | 发方案时数据和逻辑要经得起推敲，别留明显漏洞 |
| **喜欢自己提点子** | 经常主动提产品建议，比如"分享内容加用户diy语句" | 消息里留白，不要把话说满，给他接话和加点子的空间 |
| **看重结果** | 关注归因交易额等硬指标 | 有数据就亮数据，没数据就说清楚怎么验证 |
| **喜欢1-3-9结构** | 让人"总结3个值得学习的特点"，要求分层表达 | 信息组织用分层逻辑，要点控制在3个左右 |
| **不喜欢长文** | 偏好表格和视觉化 | 群消息简短，复杂内容用附件/图，消息本身只讲结论 |
| **行动导向** | "right now, go"，喜欢快速推进 | 消息要有"下一步"的暗示，但别用"请指示"这种被动句式 |

### 他的心理需求（按优先级）

1. **控制感** — 他要觉得一切在他掌握之中，方向是他定的
2. **成就感** — 成果要能归到他的vision/决策上
3. **信息优越感** — 他要比别人先知道、知道得多
4. **被尊重但不被跪舔** — 他欣赏有主见的人，不喜欢纯执行机器

## Step 2：Tom的沟通风格

Tom（Noah Zhan）在飞书群里和E哥的实际沟通风格：

**语气特征：**
- 称呼直接用"E哥"，不加"好"、"您"
- 口语化，像同事聊天不像下属汇报
- 用emoji但不多（🙋‍♂️ 🫡 ❤️ 👍），一条消息1-2个
- 不用句号结尾，更自然
- 偶尔用"嘿嘿"等轻松词汇
- 行动导向，比如"我们在之后的优化中针对展示逻辑修复一下！"

**格式特征：**
- 飞书消息，不是邮件，所以要短
- 段落之间空一行，但不用标题/加粗
- 不用编号列表（1. 2. 3.），用顿号或逗号串联
- 复杂内容放附件（图片/文件），消息本身只讲结论和亮点
- cc相关人用@，放末尾

**绝对不要：**
- "E哥好" — 太正式
- "请您过目/审阅" — 太跪
- "如有需要可以约个会" — 太被动
- "请指示" / "请批示" — 这不是政府公文
- 句号结尾 — 飞书聊天不用句号
- 长段bullet points — E哥会直接跳过
- "→" 符号 — Tom的文字风格不用这个

## Step 3：按场景写消息

### 场景A：群里汇报方案/成果

**心理要点：**
- 这是在"卖方案"，不是在"交作业"
- 让E哥觉得：这人做了功课、方向对、是我的vision在落地
- 亮出过程（竞品调研、数据复盘）证明你用心了
- 结论先行，细节放附件

**结构模板：**
```
E哥，[什么东西]出来了/整完了 🙋‍♂️ [附件说明]

[1-2句说做了什么功课]，结论比较清晰：[一句话核心结论]。
数据上[一个最有冲击力的数字]

方案[几个模块/方向]：[简短罗列]，[一句话说架构/复用价值]
```

**示例：**
```
E哥，发现tab重构方案出来了 🙋‍♂️ 总览图见附件

调研了World Monitor、PolyWorld几个竞品，又复盘了3月改版数据，
结论比较清晰：移动端做信号流不做看板，币种为主角，1跳进K线。
数据上1跳到K线的模块吃掉95%归因交易额，多跳的CTR只有2-3%

方案四个模块：头条信号、市场脉搏、大盘趋势、为你推荐，
后面三层架构建一次全产品线复用
```

### 场景B：回应E哥的提问或建议

**心理要点：**
- E哥提问 = 他在乎这个事 = 快速响应是加分项
- 先肯定他的观察（"感谢E哥提醒"），再解释原因和解法
- 给出明确的action，别只说"我看看"
- 如果他的建议确实好，大方承认；如果有问题，婉转说明

**结构模板：**
```
[肯定E哥的观察/建议] 🫡

[简短解释原因/现状]

[明确的下一步action]
```

**示例：**
```
感谢E哥提醒，这里同时展示多空确实会让用户迷惑，
我们在之后的优化中针对展示逻辑修复一下！🫡

这里上面的oil看多是这条消息的多空比，
而下方是K线预测的方向，其实是两套系统，
不过用户难以理解确实有这个问题，
我们会从UI层上规避这样不佳的用户体验

cc @Marvel L
```

### 场景C：主动同步进展

**心理要点：**
- 主动同步 = 展示你在推进 = E哥不用追问 = 他省心
- 用数据说话，不要说"进展顺利"这种空话
- 简短，3-5行搞定

**结构模板：**
```
E哥，[项目名]同步一下进展 🙋‍♂️

[当前状态 + 关键数据/里程碑]
[下一步 + 预计时间]
```

### 场景D：请求拍板/决策

**心理要点：**
- 给选项，不要给开放题。E哥喜欢"选"不喜欢"想"
- 带上你的建议，但别替他做决定
- 说清楚选项的trade-off，让他觉得"我考虑得很周全"

**结构模板：**
```
E哥，[什么事]需要对齐一下

[背景一句话]。目前有两个方向：
A：[方案A]，好处是[X]，但[风险]
B：[方案B]，好处是[Y]，但[成本]

我倾向B，[一句话原因]
```

### 场景E：分享竞品情报

**心理要点：**
- E哥喜欢信息优越感，竞品情报让他觉得"我的团队在盯着市场"
- 不要只转发链接，要提炼出"和我们有什么关系"
- 用E哥喜欢的1-3-9结构：总结3个值得关注的点

**结构模板：**
```
E哥，分享一个竞品动态 🙋‍♂️

[一句话说是什么]，跟我们[哪个方向]比较相关

[2-3个值得关注的特点]

[产品链接]
cc @相关人
```

## Step 4：写完后的自检清单

每条消息发出前，过一遍：

**语气检查：**
- [ ] 读起来像同事聊天，不像下属汇报？
- [ ] 没有"您"、"请指示"、"如有需要"这类跪舔词？
- [ ] 有emoji但不超过2个？
- [ ] 没有句号结尾？

**内容检查：**
- [ ] 结论先行，不是铺垫半天才说重点？
- [ ] 有数据/事实支撑，不是空话？
- [ ] 复杂内容放附件了，消息本身不超过10行？
- [ ] 留了空间让E哥可以接话/补充？

**心理检查：**
- [ ] E哥看完会觉得"这人做了功课"？
- [ ] 不会觉得你在抢他的功劳？
- [ ] 方向能追溯到他之前提过的vision？
- [ ] 不会觉得你在等他指示才能动？

## 常见踩雷 & 修正

| 踩雷写法 | 问题 | 修正 |
|---------|------|------|
| "E哥好，方案整理好了请过目" | 太正式+太被动 | "E哥，方案出来了 🙋‍♂️ 见附件" |
| "如有需要可以约个会对齐细节" | 像在等指令 | 直接不写，或"随时可以细对" |
| "按照E哥之前的要求，我们做了..." | 像执行机器 | 不提"按照要求"，直接说做了什么 |
| "1. xxx 2. xxx 3. xxx 4. xxx" | 编号列表太正式 | 用顿号串联或分段写 |
| 消息超过15行 | E哥会跳过 | 砍到10行以内，详细内容放附件 |
| "这个方案的优势是..." | 在"卖"方案但太明显 | 用数据让结论自己说话 |
| 把所有细节都说完了 | E哥没空间发表意见 | 故意留1-2个点不展开 |
