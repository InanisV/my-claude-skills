### 结构规则（9/1 因偏离金标被值班人指出，故写成硬规则）

- 链接行用带文档标题的 markdown 链接 `[YYYY年-MM月-DD日 每日洞察](url)`，不裸贴 URL。
- 「用户洞察：」后**换行**，正文独立成一段（一段只讲一个叙事：反常识判断句＋最关键依据，2–3 行内）；正文与 bullet 之间空一行。
- 第二层用 `* ` bullet：一条是「核心假设（待检验）」或「关键发现/规则对照」，一条是「产品建议」；建议下再用三空格缩进的 `   * ` 二级 bullet，**一条建议一行**。
- 「数据洞察：」后空一行，再列 3–4 个 `* ` bullet，**一个 bullet 只放一个论点**（最大异动／亮点／延续跟踪／数据请求进展）。
- 禁止把多个论点用分号串成一行；禁止括号套括号；一行不塞超过两个数字。
- 全文控制在金标的篇幅量级；样本量标注、量级账、次要竞品动态、口径说明只进文档不进消息。
- **禁写自我加码承诺**：「随报告同步／知会XX侧／持续跟进／明日更新」一律不写；议题归属句可写（如「属品牌侧议题」）。
- 值班人粘贴后手动 @所有人。

## 详情文档（飞书 docx）

标题：`2026年-0M月-DD日 每日洞察`。用 lark-cli 官方创建流程（init-draft → 写 XML → parse 预检看 assessment.status → create → fetch 回读验证）。改稿用 str_replace/block_replace；文档为当日自建且无他人内容时允许 overwrite 重建（图片用本地文件重传）。
