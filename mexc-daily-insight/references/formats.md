# 格式契约（严格照组内 Connor/Tili 房式，勿自创章节）

## 群消息稿

### 风格铁律
- 全文 **8 行以内**，每段 1–3 短句；照 Tili 8/25、8/28 的密度。
- 消息只留**重点与亮点**；样本量标注、量级账、次要竞品动态、口径说明——全部只进文档不进消息。
- **禁写自我加码承诺**：「随报告同步 / 知会XX侧 / 持续跟进 / 明日更新」一律不写（发群即知会，跟进走登记表状态列）。议题归属句可写（如「属品牌侧议题」——把归属推离值班人是减负）。
- 固定开头 `【每日洞察｜M.DD】`＋文档链接；值班人粘贴后手动 @所有人。

### 模板与金标样例（8/31 实发版）

```
【每日洞察｜8.31】
<文档链接>
竞品更新：今日无新版本，近三日仅 Bitget 2.92.0 有实质动作（交易机器人入口重构+UTA升级+直播增强）
重大舆情：<仅在有重大事件时保留此行，一句话>
用户洞察：
<一句洞察句——反常识、指向钱>；<一句当日数据呼应>
* 核心假设（待检验）：<假设一句>
* 产品建议：
   * <建议1，通常是数据请求：请数分拉XX，差距显著即立项依据>
   * <建议2，机制评审或AB预埋>
数据洞察：
* <最大异动一句，标注与今日洞察互证/延续上周洞察>
* <亮点一句>
* <延续跟踪一句>
```

洞察句的品味参照：「留存的答案可能不在交易里」「激励的确定性要前置」——先给反常识判断，再给证据，不要先铺证据。

## 详情文档（飞书 docx）

标题：`2026年-0M月-DD日 每日洞察`。用 lark-cli 官方创建流程（init-draft → 写 XML → parse 预检看 assessment.status → create → fetch 回读验证）。改稿用 str_replace/block_replace；文档为当日自建且无他人内容时允许 overwrite 重建（图片用本地文件重传）。

### XML 骨架（照抄改内容）

```xml
<title>2026年-0M月-DD日 每日洞察</title>
<h1>今日竞品 App 更新</h1>
<table>（竞品/最新版本/时间/更新重点，5行，更新重点末尾附 App Store hk 链接）</table>
<h2>重点结论</h2>
<callout emoji="📌"><p><b>今日判断：</b>一句话。无更新就明说；有实质更新点名建议真机走查。</p></callout>
<p><b>竞品重大动作｜主题：</b>仅在有重大动作日保留此段（Tili 8/24 先例），事实+来源链接，可带一句对照观察，不提建议。</p>
<p><b>重大舆情知会：</b>仅在有重大舆情日保留，逢链必点后才写「已被引用」。</p>
<h1>今日用户声音洞察</h1>
<h2>洞察标题（反常识判断句）</h2>
<ul>
<li><b>目标用户：</b></li>
<li><b>用户声音：</b>原话转述+原帖链接+样本边界标注</li>
<li><b>数据互证：</b>当日看板数字</li>
<li><b>核心假设（待数据验证）：</b></li>
<li><b>MEXC 现状：</b>[待内部核实] 标注诚实写；现状三查结果</li>
<li><b>行动建议（归属与落地待评审）：</b>①通常含一条数据请求 ②机制评审 ③AB预埋</li>
<li><b>用户收益：</b>…；<b>平台收益：</b>落在钱指标，量级换算标「若假设成立」</li>

<h1>数据洞察与行动项</h1>
<grid><column width-ratio="0.32"><img path="@./dau.png" caption="注册DAU看板"/></column><column width-ratio="0.68"><img path="@./uj.png" caption="UJ核心链路"/></column></grid>
```

### 文档写作注意
- 表格列表等块级结构在 range 替换时会因「无 ID 的列表容器」失败——大改直接 overwrite 重建更可靠。
- 图片本地留档（当日 dau/uj 截图），overwrite 时随 XML 重传。
- 环比口径必须标注；数据图只是证据，正文必须给文字结论与关键数值。
