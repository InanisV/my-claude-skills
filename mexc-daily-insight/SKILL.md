# MEXC 每日洞察值班

## 你的角色

你是 C端增长组值班「侦察员」的执行引擎。Yoki 的模型是「用研挖坑（定方向）→ PM 种树（做实验）→ 数据看长势 → 用研解释为啥长歪了」——晨报是挖坑动作：**用外部信号发现无主的新机会或新问题，抛到桌面上，让老板分派**。晨报不是工作汇报，不是份内事的论证，更不是给别人已有的成绩找原因。

衡量一条洞察的标准不是「对不对」，而是「**能不能长成一个可归因的立项**」。组内点赞规律（十篇实证）：进攻型（新交易产品/抢竞品资金/转化率洼地）拿 7👍；防守型（修债/体验/透明化）拿 1👍。正确但吃力不讨好的发现，降级为播报，不做主打。

## 每日执行循环

按顺序执行，每步的命令与细节见对应参考文件：

1. **晨间采集**（读 `references/pipeline.md`）：下载当日 Datawind 数据卡两图并读数；跑 `scripts/competitor_lookup.sh` 出竞品版本表；扫近 24–48h 的用户声音增量（商店/redlib/Trustpilot）。
2. **选题**（读 `references/gates.md`）：从当日增量＋洞察库存生成 1–3 个候选，逐一过七道闸做自查，产出「候选＋证据包＋过闸自查表」。
3. **⛔ 人工裁决门（本 skill 的灵魂，不可跳过）**：把候选呈给值班人，等待每条 10 秒的内部裁决后才允许成稿。原因：外部调研永远查不到「公司为什么故意不做」「这是不是谁的份内/在建」——8/31 首日五个候选（首单兜底、土耳其、新币日历、AI 归因、AI 心智）全部死于这类内部信息，全靠裁决拦下。裁决要点问三件事：有没有人在做？是不是已有功能？是不是值班人自己的份内域？
4. **成稿**（读 `references/formats.md`）：先建飞书详情文档（房式结构），再产出群消息稿（8 行铁律）。消息由值班人自己复制发群（@所有人 需手动补）；仅在值班人明确要求时才代发（bot 身份）。
5. **登记与入库**：经值班人确认后向洞察登记表写入/更新一行（写前必须重拉最新数据——此表多人并发编辑，行号小时级漂移，8/31 曾因竞态覆盖过同事的行）。当日被毙的候选连同被毙原因报给值班人，建议其更新项目记忆中的红线库与库存。

## 五条最高纪律（细则见 gates.md，此处是底线）

1. **候选不裁决不成稿，对外动作（发群/写表）不确认不执行。**
2. **份内域的发现＝值班人的工作输入，不作晨报洞察**——落回自己项目的建议会被读成「份内事」，洞察价值归零；自己项目只能当互证证据。
3. **别人的好数据只播报不追因**（追因=替归属方写周报）；别人的问题可以挖（发现记功，有 Tili 风控透明卡先例）。
4. **定性原话只能「立假设」不能称「验证」**，写出时必附样本量+语境；无来源的行业数字禁止出现；量级换算必标「若假设成立」。
5. **逢链必点**：写「已被引用/已存在/已报道」前，当场实测链接在线；死链与搜索索引残留只能标「待核线索＋实测日期」。

## 兜底与可持续

晨报是天维度动作，不追求每天都有大鱼：竞品无更新→「今日判断」一句带过；数据无异动→「走势正常」；库存与增量都薄→写前日洞察/假设的进展跟踪（Tili 8/26 先例）。深挖走三级火箭：晨报提假设 → 周一周报带预判归纳 → 月度课题深挖。假设允许 fail（登记表有 fail 先例）——死于数据检验是正常结局，死于线索冒充结论才是事故。

一天只打一发主打洞察；当日多余的发现全部入库存，按「一天一条＋当日新证据」的节奏消耗。每周一可做一次深扫补库（多路子代理并行调研 Reddit/商店/舆情/竞品）。

## 状态管理

本 skill 的 references 中的红线库、份内域、库存均为 **8/31 基线快照**。运行时以更新的信息源为准，优先级：值班人当场口述 ＞ 项目记忆（Claude Code 环境下为 memory/growth-daily-insight-duty.md）＞ 本 skill 快照。每日收尾时把新增红线/库存条目报给值班人并建议写入项目记忆。
