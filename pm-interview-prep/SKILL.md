# PM Interview Prep

帮 Tom 准备产品经理面试的全流程工具。核心是把一份候选人简历转化成一个**带追问、带听点、带评分模板**的面试准备包。

## 核心方法论（这是 skill 的灵魂，不要偏离）

1. **过往经历 > 情景假设**。问"你之前做过 X 吗、怎么做的"远好于"如果让你做 X 你会怎么做"。情景假设容易让候选人编一个漂亮答案，过往经历挖到底就会现原形。
2. **简历先扫红旗**。任何面试准备的第一步是把候选人简历当作"待审计文档"看，找数据矛盾、归因模糊、规模错配、时间线断点——这些是后面追问的弹药。
3. **每题至少 1-2 层追问**。"具体多少？""哪个时间点？""谁来做的？""上线后效果怎么验证？"——细节是测谎仪。
4. **听点比问题更重要**。问出问题不难，难的是知道她答得好/差/在套话。每题都要预设 red/yellow/green flag。
5. **结构化评分**。面完按维度打分，写一段 30-50 字的整体判断，比"凭感觉给个总分"有用。

## 工作流程

**Step 1：理解面试上下文**

在开始之前，先快速搞清楚 5 个关键变量。如果用户没说，直接问（一次问完，不要来回挤牙膏）：

1. **候选人简历**（必须）— 文件或粘贴文本
2. **岗位 / 业务方向** — 比如"合约 AI 产品 PM"、"增长 PM"、"用户产品 PM"。决定题目侧重
3. **面试官身份和经验** — Tom 自己面 vs 代 leader 面？第一次面试 vs 有经验？影响紧张度提示和题目难度
4. **重点考察方向** — leader 或自己最关心什么？默认是增长思维 + 数据习惯 + 竞品 + 市场洞察四件套，但如果有特别侧重要说
5. **面试时长** — 30/45/60 分钟，决定问题数量和深度

如果上下文已经能推断出来（比如对话里已经讨论过候选人），就直接进入 Step 2，但在产出前确认一下。

**Step 2：简历红旗扫描**

打开候选人简历，按 `references/resume-analysis.md` 的检查清单跑一遍。产出一个 **3-5 条"必问点"清单**，比如：

- 数据矛盾：A 处说 500 万注册，B 处说 5 万注册 → 必须问清口径
- 归因模糊：把"币上线币安"算作个人成绩 → 必须问她在里面具体做了什么
- 规模错配：声称管理 20 人但项目只有 5 万 DAU → 必须问团队构成
- 跨界跳跃：从视觉传达跳产品 → 可以问驱动力
- 时间线断点：某段经历只写 1 行 → 可能是不愿意讲的部分

这些"必问点"会被 Step 3 编织到题库里。

**Step 3：生成定制化题库**

根据简历内容 + 重点方向，从 `references/question-bank.md` 里挑选并定制问题。**不要直接复制题库**，要把候选人的具体项目名、具体数字、具体业务嵌进去。比如不要问"你做过的最有效的增长动作是什么"，要问"你简历里写日交易量增长 300%，能讲讲里面最有效的一个动作吗"。

题库覆盖 6 个标准模块（45-60 分钟版本）：

| 模块 | 时长 | 主问题数 |
|---|---|---|
| 1. 开场暖身 | 5 分钟 | 1 |
| 2. 增长思维（项目深挖） | 15-20 分钟 | 4-5 |
| 3. 数据分析习惯 | 10-15 分钟 | 3-4 |
| 4. 竞品分析 | 10 分钟 | 2-3 |
| 5. 市场洞察 | 5-10 分钟 | 1-2 |
| 6. 个人成长 / 软实力 | 5 分钟 | 2-3 |
| 7. 候选人反问 | 5 分钟 | — |

每个主问题必须配：
- **追问 2-3 条**（按候选人可能的回答方向预设）
- **听点**（red flag 是什么、green flag 是什么）

详细题库和追问模板见 `references/question-bank.md`，听点细则见 `references/listening-cues.md`。

**Step 4：评分模板和面试技巧提醒**

附上 `references/scoring-template.md` 的简化版作为面试结束后填写的工具。包含 4 个维度（增长思维 / 数据习惯 / 竞品 sense / 表达结构）+ 30-50 字整体判断。

最后给 5-7 条**针对这次面试的具体提醒**（不要泛泛的"多倾听"），比如：
- "简历那个数据矛盾，建议放在 Q4 增长归因里顺势问，别单独抛出来质问"
- "她讲到第 3 分钟还没到点的时候，可以打断：'背景 get 到了，能直接讲关键动作吗'"
- "她讲 Web3 名词的时候要让她翻译成不懂行的人能听懂的版本"

## 输出格式

最终产出一个**面试准备包**，结构如下：

```
# 候选人速读
[3-5 段，包含基本信息 + 红旗清单]

# 面试流程建议
[表格：环节 / 时长 / 目标]

# 核心问题清单
## 模块 1：开场暖身
### Q1：[主问题]
**追问**：
- [追问 1]
- [追问 2]
**听什么**：
- Green flag：...
- Red flag：...

## 模块 2：增长思维
[同样格式，4-5 个主问题]

... 各模块 ...

# 评分模板
[4 维度评分表]

# 面试技巧提醒（针对这次）
[5-7 条具体建议]
```

输出用中文，结构清晰，可以直接打印或放 iPad。每个主问题独立成块，方便面试时翻阅。

## 重要原则

- **不要写"标准答案"**。听点是描述好答案的特征（"能拆出绝对值不只是百分比"），不是写一个范文。面试官需要的是判断能力，不是答案对照表。
- **不要把候选人当反派**。红旗扫描是为了"问出真实情况"，不是为了"抓她破绽"。最终判断是基于综合表现，不是单点扣分。
- **追问要克制**。每题 1-2 层追问足够，不要变成审讯。如果她答得已经很完整，可以少追或不追。
- **量身定制 > 通用模板**。如果候选人是做 Web3 的、要面 CEX 业务，竞品题就要问"DEX 和 CEX 的差异"这种迁移题；如果是做 SaaS 跳消费产品，就问"to B 和 to C 思维的差异"。
