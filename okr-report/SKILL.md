# OKR 季度总结 / 项目汇报

## 核心理念

一份好的 OKR 汇报不是把数据按格式分区堆上去，而是用一条因果链把成果讲清楚。Yoki 评过一版总结：「挺好的，就是有点分散，逻辑不够紧密。」这几乎是所有数据汇报的通病，根因永远是按汇报格式分区组织（成绩单→过程指标→交付→成果→计划），而不是按一条故事主线。

记住一句话：**每个数字都要回答「对比谁、为什么、属于哪条主线」。汇报是一条因果链，不是数据的分区陈列。**

还有一条底线：**讲好故事，但绝不编故事。** 可以只讲好的那一面、可以裁剪、可以重新框定，但每个字都必须是真的。

## 工作流程（四步，不要跳）

### Phase 0 — 读全数据，核对口径

- 把用户给的所有数据截图逐张读完，**每个要用的数字都和原图核对一遍**。数据汇报里数字错一个，整篇可信度归零。
- **核对 KR 口径**：headline 数字到底量的是什么。踩过的坑：看板 KR 是 10.52E，分模块表却是 9.90E，差 6%。一问才知道看板取的是「合约+现货总交易额」，分模块表是「合约」。口径不对齐，后面全错。
- 遇到对不上的数字，**先问清楚再写**，不要自己猜或硬凑。

### Phase 1 — 先讨论对齐，再动笔

**不要拿到数据就开始写文档。** 先和用户对齐这几件事再动手：
- 故事主线是什么（某季的主线可能就是「场景化促交易是增长引擎」）
- 整体结构（成绩单 + 几条产品线 + 下季度）
- 哪些是重点产品要深挖
- 把所有需要拍板的数据疑问列出来一次问清：KR 口径、某个指标的归因、要不要露出某个小绝对值、负面数据怎么处理

产出一张「上季 vs 本季」核对表给用户过目，顺便让他抓错。**用户拍板了结构和口径，再进 Phase 2。**

### Phase 2 — 产出 Claude Code 的 lark doc prompt

汇报正文做成飞书文档，方式是给用户一段 Claude Code 的 prompt（用户贴给 Claude Code 跑）。要点：
- **完整内容写进 prompt，数字一字不改。** Claude Code 看不到截图，所有核对过的数字和叙述都由你写进 prompt，它只负责渲染成飞书 block。
- 让 Claude Code 读 `lark-docx-authoring` skill，用 native block 创建，不要 markdown 整体导入（表格会丢单元格结构）。
- 提醒：中文标点、`&` `<` `>` 转义、章节序号写进标题文字、**删除文末「(Note: ...generated by AI...)」水印**（飞书会自动加，每次都要删）、round-trip grep 校验关键数字。
- 文档已存在且带评论时，**必须 block-level patch，不能整体重建**（否则评论锚点会丢）。

### Phase 3 — 一图流封面

给 AI 周会配一张暗色一图流当开场页，用 `mexc-infographic` skill。结构：成绩单 + 三大重点 + 下季度，三段。820px 暗色，Playwright 转 2x PNG。

## 铁律：每个数字三要素

这是整套方法论的核心，也是 Yoki 两条具体批注的根源。

### 1. 对比谁（基线）

**凡出现「环比 / +X% / 升至 / 放大」，都要标注对比的基线（从 X 到 Y）。** Yoki 原话：「讲同之前比，要标注之前的数据。」

- 反例：AI 有效交易额日均环比 Q1 增长 20% 至 10.02E
- 正例：AI 有效交易额日均从 Q1 的 8.36E 增至 10.02E（+20%）

表格里给 from→to，正文里也要给。不要只在表格给、正文光秃秃放个百分比。

### 2. 为什么（归因）

**每个指标的变化都要说清楚是什么导致的。** Yoki 原话：「是什么导致的曝光增加？」

- 反例：智能 K 线曝光超 15% 目标
- 正例：智能 K 线曝光超 15% 目标，曝光增长主要来自场景化促交易，新增的机会卡片、亏损顶飘、跳转智能 K 线交易计划等入口把交易场景流量导向智能 K 线

归因要真实。是产品逻辑推的就标出来让用户确认，别瞎编因果。

### 3. 属于哪条主线（归属）

**一个数字要挂到它所属的故事主线上**，而不是孤立漂着。智能 K 线 +47% 不是凭空的，是场景化引流的结果，就把它讲在场景化这条线里。

## 故事线优先于格式分区

这是治「分散」的根本招。

**别按汇报格式分区组织**（成绩单/过程指标/交付/成果/计划各一节），那会让同一个主角被摊在四五个区里：智能 K 线在过程指标、分模块、分功能、重点卡片各出现一次，场景化在交付、成果、两个重点各出现一次，读者每次都要自己拼线索。

**要按因果主线组织**：先定 1-2 条核心主线，整篇围着它讲「做了什么 → 带来什么（带基线）→ 为什么」，一条龙。

具体三条：
1. 先定主线再铺内容。一个主角只在它的主线里出现一次。
2. 每个数字自带基线和归因，对比、原因、归属一口气说完。
3. 砍掉重复的指标表。别同一批数据按模块、按功能、按过程各列一张表平行铺开。

## 讲好但不编故事：八个实战手法

1. **先讲赢的，但全是真的。** 开篇结论先行，把最硬的战功放最前。
2. **可以裁剪，不能编造。** 体量小的衰退模块可以不单列（注明「其余模块体量较小」），但不能把假数字写上去。
3. **难看的指标用「因果真实」的方式重新框定。** 快讯曝光 -18%、点击人数 -12%，但这是主动缩小弹窗、修复遮挡的结果，点击率反而 +7.12%，讲「主动缩量提质，少弹精弹不打扰」。前提是这个因果是真的（确实做了遮挡优化）。
4. **小绝对值用百分比、不用绝对值。** 发现 2.0 归因 122万→382万 绝对值太小，主动提时只讲 +214%。**但如果评审要求标基线，露出基线就会暴露小绝对值，这时要么接受露出、要么直接拿掉这个指标**（发现 2.0 后来就只讲曝光 +130%）。
5. **矛盾指标，主打 KR 那个。** 交易额涨了但交易用户数、新增转化降了，以交易额（KR 本身）为主指标，用户结构解释为「高价值用户客单价提升」，用户数下降不主动展开。
6. **AB 不显著，主打声量和产品形态。** 发现 2.0 的 AB 转化和对照组基本持平，就主打曝光 +130%、为你推荐成最强承接模块，AB 那块如实标「持续观察」。
7. **平庸档位不上封面。** B+ 不是亮眼结果，大字报（一图流）上别放评级，主打「跑赢大盘 + 增长」。文档里细看场景可以留，但封面不头条它。
8. **战功归属要准。** 把增长归到真正驱动它的产品线（智能 K 线 +47% 归功于场景化引流，因为跳转是你设计的）。不要把自己没做的模块（比如别人负责的 AIbot）当自己的战功。

## 领导口味（E 哥 / leadership）

- **1-3-9 结构**：1 句结论 → 3 条主轴 → 9 个论据。
- **结论先行**：每章、每段第一句就是结论。
- **标题自带结论**：不写「核心指标」，写「核心成绩单：跑赢大盘」。
- **加粗等于正面信号矩阵**：只加粗具体数字、达成档位、战略信号，不加粗形容词和主观判断。把所有加粗连起来读，应该是一串正面信号。
- **中文标点**全程。
- **规避负面词**：不写「风险 / 挑战 / 不确定 / 可能失败」，用积极框架。
- **为 AI 总结优化**：E 哥会让 Claude 帮他总结这篇，所以 TL;DR 要是完整的信号矩阵、表格要结构化（AI 会当事实读）。

## 反 AI 痕迹（强制）

- 不用 em-dash 作分隔符
- 不用中文分号
- 不写「赋能 / 综上 / 确保 / 旨在 / 值得注意」等词
- 不过度加粗
- 句长有长有短，结构不要完全对称

## 推荐结构模板

```
开篇 TL;DR：一段话，把 KR + 核心增长 + 最硬战功讲完（信号矩阵）
一、本季成绩单：KR + 过程指标 + 大盘占比（一张表，每个数带基线）
二、过程指标：逐个讲清「涨了多少 + 为什么涨」
三、本季度做了什么：按产品线（不是按需求）组织，每条带价值
四、带来了什么：分主线讲成果（带基线），重点产品深挖
五、下季度计划：延续验证有效的方向
```
