# 01 · 进件、交付合同、授权与决策文件

## 1. 访谈（不超过 6 问，能从材料里读到的不问）

1. 受众与目的：内部老板和业务团队、外发用户、还是各一版？要"让人想去用"（发布片）、"让人会用"（教程片）还是"让人知道怎么排"（流程说明片）？
2. 语言与版本：中文、英文、各一版？内部段落（竞品对比、内部机制）外发要删。
3. 时长与渠道：发在哪里，16:9 还是 9:16，多长。
4. 素材与权限：有没有完整录屏、设计稿、demo；App 能不能切语言；谁能录。
5. 事实边界：能说什么数字、能不能点名竞品、口径是谁定的。
6. 风格参照：两三条"就要这种"的片子，或者明确不要什么。

输出 `brief/brief.md`（模板 `templates/brief.md`），沿用设计团队通用的 Brief 五段：Overview / Objectives / Audience / Key Messages / Tone & Style。

## 2. 交付合同（开工前填满，模板 `templates/delivery-contract.md`）

| 项 | 为什么必须先定 |
|---|---|
| 介质：MP4 / GIF / 外链 | 有的上传入口只收 GIF；GIF 无声，整套配音白做 |
| 大小上限（实际字节数） | 按严格十进制验收，目标留 4% 余量 |
| 分辨率 / 帧率 / 时长 / 循环 | GIF 帧延迟是 10 ms 单位，帧率不能任意 |
| 声音：要不要、谁的音色授权 | 外发只能用公司授权音色 |
| 受众版本：内部 / 外发 / 语言 | 决定分支数和删减 |
| 合规角标：要不要、文案谁给 | 外发留占位，文案由宣发或合规提供 |

合同有空项就问人，不猜；上传渠道的报错原文也属于合同信息。

## 3. 授权与决策文件（`brief/decisions.md`，模板 `templates/decisions.md`）

只记录四类：
- 允许把哪些内容发给哪些服务（旁白文本 → 哪些 TTS；录屏 → 哪些本地或平台工具；设计稿 → 哪些工具）。
- 人做过的选择：方向、音色、配乐、删减、隐私策略（用户名 allow / blur / demo）。
- 事实口径与来源：数字从哪份材料来、谁认可；没有来源的数字不进成片。
- 介质合同的历次变更（后者覆盖前者，保留日期）。

同范围的授权不重复索要；新增接收方、新增用途、公开范围变化时重新确认。授权绑定项目，不随 kit 迁移。

## 4. 档位判定

- 轻量档：一个功能点、内部、一种语言、不外发。
- 标准档：大功能、老板和业务团队、可能转发给高层。
- 外发档：标准档加外发分支。

档位决定阶段 2 和 3 的深度，不改变硬规则。
