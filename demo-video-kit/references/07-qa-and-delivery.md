## 1. 仪表全套

| 维度 | 指标 | 性质 |
|---|---|---|
| 旁白 | 归一后字错率 0；UTMOS；语速；句尾斜率；音高标准差 | 前一项门禁，其余诊断 |
| 混音 | -16 LUFS ±1；真峰值；旁白期间音乐频段压低；三个无旁白窗口为数字零 | 门禁 |
| 对拍 | 关键落点对实际音乐瞬态 < 1 帧 | 门禁（只认证关键落点） |
| 画面连续 | 运动段相邻重复帧 < 2%；无 A-B-A 单帧跳变；每 0.5 秒窗口无未计划静止；产品段相邻帧差 > 25 的候选逐对解释 | 门禁 + 解释 |
| 构图 | 卡片两两不重叠、不出画、不进禁区；相邻两拍版式不同、光带位置不同；阶段串行按时间戳核对 | 门禁 |
| 清晰度 | 屏幕区域拉普拉斯方差对同源基线 ≥ 1.5 倍；特写 OCR ≥ 90% | 门禁 |
| 文字 | 标题、字幕、字卡、关键数字对实际编码帧 OCR 逐项通过；OCR 不给期望文本提示 | 门禁 |
| 时长 | 总长、各拍硬上限、旁白占比、最后一句距片尾 ≥ 3 秒 | 门禁 |
| 黑帧 | 计划黑场预声明区间，其余无黑帧 | 门禁 |
| 美感 | LAION、VLM 十项 | 诊断 |

每项的方法和边界写进 `reports/instruments.md`，以后每版跑同一套。

## 2. 最终编码优先与口径

- 读最终 MP4 的像素、PTS、AAC；storyboard 里计划的帧不等于发生的帧；DOM 读回（transform、可见性、数字状态）和最终像素分开记录。
- MAE > 25 是候选触发，不等于一次剪辑硬切；连续缩放也会超阈值，逐对目视解释后保留数值失败。
- 全画面 0% 重复不是局部 UI 的重复率证书；背景在动不代表界面没卡住。
- 最后非黑帧必须从实际编码文件找，不用"总帧数减 N"猜。
- OCR 把"币"识成"市"、"AI"识成"Al"这类，目视确认后保留机械失败，不改成通过。
- 命令返回码 0 不等于 QA 通过，读实际 JSON 结果。

## 3. 保留失败

QA 报告的开头先列未过项和原因，再列通过项。用户满意、文件齐全、门禁全过是三件事；发布成功不会让未过项变成通过。原值不改阈值不动，想放宽就写"改为诊断项"并注明日期。

## 4. 交付包与版本分支

- 版本分支在同一个 storyboard 里用分支字段：内部版（含内部段）、外发版（删内部段，合规角标占位，公司授权音色，界面与字幕换语言）；画面流一致的版本比 SHA，分辨率不同的比抽帧 SSIM。
- 每个版本：1080p 成片、4K 母版（标准档以上）、两个配音版本供人耳选。
- 文件：storyboard.json、script、qa_report.md、run-log.md、接触表（每 2 秒一帧）、关键段落的密集接触表（开场每 0.5 秒、特殊拍每 1 秒、片尾每 0.5 秒）。
- 交付说明写清每个文件是什么、给谁、限制（无声、内部）。

## 5. 上传排障与 GIF

真实事故：MP4 从 4.7 MB 压到 0.8 MB 仍上传失败，问同事才知道入口只收 GIF，再补充 25 MB 上限。教训是先问合同，不是先压文件。

- 上传失败先问三件事：介质、大小上限、报错原文；都不知道时给可试的替代，明确"未确诊"，不无限压小。
- GIF：从原生清晰源取帧，不从多轮压小的视频转；两步全局调色板再 paletteuse；256 色；先关抖动减熵再权衡尺寸与帧率（720p/10fps 常是 25 MB 内的平衡点，别无限降帧率）；`-loop 0`；帧延迟 10 ms 单位，8 fps 会 120/130 ms 交替，用所有帧延迟之和核总时长；按严格十进制字节验收，目标留 4% 余量；逐帧解码验证尺寸、帧数、全长、循环；GIF 无声，说明里写明。
- 小 MP4：只换码率不重渲；低码率 AAC 真峰值可能顶过 0，重新量。

## 6. 复核材料

人复核只看四样：成片、接触表、QA 报告首段（未过项）、10 行汇报。提意见格式"第 N 拍怎样"、"用 voiceB"、"换 musicB"，按镜号增量改。
