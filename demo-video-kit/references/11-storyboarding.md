## 1. 为什么分镜阶段要占最大预算

上一条片真正的分数跳升只发生过一次：形式推翻、分镜重做的那一轮。之前四轮在版式、字号、光照、音色上的打磨加起来不如那一次。原因很简单：生产阶段只能把分镜里有的东西做得更好，做不出分镜里没有的东西。分镜草率，后面所有精力都在给一个错的结构抛光。

规则：分镜阶段的精力不低于生产阶段；分镜评审不过，不进生产；生产中发现的"结构问题"回到分镜改，不在渲染器里打补丁。

## 2. 前期研究：三件事（都要落成文件）

1. 产品事实：所有入口、关键页面、真实内容、能说的数字与口径、不能说的事（从录屏索引、设计稿清单、brief 里来）。分镜里每一个画面必须能在这份清单里找到依据。
2. 受众认知：他们已经习以为常的是什么（别拿基础功能当亮点），他们会被什么打动（唯一的差异点、一个具体时刻），他们会挑什么刺（内容质量、口径、与竞品的关系）。
3. 参考片拆解：两三条同类型的好片，逐条拆出结构（几拍、各多长）、镜头时长分布、文字密度、音乐结构、记忆点在哪。拆解结果写成 grammar.json 当本片的目标，不拍脑袋定秒数。

## 3. 主线：三个候选，选一个

- 一句判断：观众看完记住的那一句话。
- 唯一差异点：只允许一个，其他优势让位。
- 一个事件：谁、什么时候、几分钟、发生了什么，功能在事件里"被用到"。

写三个候选主线，各配一段 logline（三句话）和各自的风险；用 02 第 1 节的片型表判断形式；由人选一个，或执行者按"差异点最锐、事件最具体、素材最可得"自评后给出推荐并说明理由。只写一个候选就定稿是草率的典型表现。

## 4. 结构：beat sheet 与能量曲线

- 八到十拍，每拍写：目的、情绪、能量（高中低）、时长区间、承接上一拍的动作（因果）。
- 画出能量曲线：开场高、揭晓最高、中段起伏、收束回高；相邻两拍不能同能量三次以上。
- 标出：三个无旁白窗口、三个记忆点、硬切上限（三处）、内部专用拍、合规角标位。
- 用问题制造信息缺口：开场一个问题，揭晓回答它；每拍结尾留一个"然后呢"。

## 5. 分镜表：每镜一行，每镜一个问题（模板 `templates/shot-list.md`）

每拍拆 2 到 3 个子镜头，每镜写满这些列：

| 列 | 内容 |
|---|---|
| 镜号 | S04b |
| 问题 | 这个镜头回答观众的什么问题；答不出来就删 |
| 景别 / 主体 | 全景、特写；主角是谁 |
| 运动 | 用 motion-prompt 的名称和编号（见 12），加时长、幅度、缓动 |
| 转场（到下一镜） | 名称与时长（硬切、推入、翻转、光扫…） |
| 时长 | 秒，区间 |
| 旁白 | 一句，≤ 10 字；或"无" |
| 文案 | ≤ 10 字；一个词品牌色 |
| 画面事件与声音 | 事件名、发生在第几秒、配哪一类音效或无 |
| 来源 | GEN / UI 真机 / 复刻 / HTML；具体素材或页面 |
| 版式 / 色温 / 光带 | 02 第 4、6 节字段 |
| 素材需求 | 需要补录或生成什么 |

规则：每镜一个运动；一个镜头只回答一个问题；相邻镜头的运动方向有因果（上一镜推进，下一镜就在推进的终点开始）；每拍第一镜就有事发生。

## 6. 关键帧板与动态预演

- 关键帧板：每镜 2 到 3 张静帧（复刻界面或真机截图放进舞台，带版式和色温），拼成一张板；板上每镜标问题和运动名。
- 动态预演（motion board）：每镜的运动先用 motion-prompt 的样本（或本项目自建 pack 的样本）拼成一条"运动小样"，只有形状和运动，没有正式内容；用来看节奏和运动语言是否成立。它比 animatic 便宜一个量级。
- animatic：关键帧 + 简单位移 + 真实配音 + 配乐。两处都是人看一分钟就能拍板的东西。

## 7. 分镜评审（门禁，模板 `templates/storyboard-review.md`）

执行者先自评，再交人看板。任一项不过，回到对应节修，不进生产：

1. 主线一句话能复述；唯一差异点只有一个。
2. 事件具体（谁、何时、几分钟）；功能在事件里被用到，没有功能清单段。
3. 每镜有问题，答得出；没有"为了展示而展示"的镜头。
4. 因果连续：产品段内每镜承接上一镜的动作，硬切不超过三处。
5. 能量曲线有起伏；三个无旁白窗口；三个记忆点能指出来。
6. 开场第一帧有事发生；结尾有收束（最后一句距片尾 ≥ 3 秒，定格）。
7. 旁白是话不是标语，总时长 ≤ 片长 60%；文案 ≤ 10 字。
8. 每镜来源确定、素材可得；补录清单已开。
9. 每镜运动有名称、时长、缓动；相邻两拍版式和光带不同；卡片类元素满足碰撞规则。
10. 内部与外发分支标清；数字都有来源。

## 8. 冻结与之后的改动纪律

评审通过写 storyboard.json v1 并冻结。生产阶段只允许按镜号增量修改；出现"结构不对"的感觉时，回到第 3 到 5 节重走，而不是在渲染参数上找补。两到三轮后定稿。

## 9. 时间预算（标准档 5 天的参考分配）

研究与主线 1 天，分镜表与关键帧板 1 天，动态预演与 animatic 半天，评审与修改半天；生产 1.5 天，修改与交付 0.5 天。轻量档按比例压缩，但分镜仍不少于总时长的三分之一。
