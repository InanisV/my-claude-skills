# 国际化词条提取 —— 从 PRD 抽出要翻译的 UI 文案

> 用于填 PRD 的 **Localisation Requirements** 章节。源自成熟的「词条筛选器」工作流。核心是**严禁编造**：只抽 PRD 正文里**逐字真实出现**的前端文案。

## 铁律（违反则整份词条作废）
- 你输出的每一条，都必须能在 PRD 原文里**找到对应的文字**。
- PRD 正文里找不到任何前端文案 → **直接输出空**，什么都不写。
- **严禁**凭空补"常见交易所通用词条"：推荐、热门、新币、涨幅榜、跌幅榜、K线、限价、市价、止盈止损、资金费率、添加自选、立即交易、搜索币种… 这类若未在本 PRD 原文出现，**绝对不许输出**。
- 拿不准某条是否真实出现 → 不输出。**宁可少，不可编。**

## 什么是词条
词条 = 最终显示在 App 界面、被终端用户看到、需要翻译的文本字符串。三条**同时**满足：
1. 是给 App 用户看的文字，不是给产品/开发看的描述；
2. 是具体的**文案内容本身**，不是元素名/字段名/规则名；
3. 出现在 UI 上：按钮、标题、提示语、标签文字、状态文案、模板句式等。

## 常见误判（不要抽）
- **UI 元素名**：信号条、弹窗、卡片、icon、按钮、tab、走势线、多空比条
- **字段/属性名**：主文案、标题文案、币种icon、涨跌幅、24h走势线
- **后端常量/类型代号**：RT_TRADE、standard_ElementClick、template_name
- **规则/格式描述**：千分位、KMBT 缩写规则、四舍五入、降级取下一张
- **交互/动画描述**：浮现动画、下滑手势、滑入动画
- **功能模块名**：信号条延时触发、为你推荐接口
- **文档结构性文字**：触发逻辑、需求逻辑、异常场景、兜底逻辑、验收标准
- **纯占位/兜底符号**：`--`、`暂无`（除非 PRD 明确说明它作为展示文案）
- **纯变量模板**：`{收益}({收益率})`、`{值}`（只有变量和标点、无可翻译文字）
- **格式符号**：`$`、`%`、`+/-`（单独出现时；作为完整文案一部分则整条保留）

## 在 PRD 里怎么找
- 带中文引号「…」的内容（旧稿若写成 `"…"` / 反引号包裹的形态，一并找出来，落表时按 `07 §二` 统一成「」）
- "文案：xxx"、"默认文案：xxx"、"用尽后文案：xxx" 后面的内容
- 模板句式，变量用 `{}` 保留（如「{数量}人在交易」）
- 同一字段在不同条件/分支下的多版本文案（**全部**提取，分行）

## 输出与清洗
- 每行一条，**保留 `{}` 占位符**；不加引号、不加编号、不加标题、不加解释；第一行就是第一个词条。
- 复合文案/模板句式**保持完整、禁止拆分**（「AI 策略 | {策略名}」整条，不拆成两行）。
- 同一字段不同尺寸/状态的不同版本都列（横版「{数量}D PNL: {值}」与竖版「{数量}D PNL」是两条）。
- 去掉：只有符号的行、纯变量模板行、以及"词条/提取的/以下/如下"这类 meta 前言行。

## 交叉检查：后端已拼接文案 × 多语言（开工阻塞项）
凡 PRD 写「后端返回已拼接文案、前端直接展示」的字段：必须写明多语言在哪一层解决——推荐**后端返回模板键+参数、前端查词条表拼接**（与本地化表自洽）；若后端按用户语言返回成品文案，则**删掉本地化表里对应模板词条**并注明「该字段文案由后端维护」。两头都写（已拼接直出 + 前端模板词条）= 互斥矛盾，研发无法开工。

## 喂给 Localisation 章节
把抽出的词条填进模板的 `Localisation Requirements` 表「原文（中文）」列，译文列（zh-CN / en-US）留给本地化平台或按需补；若抽出为空 → 章节写"本需求无新增文案，无需本地化"。UI 词条的「」框选与"英文设计稿先译中文"约定见 `07-format-conventions.md`（正文里「」框出的中文词条 = 本表原文列；**UI 文案禁反引号 / code 样式包裹**）。

🔴 **正文 ↔ 文案表双向闭环（交付前必核，机械项见 `05 步骤0`）**：①正文里出现的**每一个用户可见字符串**（状态标签、按钮的两种态、计数格式如 `{n}/500`、权限引导、二级菜单项）都要有词条——漏了研发只能硬编码；②文案表里的每条都要在正文有触发条件（孤儿文案要么删要么补规则）。**PRD 里另有错误码表时，表内「用户文案」列同样入本表**（触发条件即该行的触发场景）；i18n key（`mc_xxx`）只在 `04 步骤 6` 回填进本表，不散落正文（同族规则总纲见 `07 §二之三` 节末「技术标识各有其家」）。
🔴 **禁止「文案缺失时使用通用文案/通用状态」这类没有具体值的兜底**——无法实现，写就要写出那句字。

## 词条表交付后的常规回合（维护 · 错误码 · 校对登记）——2026-08 广场一期实战

词条表一旦交给 UED / 本地化，每轮需求变更都会回到它。动手前先读表：**第一行 legend + 表头**（列名以表为准，常见 序号 / 源文案 / zh-CN / en-US / 动态参数 / 出现位置·说明 / 状态 / 所属界面），🔴 **序号列 ≠ 行号**（中间夹着废弃行），定位一律用行号。

- **批次标色**：整行背景色标批次——本轮首次新增一种色、历史批次另一种（颜色值以表内 legend 为准，别自创）；`lark-cli sheets +cells-set-style --range A<行>:I<行> --background-color <色>`（批量用 `+styles-put`）；🔴 **每次改色同步改写 legend**（颜色含义 + 日期），改完 `+cells-get --include value,style` 回读枚举验收。
- **"新增"要判定，不能凭感觉**：三重交叉——「出现位置·说明」里的来源日期 / 来源人 × `+history-list` / `+changeset-get` 修订历史 × 原底色。🔴 **本轮复核过 / 复用过 ≠ 本轮新增**（实测把 10 行老词条误标成新增，产品一句「这几条之前就有」全部退回）。
- **废弃词条**：原地保留 + 状态列标「废弃」+ 保持原色，**不删行、不搬到表末**；被替换的写「复用第 N 行」。
- **错误码 ≠ 词条**：词条表只收**用户可见文案**；错误码在 PRD 侧建**唯一一张错误码矩阵**（码 → 用户看到的文案 / 动作），其它章节引用不复述；不展示文案的码不入词条表；**只有未约定的码才走兜底文案**——别把「多个码」概括成「统一兜底」。
- **不建词条的**：loading / 按钮禁用 / 隐藏态 / `x/15` 这类纯动态数值——不产生用户可见文案。
- **英文动态数量词条单复数必拆**：`1 day` 与 `{n} days` 两条独立词条，禁 `day(s)`；改一处**全表排查同类**。
- **与问卷 / 配置类定稿核对顺序**：先给「题号 → 词条行区间」映射再下结论；"顺序不一致"多半是序号 ≠ 题号 + 废弃行夹在中间的错觉。
- 🔴 **校对登记（流水线 S4，每个有新增 / 改动词条的需求都要走；话术见 `13 §三`）**：词条定稿后向文案 / 本地化团队提校对需求，走公司「产品文案设计登记表」（表单地址在 `12-library-manifest.json` → `forms.copy_review`；没有该文件的环境请产品给链接）。**触发**：产品说「登记校对 / 提校对」，或 PRD 发布 / 变更后 Localisation 表有新增或改动词条 → kit 主动问。**只问一件事：优先级**（产品原话：以后填写前优先级要先跟我确认），其余按 PRD 自动填并在同一句里预览：
  - `需求名称` = 「<PRD 名>词条文案设计与校对」；`文案设计类型` = 词条只有中文、英文要人写 → 「文案设计」，中英都已有只要核 → 「仅英文文案校对」；`需要处理的文档链接` = 词条表（有单独 sheet）或 PRD 链接；`内容上线后可见范围` = UI 词条一律「对外（用户可见）」；`产品线` = 按端与业务线从表单选项里选（APP → 「App产品」，Web/H5 → 「Web产品-<业务线>」）；`是否已开放文档编辑权限` = 先把文档设为组织内可编辑（或把校对方加为编辑者）再填「是」，做不到填「否」并写进备注；`备注` = 本轮新增 / 改动的行号或条数 + 特殊要求（如单复数已拆分、模板变量含义）+ PRD 链接。
  - 命令：`python3 scripts/register.py copy-review-plan --doc-url <url> --name "<需求名称>" --type 文案设计|仅英文文案校对|AI批量 --priority <P?> --product-line "<选项>" --visibility 对外|仅内部 --edit-open 是|否 --note "<备注>" [--ai-req "<AI 批量校对要求>"]` 出预览 → 产品点头 → `python3 scripts/register.py copy-review-apply copy-review-plan.json --yes`（脚本先 `+form-submit --dry-run`；表单可能有 `+form-detail` 没露出的必填项，被拒就把缺的字段名报出来补，**不猜填**）。提交回执写进闭环清单；成功后脚本自动记一行使用记录（模式 `登记校对`，`--requirement` 填 PRD 文档名、`--platform` 填本平台；输出「未写入」才按 `11` 手动补）。
