# 数字·文案·UI 格式规范（house canon）

> 交易所 PRD 每次都要写、也最容易被 QA 追问的"字段怎么显示"。这一份是可直接套用的口径。`02-prd-template.md` 的元素表「展示规则」指向本文件；写到价格/涨跌/收益/百分比字段时照此写清，能同时满足 house 风格与 `implementation_ambiguity` / `developer_confusion`（消除"显示成什么样"的歧义）。

## 一、数字格式

| 字段类型 | 规则 | 示例 |
|---------|------|------|
| **价格 / 金额** | 千分位；跟随该币种价格精度（无则默认 2 位小数）；**不带正负号**；无数据兜底 `--` | `43,201.50`、`1,234.00` |
| **涨跌 / 盈亏 / 收益率** | **必带 +/- 号**；带 `%`（比率类）；**跟随 App 涨跌色**（涨绿跌红或站点配置，中性场景除外）；精度按 PRD（一般 2 位）；无数据兜底 `--` | `+12.34%`（绿）、`-5.00%`（红） |
| **中性百分比**（胜率/匹配度/占比等，不表示盈亏） | 带 `%`；**不带正负号、不跟涨跌色**（中性色）；精度按 PRD；`--` 兜底 | `68.30%`、`匹配度 92%` |
| **大数缩写 KMBT** | 启用条件由 PRD 指定（一般卡片位、空间受限处）；K=千 M=百万 B=十亿 T=万亿，保留 2 位小数；**缩写后仍保留正负号与涨跌色** | `+1.20M`、`323.45K`、`-2.10B` |
| **时间** | 相对时间（`{N}min`/`{N}h`），超阈值转日期 `MM-DD`；或绝对 `yyyy-MM-dd HH:mm:ss`（标时区）；**分段口径必须完整**（见下方默认口径库，可直接引用） | `3min`、`12h`、`07-05` |
| **杠杆/倍数** | `{N}x`，兜底不展示 | `20x` |

写字段时，一句话把"精度 + 千分位 + 正负号 + 涨跌色 + 兜底值"讲全，例如：
> 30D 收益率：`+/-` 号必带，2 位小数带 `%`，跟随涨跌色，兜底 `--`。

### 分段格式必须给完整口径（研发实测必问，缺了就是返工）

**凡是"展示形态随取值切换"的格式模式**——相对时间（`{N}min`/`{N}h`/`MM-DD`）、KMBT 缩写、百分比精度、滚动窗口（7D/24h/72h）——它的**分段边界、边界归属、取整方向、时区、窗口起点不是实现细节，是产品口径**，研发无法替你决定（实测：只写"相对时间展示，超过 24h 展示 MM-DD"会被研发追问"具体计算规则是怎样的"）。两种合规写法任选：

1. **引用默认口径**（最省）：PRD 里写"按 house 默认口径"或把下表抄进「通用显示口径」块，行内只写差异；
2. **自定义**：给全 区间划分 + 边界归属（`=24h` 落哪边）+ 取整方向 + 时区 + 异常值。

**House 默认口径库**（PRD 直接引用即视为写清）：

| 模式 | 默认口径 |
|------|---------|
| 相对时间 | 基准=设备当前时间，差值**向下取整**：不足 1min 按 `1min`；1–59min 展示 `{N}min`；满 60min 起展示 `{N}h`（1–23h）；**满 24h 起**展示 `MM-DD`（设备本地时区）；未来时间戳（时钟偏差）按 `1min` 兜底 |
| KMBT | **≥1,000 起启用**：K=10^3、M=10^6、B=10^9、T=10^12，除后保留 2 位小数**四舍五入**；<1,000 按原数值精度展示 |
| 百分比取整 | 2 位小数**四舍五入**；说明"无需补 0"时 `+5%` 不写成 `+5.00%` |
| 滚动窗口（7D/24h/72h） | 自请求时刻起往前滚动 N 自然小时/日（**非自然日切**）；口径不同须显式写"自然日，以 UTC+X 零点切" |

## 二、UI 词条约定（减少词条歧义）

- **UI 上真实出现的固定文案 / 按钮名 / Tab 名 / 字段名，一律用中文引号 `""` 框出**（如点击`"立即跟单"`、切到`"精选带单员"`）。这样研发/QA 一眼分清哪些是界面真字、哪些是描述性语言。
- **设计稿是英文时，先译成中文再写进需求逻辑**（Trending→热门、Long/Short→看多/看跌）；正文出现的中文词条 = `Localisation` 表「原文（中文）」列，**英文只出现在本地化表**，不散落正文。
- 动态数值、带单员昵称、后端返回的业务串不算 UI 词条，不用 `""` 框、不进本地化。

## 二之二、产品口径 vs UED 职责（边界条：什么该写、什么一个字都别写）

**「字段怎么显示」是产品口径，「组件长什么样」是 UED 职责。**

- **必写（产品口径，研发/QA 问你你必须能答）**：数据显示口径——千分位、涨跌色、精度、缺失兜底、时间分段（相对时间/KMBT/滚动窗口，见 §一）、UI 词条中文原文（§二）、展示条件与交互闭环。
- **不写（UED 职责）**：① **组件视觉样式**——颜色值、尺寸、圆角、间距、阴影、字重；② **布局适配**——占宽、横滚、截断、字号、元素排列顺序、响应式断点。
- **连「以 UED 设计稿为准」都不必写**——那是默认分工，写了 = 凑行数（实测被产品点名删除）。要指设计稿就放线框/UED 小节的链接，不在需求逻辑里补免责句。
- 判别式：**这条规则变了要不要改需求评审结论？** 要 → 产品口径，写；只影响好不好看、研发照设计稿实现即可 → UED，不写。
- ⚠️ 边界提醒：**免责句不豁免产品决策**——「以 UED 为准」盖不住"这个态到底展不展示"这类口径（见 `01 §0.5` 推断申报闸①）。省的是样式，不是决策。

## 三、措辞与排版禁忌（读起来不像 AI、也更好过审查器）

- **禁用 AI 味词**：值得注意的是、需要指出、综上所述、旨在、赋能、助力、一站式、无缝、确保（改成"要求/必须"）。
- **排版**：正文避免用 `→` 箭头串逻辑、避免 `——` 长破折号、列表项结尾不加分号；用短句和明确主语。
- **只对"真实多取值且处理不同"的字段做分输入域**（0/null/空/非法分开写）；不可能出现的取值一句话收口，别为分域而分域凑篇幅。

## 四、标准兜底措辞（统一，避免同义不同写触发 internal_consistency 误判）

| 场景 | 统一写法 |
|------|---------|
| 数值缺失 | 展示 `--` |
| 头像/图缺失 | 展示默认图 |
| 某模块整体无数据 | 后端未返回则**不展示该模块**（不占位） |
| 列表为空 | 展示空态，不渲染卡片 |
| 单字段加载失败 | 该字段 `--`，不阻塞同卡其余字段 |

## 五、可读性与 AI 友好排版（强制）

服务两类读者：人要能扫读到单条规则；LLM 审查器不能把同句里的两条规则读成矛盾（internal_consistency / implementation_ambiguity 误判源）。

1. **一格一列表**：单元格内 >1 条规则必须用真列表，禁止分号/顿号/破折号串行。元素表等需要格内列表的表用**内嵌 HTML 表格**写法——`<table>` 单元格内的 `<ul><li>`/`<ol><li>`（含嵌套）经 `docs +create --doc-format markdown` 导入会 round-trip 成**真正的飞书列表块**（实测，见 `06`）；管道表格里 `<br>`+连字符只是假列表。
2. **格内分组**：按 **展示条件 / 展示规则 / 交互** 分组，每个字段一行（`字段名：格式/兜底`）。
3. **散文上限**：正文任何连续散文 ≤3 行，超过转 bullet/编号/小表。
4. **分档必表格化**：数值分档（阈值区间×系数类）必须用小表逐档一行，禁一句话串档（❌ `≤100→×10–20；≤500→×2–5；>500→×1–2` 连写一句）。
5. **流程用编号**：多步流程写 `1) 2) 3)` 编号列表——这是 §三「禁 `→` 箭头串逻辑」的正向替代写法。
6. **通用显示口径块**：US-R 顶部可设 3–5 行「通用显示口径」（数字格式/涨跌色/缺失兜底），元素表行内只写差异项 +「其余按通用口径」，防同一规则多处重复后漂移。
7. **AI 友好度 = 分层标题 + 具名章节 + 列表化**：审查器先做 SOURCE_FORMAT 判定，不友好会被转写评审并在报告公开标注——直接写成友好格式、跳过转写才稳。
8. **比率/指标公式一律 LaTeX 分式**：`$$率=\frac{分子}{分母}$$` 且分子分母写明统计口径（哪个集合、什么窗口）；禁止"A 占 B 的比例"式文字串（实测用户点名要求公式化+层级化后可读性显著改善）。
9. **跨系统流程步骤句以执行主体开头**：「agent 侧：…」「后台：…」「运营：…」——主语缺失是"这事谁做"误读的直接来源（实测"打标"归属被读反）。
10. **流程配画板导览**：≥4 步的流程/状态流转/多分支判定，配一张原生画板（mermaid fence 导入自动转，见 `06`）；图管全貌、文字管判定规则（唯一权威）。**mermaid 源码与「供 XX 读取」说明句禁止出现在正文**。

## 五之二、排版工具箱选型表（何时用什么·怎么不滥用）

§五管结构（列表化/表格化/编号/画板），本表管**选型与视觉强调**。总则：**视觉标记是稀缺资源，密度越高信号越弱**——结构承担九成可读性，视觉强调只给「读错会出事故」的词。实测负例：结构齐全但全文加粗 0 处的 PRD，阈值与主体淹没在素文里，扫读无抓手；反过来满篇加粗等于没有加粗。

| 工具 | 该用在 | 禁用负例 | lark 落地 |
|------|--------|---------|----------|
| 管道表格 | ≥2 实体×≥2 属性的对齐信息：概念表/配置项表/口径表/分档表/对接表/「条件-口径-不满足动作」判定表（**"判定+例外动作"混在一句的编号长句，拆成这种三列小表**） | 单列表格（该用列表）；格内长散文 | md 管道表 |
| 内嵌 HTML 表 | 格内需要真列表的元素表 | 无 CLI 降级时禁用（`07 §六`） | `<table>`+`<ul><li>`（§五.1） |
| 画板 | ≥4 步流程/多分支/状态流转的全貌导览 | 承载唯一逻辑；画板旁贴 mermaid 源码 | mermaid fence 导入自动转（`06`） |
| 编号列表 | 有先后/优先级的步骤与判定 | 无序并列硬编号 | md `1.` |
| 项目符号 | 无序并列（功能点/排除项/依赖） | 有序流程用符号 | md `-` |
| 加粗 | 判定关键词逐点强调：**阈值数值带单位**（30 分钟/3 条/48 小时）、状态名、执行主体（agent 侧/后台/运营）、否定与限定词（不/仅/禁止/至多）、首次定义的实体名 | 整句整段加粗；一个条目/单元格 >2 处、一段 >3 处（全粗=没粗） | md `**`（导入与 `block_replace` 均生效） |
| 导读表 | ≥5 节的长文档开头放「你要做什么｜看哪里」两列表（实测好评） | 短文档硬加 | md 表 |
| 文字颜色 | **仅语义色：红=本轮新增/变更待评审，评审确认后转黑**（团队评审惯例）；首发稿全黑 | 装饰性用色；用颜色编码分类（色盲/打印/AI 都读不到——分类用表格列） | markdown 表达不了；XML text style（block 级，语法读 `lark-doc-xml.md`） |
| 单元格底色/高亮块 | 词级/格级强警示（资金红线、不可回退操作） | 大面积铺底、装饰 | XML 路径；markdown 路径退化为 `>` 引用块+加粗 |

- **视觉标记不进审查可见面**：审查器与下游 AI 读不到粗体/颜色的语义——任何约束**必须在文字本身成立**（"仅 P0"的「仅」要在句子里；"这是新增"不能只靠标红表达）。
- 加粗密度自查：交付前扫一遍，通篇 0 加粗与满篇加粗都打回；每段 ≤3 处、每格 ≤2 处。
- 颜色只承载评审语义一种含义，不做第二用途。

## 六、无 lark-cli 纯文本交付格式（降级专用；与 §五/§五之二 冲突时**本节优先**）

> §五第 1 条的内嵌 HTML `<table>`/`<ul><li>` 是 **lark-cli markdown 导入专用**——无 CLI 时产品是**人肉复制粘贴**进飞书，HTML 标签会原样显示成代码文本、直接出错。降级交付一律改用：

1. **标准 markdown 表格**（`|` 管道语法）；单元格内多条规则用 `①②③` 编号衔接在同格内（禁 `<br>`、禁内嵌 HTML）；格内仍按 展示条件/展示规则/交互 分组，组间用 `；` 衔接编号重排。
2. 复杂大表（元素表/埋点十列表）保持标准 md 表格整表交付；**经飞书「上传 → 导入为在线文档」(.md) 转为原生表格**（飞书官方不支持 markdown 表格语法，直接粘贴时 `|` 表格可能保持原文本——给用户的操作话术以 `00 §降级` 第3条为准：导入为主、粘贴为兜底）。
3. **流程图照样用 ```mermaid fence 写在 md 里**——产品经「导入为在线文档」后 fence 自动转为原生画板，代码不残留；粘贴路径下 fence 可能保持文本，**导入路径优先**。
4. **内容标准一个不降**：章节/验收/兜底/幂等照旧齐全——降级改变的只是**载体格式**，不是内容标准；§五的散文≤3行/分档表格化/编号流程等仍适用。
5. 交付前照跑 `06` 步骤 0 的净化口径（去 [必填]/占位符/写作指引），产物是本地 `PRD-<需求名>.md` 文件而非飞书文档；文件开头**不要**写任何"本文件由降级模式生成"之类的元说明（产品要直接导入/粘贴成正式 PRD）。**升级模式例外**：全文 md 仅作对照，用户操作指引以 `04 步骤5` 降级行的「按清单手动改原稿」为准，**勿引导整篇导入/粘贴**（会丢原稿截图/@）。
