# Check: 告警/推送冷却机制

## 检查对象
主动外发、订阅式、可重复触达的告警/推送/通知类功能。

## 判断标准
- 通过：当同类事件可能高频发生时，PRD 对冷却、去重或节流有说明。
- 不通过：高频告警/推送场景没有任何冷却或去重约束。

## 豁免与边界
- 前端本地交互提示不在本检查范围内，例如 toast、表单校验提示、超限拦截提示、按钮禁用提示。
- 只有当功能本身包含主动发送消息、订阅通知、重复触达用户的外发链路时，才适用本检查。
- 风险章节里的“错误日志与告警”“监控告警”“告警阈值”这类运维观测描述，不等于用户触达型通知功能，不应触发本检查。
- 若当前需求主体是查询、导出、表单校验、页面展示等功能，而不是向用户主动外发消息，直接判通过。

## 输出格式
返回 JSON：`{"pass": bool, "severity": "P0|P1|P2|none", "location": "...", "description": "...", "why": "...", "fix": "..."}`。
