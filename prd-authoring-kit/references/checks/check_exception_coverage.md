# Check: 异常场景覆盖

## 检查对象
异常流程、边界场景、错误处理、空态、权限、网络等说明。

## 判断标准
- 通过：关键异常场景有说明，至少不会让研发或 QA 完全空白。
- 不通过：只覆盖主流程，异常与边界场景几乎没有定义。

## ✗ 典型不通过案例
- 只有主流程，没有任何失败、空态、权限、网络异常或数据异常描述。
- 只写“异常时提示用户”，但没有说明提示什么、系统如何处理、是否允许重试或回滚。
- 业务复杂度较高，但完全没有边界或失败场景覆盖。

## ✓ 典型通过案例
- 至少覆盖关键异常场景，并说明系统行为，如“无权限时提示并禁止提交”“网络失败时允许重试”。
- 主流程之外的高频边界情况有可执行描述，研发和 QA 不需要从零猜测。

## 豁免与边界
- 不要求穷举所有异常，只要求关键异常场景不为空白。
- 对极小型或探索型 PRD，可接受覆盖较少，但不能完全没有关键异常口径。

## 输出格式
返回 JSON：`{"pass": bool, "severity": "P0|P1|P2|none", "location": "...", "description": "...", "why": "...", "fix": "..."}`。
