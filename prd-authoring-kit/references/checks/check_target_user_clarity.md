# Check: 目标用户清晰度

## 检查对象
目标用户相关章节，以及任何描述使用者、受众、角色边界的内容。

## 判断标准
- 通过：明确说明主要用户是谁，且不是“所有用户”“相关人员”等泛化表达。
- 不通过：目标用户缺失，或描述过泛，无法指导功能取舍。

## ✗ 典型不通过案例
- 只写“所有用户”“平台用户”“相关人员”“业务方”等无差异化描述。
- 没有任何角色特征、使用场景、权限边界或规模信息，无法指导功能优先级。

## ✓ 典型通过案例
- 明确指出主要用户是谁，并提供角色、场景或行为特征，如“运营同学在活动配置页维护规则”。
- 即使用户范围较广，也能识别主要受益角色和次级角色。

## 豁免与边界
- 不要求提供完整用户画像文档，只要足以指导功能取舍即可。
- 若目标用户信息分散在背景、用户故事、功能场景中，需先 cross-check 全文后再判断。

## 输出格式
返回 JSON：`{"pass": bool, "severity": "P0|P1|P2|none", "location": "...", "description": "...", "why": "...", "fix": "..."}`。
