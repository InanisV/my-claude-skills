# Check: 埋点诉求覆盖度

## 检查对象
对照 PRD 的【需求背景和目标】【成功指标】与【功能需求/核心功能】，判断埋点诉求是否覆盖了「需要被数据回收/衡量」的关键行为与指标。

## 判断标准
- 通过：本次需求的核心功能/关键交互、以及用于衡量需求成败的成功指标，都能在埋点诉求里找到对应的采集点（曝光、点击、页面访问、资源加载结果之一）。
- 不通过（任一即算）：
  - PRD 写明了量化成功指标（如「点击率提升 X%」「转化率」「使用率」），但埋点诉求里没有任何能回收该指标的事件，指标将无数据支撑、无法验证。
  - 核心功能/关键交互（新增的主路径按钮、入口、模块）完全没有对应的曝光或点击埋点诉求。
  - 埋点诉求只覆盖了次要场景，却漏掉了与需求目标最直接相关的关键行为。

## 豁免与边界
- 只要求覆盖「核心功能与成功指标」，不要求穷举每个像素级元素；边缘/装饰性元素缺埋点不算问题。
- 若 PRD 没有提出任何成功指标，也未明确埋点需求，本检查不强行要求补埋点，判通过（该缺口由成功指标量化等其他检查负责）。
- 覆盖度判断基于 PRD 文本能否对应得上，不需要核对真实埋点表里的事件名（那是 tracking-review 的职责）。
- 若 PRD **明确声明本次需求无需埋点**（如埋点/数据章节注明「本需求无需埋点」「无埋点诉求」），直接判通过（severity=none）；**即使 PRD 写有量化成功指标也不因此要求补埋点**（这些指标可能由后端或其他方式回收，不在埋点覆盖度的判断范围内）。
- PRD 不涉及埋点时直接判通过（severity=none）。

## 输出格式
返回 JSON：`{"pass": bool, "severity": "P0|P1|P2|none", "location": "...", "description": "...", "why": "...", "fix": "..."}`。
