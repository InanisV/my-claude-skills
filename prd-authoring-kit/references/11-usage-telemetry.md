# 使用采集（telemetry · 尽力而为，绝不打扰用户）

> **目的**：回收 kit 在公司内的使用情况，用于向部门汇报采用率与价值。**只记 时间 / 使用人 / 需求名称 / 平台 / 模式 五个字段，绝不采集 PRD 正文、链接或任何评审内容。**

## 何时记录
**任一主流程成功收尾后**，追加**一行**。**模式列共五种、五种都记**——前三种由主 kit 记，后两种由伴生 skill 记（伴生**不复制命令**，一律按本文件执行）：

| 模式列填 | 谁记 | 触发的主交付动作 |
|---|---|---|
| `写` | 主 kit（`05` / `06`） | 飞书 PRD 发布成功 |
| `升级` | 主 kit（`04`） | 升级改动回写成功 |
| `自检` | 主 kit（`05` 模式 A） | 自检报告出完 |
| `建卡` | 伴生 `jira-card-kit` | `apply` 成功建出卡（汇报之前） |
| `demo` | 伴生 `showcase-demo` | demo HTML 文件交付那一轮 |

一次调用只记一行（别对每个 lark-cli 子操作都记）；**一轮主交付只记一行**，同一轮里的其它支线不再记。

🔴 **单一真源在本文件**：伴生 skill 里只有一句「按 `../prd-authoring-kit/references/11-usage-telemetry.md` 执行」，**命令文本、平台形态、五条铁律、写入契约全部只活在这里**（双轨维护 = 以后改一处漏一处）。伴生所在机器上**主 kit 不存在、该文件读不到 → 静默跳过本次采集**：不提示用户、不报错、不另找写法、不凭记忆拼命令。

## 五条铁律（先记死）
1. **尽力而为、失败静默**：整段用 `2>/dev/null … || true` 包住；**采集失败绝不报错、绝不重试、绝不阻塞交付**——用户永远不该因为采集看到任何异常。
2. **不问、不提**：这是后台动作；**除非用户主动问，不要在对话里提"记录了一条使用"**。
3. **只在 lark-cli 已登录时记**：`lark-cli auth status` 不 ok 就**直接跳过**（连不上公司 lark 就不采集，正常）。绝不为采集去触发 `auth login` / 扫码。
4. **零敏感**：只写下面 5 字段，绝不写 PRD 正文 / 链接 / 评审明细。
5. **主交付动作完成的当轮立即执行（按动作判，不按回合判）**：飞书稿发布成功 / 升级回写成功 / 自检报告出完 / **卡建出来（`apply` 成功，汇报之前）/ demo 文件交付**——**拿到结果的下一个动作就是本采集，然后才回复用户**（只两次快速 API，不拖慢交付）。🔴 **别等"会话最终回复"**（2026-08 改）：多支线会话里那个锚永不触发——实测发布后被 建卡 / 补图 / 拉群 等支线接连打断 N 轮，每轮都不是"最终回复"，当天使用表 0 行。🔴 **也别放到回复之后**——部分平台「回复即结束回合」，放在回复后的采集永远轮不到（实测多机漏记）。**一轮主交付只记一行**，后续支线不再记；口径同 `00 §恒定规则 8`。🔴 **别把建卡 / demo 当成"支线"漏记**：它们各自是**独立的主交付动作**（同一需求下的三件事），各记各的那一行——这里说的"支线"指补图 / 拉群 / 改标题这类**没有独立模式列**的动作。

## 环境要求（🔴 通用条款，改命令前先过一遍）

**只用 macOS 自带工具（`python3` / `grep` / `sed` / `date` / `tail`）；禁 `jq` / `timeout` 等需另装的命令。** 产品经理的 Mac 普遍没装 `jq`、macOS 也从来没有 `timeout`——采集命令一旦依赖它们，就是**静默失效**：文档照发、统计表一行不落（v1.4.22 前的旧命令栽在 `jq` 上，多台机器漏记）。改动本文件命令前自问一句：**这条命令在一台刚开箱的 Mac 上跑得起来吗？**

🔴 **五种交付都做（写 / 升级 / 自检 / 建卡 / demo，含模式 A 只自检；建卡 / demo 由伴生 skill 按本文件执行）**——写的是独立使用记录表，不算违反 `05` 铁律 2 的「只读」（其「唯一例外」句即授权）；各模式执行清单已把本步挂为正式末步（`05` 模式 A 第 7 步 / `06` 步骤 4 / 伴生 `jira-card-kit` SKILL 流程第 7 步 / 伴生 `showcase-demo` SKILL §6），**读到这里 = 该执行，不是可选参考**。

## 🔴 写入契约（两形态通用，违反 = 宁可不写）

> 形态 A / 形态 B、新集 / 旧集**全都受本节约束**。**这几条比"记上"更重要**：采集是尽力而为的附赠品，写错一行的代价（覆盖真人记录、把敏感内容写进公共表）远大于漏记一行。

1. 🔴 **行号唯一来源 = csv-get 输出里「最后一个非空数据行」+ 1**。两种合法取法：①自己数返回内容里的 `annotated_csv`，找最后一个真有内容的行；②读 `data.current_region` 的尾部行号（形态 A / 形态 B 命令内建的取法）。🔴 **禁止用「表有多大」类数字推行号**——网格总行数 / `row_count` / `actual_range` 一律不作数（飞书 sheet 的网格行数远大于实际数据行数）。**实测事故（2026-08-20）**：某会话用网格总行数推算，记录落到**第 234 行**，与真实数据末行之间留下 **154 行空洞**，表由上游手工修复。
2. 🔴 **列契约：固定 5 列 A–E、固定列序 `使用时间 | 使用人 | 需求名称 | 平台 | 模式`，时间到分钟不带秒（`YYYY-MM-DD HH:MM`）。** **严禁**：加第 6 列、改列序、把 PRD 链接或任何说明文字写进任何一格（**零敏感是铁律，见上方五条铁律第 4 条**——实测那条违规行正是把 wiki 链接写进了表）。这 5 个字段之外的内容，一个字都不写。
3. 🔴 **sanity 护栏（按下回车前自问一句）**：若算出的写入行 **≠ 最后一个非空行 + 1**，说明前面某步算错了——**跳过本次写入**，不猜、不试、不改用别的命令凑。**宁可漏记一条，不可错写一行**（形态 A 的「防覆盖护栏」、形态 B 分支一第 2 步的「读不到 N 就停」是本条在各形态的具体落法，同向不冲突）。
4. **旧命令 `+append` 分支天然服务端定位**（形态 B 分支二）：调用方拿不到也不需要行号，第 1、3 条的行号部分自动成立；**第 2 条列契约照样适用**——`--values` 里就是这 5 个值、这个顺序，不多不少。
5. 🔴 **别即兴发挥**：本文件的命令模板是唯一写法。上面那起事故正是**没读本文件、凭印象拼命令**的结果——列序全错、多写 1 列、时间带秒、行号靠猜，四种错一次犯全。**读到这里 = 照模板抄。**

## 🔴 需求名 = 跨技能统一去重键（五种交付共用一个名字）

汇总看板**按需求名去重**算「AI 覆盖了多少个需求」。**同一个需求的写 PRD / 建卡 / demo，必须落同一个需求名**——名字对不上，一个需求会被算成三个，渗透率直接失真（这正是把伴生也接进采集之后最容易翻的车）。

**取名优先级（从上往下，取到即停）**：

1. **飞书 PRD 的文件标题**（本会话写过 / 升级过 / 自检过该 PRD，或用户给了 PRD 链接）——与主 kit 口径完全一致：取「文件标题 / 文档名」（内容里的 `<title>` 块），**不是正文第一个 H1**；
2. **Jira 主卡 summary**（没有 PRD 时）——**去掉 `【iOS】` / `【Android】` / `【WEB】` 这类端前缀**，只留需求名本身；
3. **用户口头的需求名**（前两者都没有时）——用他自己叫它的那个名字，别自己另起一个。

🔴 **会话里已经出现过更高优先级的名字，就沿用它**：建卡时若会话里已有该需求的飞书 PRD（刚发布的、或用户贴过的），需求名就按第 1 条取 PRD 文件标题，**别用主卡 summary**。反过来，先建卡后写 PRD 的场景，建卡那一行**已经写进表了、不回头改**——PRD 那一行按第 1 条正常取，两行名字不一致时以后续人工对齐为准，**采集本身绝不去改已写入的行**。含英文逗号 `,` / 引号 `"` 先替换掉（仅记录用）。

**三行示例（同一个需求、三种交付、同一个需求名）**：

```
2026-09-02 10:12,张三,自选列表分组 H5,claude,写
2026-09-02 10:41,张三,自选列表分组 H5,claude,建卡
2026-09-02 15:07,张三,自选列表分组 H5,claude,demo
```

反例（**一个需求被算成三个**）：`自选列表分组 H5` / `【iOS】自选列表分组 H5` / `自选分组 demo` 三行各写各的。

## 怎么记（两种形态，先按平台选一种）

> 🔴 **先过上方 §写入契约**——行号唯一来源 / 5 列固定 / sanity 护栏三条是硬约束，下面两种形态**只是它在不同平台的落地写法**，不是各自另立一套。

> 🔴 **版本探测总则（v1.4.27 起 · 先于平台分叉过一遍）**：**`sheets` 命令集随 lark-cli 版本变化**，本文件的命令**不是所有机器都成立**。实测三段（`npm @larksuite/cli` 逐版跑 `sheets --help`）：
> - **≤ 1.0.46 · 旧集独有**：只有 `+read` / `+write` / `+append` / `+find` / `+info` 这类命令，**没有 `+csv-get` / `+csv-put`**；
> - **1.0.47 – 1.0.68 · 两套并存**：新集（`+csv-*` / `+cells-*`）与旧集别名同时在；
> - **≥ 1.0.69 · 新集独有**：只有 `+csv-get` / `+csv-put`，**旧集别名已删**（本机 1.0.83、npm latest 1.0.84 均属此段）。
>
> **动手前先裸跑 `lark-cli sheets --help` 看本机实际命令集**，按下面对应分支走；**两套都对不上 → 静默放弃本次采集**（别硬拼参数、别凭记忆猜 flag）。口径同 `06 §提交前` 那条「**flag 以 CLI 自带、版本匹配的技能为准**（不同 CLI 版本 flag 有差异，别凭本文件或记忆硬拼）」——**本文件的采集命令同样受该纪律约束，不是例外**。
>
> **✅ 顺带证伪一条传闻**：旧集**照样认 `--spreadsheet-token`**（1.0.20 / 1.0.30 / 1.0.40 / 1.0.60 的 `+append --help`、`+read --help` 原文均列出该 flag）。旧机器采集失败的真因是**压根没有 `+csv-get` / `+csv-put` 这两个命令**，**不是** token 参数名变了——排查时别往改 flag 名的方向跑偏。

> 🔴 **平台分叉（v1.4.25 起）**：**Codex 走「形态 B · 分步裸跑」**，**其余平台（Kiro / Claude / Gemini / Antigravity）走「形态 A · 单行分号」**。原因：Codex 默认 `workspace-write` 沙箱拦 macOS Keychain，用户配的放行规则只匹配 **argv 首 token 为 `lark-cli` 的裸命令**——分号复合 / 管道 / env 前缀一律不匹配，形态 A 在 Codex 下**整条必失败**（实测；见 `06 §Codex 沙箱适配`）。反过来，**Kiro 的单行 + 结尾 `echo` 是终端检测需要，别拿形态 B 去替**。**两种形态的五条铁律与防覆盖护栏完全相同。**

### 形态 A · Kiro / Claude / Gemini / Antigravity（一段自包含 bash，单行执行）
```bash
# PRD kit 使用采集 —— ⚠️【务必单行执行】(分号连接、别换行、别把 if 拆多行) + 结尾 echo；
# 🔴 只用系统自带工具：jq / timeout 一律禁用(macOS 不自带→整条静默失效)。占位符按下方注释替换后整条粘为一行跑。
lark-cli sheets +csv-get --help >/dev/null 2>&1 && { TG_T=LFvMsXyKAhvW8Utprn4ugtPgs0f; TG_S=bf6df9; TG_REQ='<文档名>'; TG_PLAT='<平台>'; TG_MODE='<模式>'; if lark-cli auth status >/dev/null 2>&1; then TG_U=$(lark-cli auth status 2>/dev/null | python3 -c "import json,sys;print((json.load(sys.stdin).get('identities') or {}).get('user',{}).get('userName') or '')" 2>/dev/null); TG_U=${TG_U:-使用者}; TG_TIME=$(date '+%Y-%m-%d %H:%M'); TG_L=$(lark-cli sheets +csv-get --spreadsheet-token "$TG_T" --sheet-id "$TG_S" --range A1:A100000 2>/dev/null | python3 -c "import json,sys;r=(json.load(sys.stdin).get('data') or {}).get('current_region') or '';print(''.join(c for c in r.split(':')[-1] if c.isdigit()))" 2>/dev/null); if [ -n "$TG_L" ]; then lark-cli sheets +csv-put --spreadsheet-token "$TG_T" --sheet-id "$TG_S" --start-cell "A$((TG_L+1))" --csv "\"$TG_TIME\",\"$TG_U\",\"$TG_REQ\",\"$TG_PLAT\",\"$TG_MODE\"" >/dev/null 2>&1; fi; fi; }; echo "[telemetry] 本步结束"
# 占位符：<文档名>=需求名(取法见上方 §需求名 = 跨技能统一去重键；写/升级/自检下 = 飞书文件标题(<title>块，非H1))  <平台>=claude|antigravity|codex|kiro|gemini  <模式>=写|升级|自检|建卡|demo
```
- 🔴 **需求名称 = 该飞书文档的「文件标题 / 文档名」**（飞书里显示的文件名，= 内容里的 `<title>…</title>` 块）——**不是正文第一个 H1 大标题**。H1 常与文件名不同（实测：codex 取了文档名"…展示 PRD"、kiro 取了 H1"…展示"，同一需求两条名字对不上、去重统计失真）。**统一取文档名**：从你已 fetch 的文档内容抓 `<title>…</title>` 的文本（`.data.document.title` 恒为 null，别用它）；wiki 链接可 `lark-cli wiki +node-get --node-token <url>` 取 `.data.title`；写模式=你新建时设的文档标题。含英文逗号 `,` / 引号 `"` 先替换掉（仅记录用）。**建卡 / demo 两种模式下手里没有飞书文档时**，按上方 `§需求名 = 跨技能统一去重键` 的第 2 / 第 3 条取名（Jira 主卡 summary 去端前缀 > 用户口头的需求名）——**同一需求三种交付必须同名**。
- **平台 / 模式** 按注释填。写完**不回读、不校验、不重试**——尽力而为即可。
- 🔴 **防覆盖护栏（别为了"总能写上"把它删掉）**：只有 `[ -n "$TG_L" ]`（行号真取到了）才执行 `csv-put`——**行号提取失败必须整体跳过写入，禁止 fallback 到 `A2` 之类固定行**（那会从表头下第一行起逐条**覆盖已有记录**，采集变删数据）。跳过时不报错、不重试，照常 echo 结束标记。使用人取不到则退成 `使用者`（只是名字模糊、不伤数据，故这一处允许 fallback）。
- 🔴 **单行 + 结尾 echo（防 agent 卡在 Working；本形态专属，Codex 见形态 B）**：整条**单行**执行 + 结尾 `echo`——**多行会让 Kiro 等 agent 终端进入 `then>` 续行、加上全程 `>/dev/null` 零输出，检测不到命令结束而一直 Working（实测踩坑：bash 早跑完了、agent 还杵着）**。**别用 `timeout` / `jq`**（macOS 都不自带，见上方「环境要求」）。跑完 echo 即 fire-and-forget **结束本回合**：别等它、别解读输出、别当需要验证的任务。
- 🔴 **开头的版本探测保护（v1.4.27 起，别删）**：整条以 `lark-cli sheets +csv-get --help >/dev/null 2>&1 && { …原整条… }` 起手——**本机没有 `+csv-get` 就整条静默跳过**，不会拿不存在的命令去撞报错。探测失败也照常输出结尾 `echo`（**单行 + 结束标记纪律不变**，agent 不会卡在 Working）。
- ⚠️ **已知局限（如实记，别硬塞）**：**本机是「旧集 CLI」（≤1.0.46，只有 `+append` 没有 `+csv-*`）时，形态 A 会静默跳过、这次采集就是不记**——一条单行里放不下双命令集的双分支（塞进去必然破坏「单行 + 结尾 echo」纪律，得不偿失）。Kiro 上想稳定采集，请把该机 lark-cli 保持在**含 `+csv-*` 的版本（≥1.0.47）**，或等 kit 后续版本；**别为了补这个缺口去手写 `+append` 变体**——形态 A 没有分支承载它。（Codex 走形态 B，旧集有专门分支，见下。）
- 极低概率两人同秒写会撞行（无关紧要，采集非事务）；别为此加锁或读校验。
> 首次在 Kiro / Claude 等平台会弹「批准运行 / 加入信任列表 Trusted Commands」——那是平台对 bash 命令的安全确认、**不是卡住**（sheet 其实已写入）；把它加入信任列表后即静默自动跑、不再打扰。

### 形态 B · Codex（沙箱兼容 · 分步各自独立裸跑）

Codex 下分号长命令不匹配沙箱放行规则（首 token 必须是 `lark-cli`），改为**每步各自独立裸跑**、**任一步失败即静默放弃**（铁律不变：失败静默 / 不打扰 / 不扫码 / 不重试）。

**第 0 步 · 版本探测（v1.4.27 起必做，先于一切写入）**：裸跑

```
lark-cli sheets --help
```

看输出的命令清单里**有 `+csv-put` 还是有 `+append`** ——
- 有 `+csv-put` → **走分支一**（两套并存的 1.0.47–1.0.68 也走分支一，新集优先）；
- 没有 `+csv-put`、但有 `+append` → **走分支二**；
- **两个都没有 → 静默放弃本次采集**（别硬拼参数、别猜 flag）。

#### 分支一 · 新集 CLI（有 `+csv-get` / `+csv-put`，即 ≥1.0.47）

1. `lark-cli auth status` —— **不 ok 就停**（连不上公司 lark 就不采集，正常）；ok 则**你自己从输出 JSON 读** `identities.user.userName`（读不到就用 `使用者`——只是名字模糊、不伤数据）。**不要接 `| python3`/`| jq`**，管道在沙箱下不放行。
2. `lark-cli sheets +csv-get --spreadsheet-token LFvMsXyKAhvW8Utprn4ugtPgs0f --sheet-id bf6df9 --range A1:A100000` —— 你从输出的 `data.current_region` 读**尾部行号 N**（如 `A1:A87` → N=87）。**输出示例**：输出 JSON 的 `data.current_region` 形如 `"A1:E23"` → 尾部行号 N=23；**先看清输出再取数，别因字段没找到就臆断失败**——确认输出里确实没有 `current_region` 才算「读不到」，停。🔴 **读不到 N 就停，禁止猜行号、禁止 fallback 到 `A2` 之类固定行**（防覆盖铁律同款，见形态 A 的「防覆盖护栏」——猜行号会逐条覆盖已有记录，采集变删数据）。
3. `lark-cli sheets +csv-put --spreadsheet-token LFvMsXyKAhvW8Utprn4ugtPgs0f --sheet-id bf6df9 --start-cell A<N+1> --csv "<时间>,<使用人>,<需求名>,<平台>,<模式>"` —— `<N+1>` 你自己算好写死；参数值里的引号/空格**不影响前缀匹配**（首 token 仍是 `lark-cli`），照常带。`<平台>` 填 `codex`。
4. **失败不重试、不回读、不校验**；Codex **不需要结尾 `echo`**（那是 Kiro 终端检测需要），也**不要**把各步用 `;` / `&&` 拼起来。

#### 分支二 · 旧集 CLI（只有 `+append`，即 ≤1.0.46）

`+append` 是**服务端追加行**：由服务端在给定范围内定位「最后一行有数据的行」并写到其**下方**——**不需要先读行号，天然不会覆盖已有记录**，所以这个分支只有两步。

1. `lark-cli auth status` —— 同分支一：**不 ok 就停**；ok 则你自己从输出 JSON 读 `identities.user.userName`（读不到用 `使用者`）。**不要接管道**。
2. **先裸跑 `lark-cli sheets +append --help` 确认本机参数名**，再拼写入命令。1.0.20–1.0.60 实测的 `--help` 原文是：`--spreadsheet-token string`（spreadsheet token）、`--sheet-id string`（sheet ID）、`--range string`（`append range (<sheetId>!A1:D10, A1:D10 with --sheet-id, or a single cell like C2)`）、`--values string`（`2D array JSON`）。据此本表的写入命令为：

```
lark-cli sheets +append --spreadsheet-token LFvMsXyKAhvW8Utprn4ugtPgs0f --sheet-id bf6df9 --range A1:E1 --values '[["<时间>","<使用人>","<需求名>","codex","<模式>"]]'
```

  （`--sheet-id bf6df9` + `--range A1:E1` 是 `--help` 列出的「`A1:D10` with `--sheet-id`」形态；等价写法是省掉 `--sheet-id`、直接 `--range 'bf6df9!A1:E1'`。**以本机 `--help` 实际列出的 flag 为准**，对不上就静默放弃。）

3. **写入失败静默放弃**——不重试、不回读、不校验、不改用别的命令凑（同铁律 1）。

- 🔴 **防覆盖护栏在本分支天然满足**：`+append` **由服务端定位追加点**，调用方压根拿不到也不需要行号，**没有「猜行号」这个动作可做**，因此分支一那条「读不到行号就停、禁止 fallback 到固定行」的语义在这里自动成立。**但护栏的精神不变**：如果 `+append` 报错，**就是不记这一条**，绝不退回去用 `+write` / `+csv-put` 之类会指定绝对位置的命令补写（那才会覆盖已有记录）。

- **时间取值**：AI 自报当天日期时间即可（`YYYY-MM-DD HH:MM`）；要机器时间就**单独裸跑一条** `date '+%Y-%m-%d %H:%M'`。（两个分支通用）
- **需求名称 / 模式** 的取值口径与形态 A 完全一致（需求名按上方 `§需求名 = 跨技能统一去重键` 取：飞书**文档名**不是 H1 > Jira 主卡 summary 去端前缀 > 用户口头的需求名；`<模式>` 五选一：`写` / `升级` / `自检` / `建卡` / `demo`）；含英文逗号 / 引号先替换掉。（两个分支通用）

> 表格：飞书「PRD写作kit使用记录」——`明细页 sheet_id=bf6df9`（本步追加）；另有「汇总看板」页用公式（COUNTA / COUNTUNIQUE / COUNTIF）**自动**算 总调用次数 / 去重需求数 / 去重使用人数 / 按模式，**无需也不要手动写汇总页**。

## 排查：表里没某人的记录（六个已知根因）

1. **那台机器缺 `jq`**：v1.4.22 之前的旧命令用 `jq` 提取使用人与行号，macOS 不自带 → 提取静默失败，**文档发了、行没写**。**把 kit 升到 ≥1.4.22 即修**（新命令只用 `python3`）。
2. **登录 scope 缺 `sheets`**：`auth status` 显示 ok **不等于** scope 齐——授权时 domain 少给了 `sheets`，就是"能发文档、写表 403"。核对法见 `06 §前提` 的「scope 机械核对」一条判定。
3. **Codex 上用了形态 A**：分号复合 / 管道命令不匹配 Codex 沙箱放行规则，整条撞 `keychain entry not found` 静默失败——**文档发了、行没写**。改用**形态 B 分步裸跑**；若连裸跑也报 keychain，是用户还没配 rules 放行，按 `06 §错误分诊` keychain 首判引导配一次。
4. **时序没落在"主交付动作完成的当轮"**：两种失效形态——①**挂在回复之后**：部分平台回复即结束回合，采集永远轮不到（规则 8 的时序 **v1.4.22 已前移到回复之前**）；②**等"会话最终回复"**：多支线会话里这个锚永不触发（实测发布后被支线打断 N 轮，当天 0 行）——**v1.5.1 已改成「主交付动作完成的当轮立即执行」**（见 `00 §恒定规则 8` 与本文铁律 5）。仍漏记的话先确认那台机器的 kit 版本。
5. **CLI 版本命令集不匹配（旧集 `+append` vs 新集 `+csv-*`）**：那台机器的 lark-cli **≤1.0.46**，只有 `+read/+write/+append/+find/+info`，**没有 `+csv-get` / `+csv-put`** → v1.4.26 及之前的采集命令（硬编码新集）在该机**必然失败**，文档照发、行不写。**判定**：在那台机器裸跑 `lark-cli sheets --help`，看清单里有没有 `+csv-put`。**现状**：**形态 B（Codex）已有旧集分支**（见上「分支二」）；**形态 A（Kiro / Claude / Gemini / Antigravity）在旧集机器上会静默跳过**——该机需把 lark-cli 升到 **≥1.0.47**（含 `+csv-*`）才能采到。🔴 **注意别误判成 flag 名问题**：旧集**照样认 `--spreadsheet-token`**（实测 `+append --help` / `+read --help` 原文均列出该 flag），**改 token 参数名是错误方向**。

6. **伴生 skill 那一轮没记（建卡 / demo，v1.6.5 起入单）**：`jira-card-kit` 的 `apply` 成功建出卡、`showcase-demo` 的 demo HTML 交付完，**那一轮就该按本文件记一行**（模式填「建卡」/「demo」）。三种已知失效：① **那台机器只装了伴生、没装主 kit**——伴生不复制命令文本，读不到 `../prd-authoring-kit/references/11-usage-telemetry.md` 就静默跳过（**设计如此，不是 bug**；两个伴生只随主 kit 的 `install.sh` 落到同一 skills 根目录，正常安装下路径恒定，装上主 kit 即恢复）；② **记了，但需求名跟 PRD 那行对不上**——去重键失效，一个需求被算成多个，口径见上方 `§需求名 = 跨技能统一去重键`；③ **拖到会话最终回复才记**——与第 4 条同因，时机按动作判：**卡建出来的当轮（汇报之前）、demo 文件交付的当轮**立即记。
