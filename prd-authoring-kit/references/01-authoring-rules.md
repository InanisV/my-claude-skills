# Authoring Rules —— 怎么写才能过 nocode 门禁

> kit 的「大脑」。写作/自检的权威口径。原始 18 条检查全文在 `checks/`（**只读，镜像真实门禁，勿改**）；本文件把它们反过来写成"怎么写才通过"。

---

## 0. 目标口径（先记死）

门禁把 18 条原子检查汇总成 4 维度打 0–100，按严重度扣分：

- **P0（≥1 个）**：🔴 有条件通过（修完 P0 才可推进）——实质仍是阻塞。
- **P1 / P2**：扣分不阻塞（审查器 2026-07-06 版：**无 P0 即通过**；≥80 🟢、60–79 🟡、<60 🔴 不通过）。
- **硬互斥封顶**：1 个 `hard_mutual_exclusion` 封顶 79（🟢 无缘），2 个及以上封顶 74——内部一致性是 🟢 硬前提。
- **维度权重**：约 30/30/20/20（完整性/可量化性/边界/技术可行性）。只帮理解失分结构、**不进判定**——记住"可量化性最易失分，优先补成功指标+验收"。
- **AI 阅读友好度**：审查器先判格式友好度，不友好会被转写评审并公开标注。**写法上直接满足**：分层标题 + 具名章节 + 列表化表达（见 `07 §五`），别交出大段散文。

**自检分两栏（详见 `05`）**：① 门禁判定（按 18 条原文，决定门禁退回；★=kit 从严升格项 core_feature / fund 完全缺失）；② kit 加严（门禁不查的第二道门/幂等有效性）——其**结构性断点默认阻塞发布、可用户知情放行**，细节项仅建议。

**发布门槛（比门禁略严，显著提高一次过概率）：**
- **标准档**：门禁 `P0=0 且 P1=0` + 第二道门（`05` 步骤2.5）无结构性断点（默认，资金/状态机结构缺陷可知情放行）。
- **轻量档**（1 US-R、不新增/改动 发奖·行情取数·主动推送链路；涉资金但纯入口/文案/展示位、不碰发奖逻辑亦可，**但幂等段落仍须完整、缺失照 P0**）：门禁 `P0=0` + 成功指标有判定口径 + 每 US-R 有验收。**禁止为凑分编造指标/验收。**

达不到就回去补。宁多写一句，不留一个可被误读的分支。

## 0.5 最小充分原则（比"过分"更重要——别被审查规则牵着走）

真实 house PRD 很简洁：背景一句、价值一句、需求逻辑几条 bullet、兜底一句"失败→现货"（见 `references/examples/example-real-draft-concise.md`）。写 PRD 的第一心法不是"写全"，是**用最少的内容清掉门禁、把细节还给研发**。

- **检查是地板，不是靶子**：每条检查清掉即可，**别为刷分堆细节**。宁可 PRD 简洁、少 1–2 分，也不要为满足某条 check 把它整复杂。
- **信任研发/QA**：实现细节——超时具体值、缓存策略、降级用什么组件、具体接口字段、双重失败怎么兜——**交给研发**，PRD 只写产品规格。dev 本能会处理的，别写进 PRD。
- **实现邻接追问用「归属声明」一句收口（实测清 P1 利器）**：审查器会追问实现邻接细节——分页协议、接口触发时机、随机值由谁生成、字段单双侧、取值分布。这些**不该写真规格**（会堆废话），用一句归属/口径声明清掉。**声明必须落在该概念的唯一定义处并替换原措辞**——在另一处追加第二种说法（原文写"前端取一侧"、字段表再加"后端已取好"）= 亲手制造双轨，会被 一致性/歧义/边界 三条检查各咬一口（实测一处双轨吃 3 个 P1）。**归属声明只能收口真实存在的现有机制**（源材料/产品提过、或能指到出处）——对源材料里不存在的机制写「以 X 文档为准」＝用免责代替提问，仍是臆造、须进推断申报清单。**归属声明必须带白话释义**：引用外部系统/既有模型的口径（"沿用 X 系统/X 模型现有定义"）时，括注半行白话说明它实际是什么行为（如"沿用 XX 节奏模型（即：按账号活跃时段把日配额随机分布成具体触发时刻）"）——**读者不需要了解 X 也能读懂本 PRD**；写不出这半行释义 = 你自己也没懂被引用的东西，去问对接人，别把黑话当收口（实测用户原话"这句话看不懂"）。声明句式：「分页机制以 X 接口文档为准，本 PRD 不约束」「点击时按需调用（非预加载）」「由后端计算返回展示值，前端不参与计算」「接口返回已按 X 取好的单侧值，前端无需自行选边」。**归属声明涉及客户端行为（内置默认值/本地兜底）时附一句"双端保持一致，由研发统一维护"**——否则会被追问"双端可能不一致"（实测 P1）。判别：**研发问"谁负责/哪层做"→归属声明一句**；问"具体规则是什么"→口径（下一条）。两条延伸（实测三轮评审提炼）：
  - **提了就要给数**：PRD 里每个数值型门槛（版本号/条数上限/阈值）要么给具体值或已定义的回填机制，要么**整个话题不提**（属研发域的，如版本兼容，不提就没得咬）；半句"上线前对齐/后续确认"必被咬 P1。
  - **跨端交接点自查（写完后端逻辑过一遍）**：每个前端展示值——谁计算/谁返回/前端是否需感知状态开关（合规/灰度态建议"后端返回最终值、前端透明"）；每个 config 数值参数——实际数据不足/越界时的分支（如 insertIndex > 卡片总数）；每个"由 X 确认"——归属到具体机制，别留悬空动作。
- **但「口径」不是实现细节（实测研发必问）**：分段格式的边界与取整（`{N}min`/`{N}h` 何时切换、`=24h` 落哪边、KMBT 启用阈值）、时区、滚动窗口起点、0 与边界归属——这些是**产品口径**，研发无法替你拍。省 token 的合规写法：引用 `07 §一` 的 **house 默认口径库**（"按 house 默认口径"一句即合规），只对差异处自定义。判别式：**研发问"具体规则是怎样的"时你必须能回答的 = 口径；研发自己能定且怎么定都对的 = 实现**。
- **不臆造产品决策（铁律）**：任何**源稿没有、产品没确认**的行为，**不得**当既定需求写进 PRD。要么①**在对话里问产品定**（访谈/升级时就问，别自己拍），要么②标"（建议，待产品确认）"，要么③留给研发。**逻辑内审(`08`)发现的缺口是给产品的问题，不是让你 AI 填的答案。** 🔴 **每条 finding 落笔前先过「分诊闸」（这是准入门、不是建议）**：① 研发能自决的（实现邻接 / 组件 / 协议）→ 归属声明一句或干脆不写；② 已被复用逻辑覆盖的（"沿用现有 X"）→ 一句归属声明收口，**别把现有状态机重写进本 PRD**；③ **只有"产品必须拍板的口径"与"本载体真·新增的行为"才允许落成规格**。分诊没过的 finding 不写进 PRD——硬写 = 新增可挑面 + 易造双轨（这正是"过度修订"的根）。 🔴 **推断申报闸（铁律的交付执行件）**：起草完成、给产品确认时，把**源材料没有、由你补充的产品级决策**集中列成「**推断申报清单**」（每条一行：补了什么＋为什么需要＋请 确认/改/删），随 5 段速览 / 改前清单一并给产品逐条拍板；**清单非空且未获回应，不得进自检发布**。六条判入：① **免责标注不豁免**——被「以 UED/接口文档/本地化为准」盖住的产品决策照样入清单（免责只免格式细节，不免决策本身）；② **引用存量系统「现状事实」**（现有口径/现有公参/现有样式/house 默认）**须能指到背景材料或 kit 口径库的出处**，指不到 → 按推断入清单，不得写成既定现状；③ 行内「（推断）」标记只是痕迹，**不替代集中申报**；④ **实体臆造同判**——源材料与「需求关联方与依赖」表里都不存在的 系统/服务/库/模块/图库 名（如凭空写出"运营模板图库"），按臆造进清单，**先确认存在再引用**；⑤ **用户纠正最小外推**——用户点名纠正 A 时只改 A；由 A 推断出的连带改动（"既然 A 不归我们，B 应该也不归"）**禁止静默落笔**，一律作为推断进清单单独申报（实测：用户说"去重不用管、大数据现成"，被外推成"打标也归大数据"，错——打标是我们做）；⑥ **产品未提出的系统性约束**——容量规划/性能预算/量级设计（「服务按此容量设计」「日产出百帖级」这类）**不得作为需求写进正文**：那是技术方案评审的内容，产品无法确认、研发不按 PRD 做容量设计，写了只会被质疑（实测：「容量口径」被产品当场问"这是什么？是必要的吗？"）。认为真有必要 → 进【待确认】问产品。连带：**自造聚合名词**（「容量口径」「XX 模型」这类非通用词）若保留，须带白话释义（同归属声明白话释义的要求）。清单只在对话里交付、不进 PRD 正文。
- **门禁必需的补充**（成功指标/验收/目标用户/本期不包含 等 house 稿常缺、但门禁要）：补，但**只补到刚好过**的最小粒度（成功指标 1 主指标——护栏默认不加、涉资金/客诉风险可选 1 条（见 §3）；验收几条关键断言；异常写真实兜底 + 命中的态），不铺陈。
- **简洁 ≠ 结构塌掉**：需求逻辑用 house **元素表**形式（`原型 | 元素 | 说明`）。说明格**内部必须分层**——**展示条件/展示规则/交互** 起行 + 字段逐条列点（见 `07 §五`）；「别退化成一串纯 bullet」指**不要丢掉元素表三列骨架本身**，不是禁止格内列点（**纯后端/纯埋点薄路径、系统/管道类需求除外**——其需求逻辑写成系统行为/口径小表，无 UI 元素不硬造元素表，见 `02` 顶部三条）。结构太薄/塌掉时，新版审查器判 `SOURCE_FORMAT=human` 走无损转写：报告被公开标注「未使用 AI 阅读友好格式」、且依赖转写救回埋没内容（真缺的照判缺失）——结构自己立好、直接被判 `ai` 才是正解。简洁指**内容**克制，不是**结构**没有。
- **开放的产品决策在对话里问、别堆「待确认」**：源稿没有、需产品拍板的行为（如空数据怎么处理、切换记忆范围），**创建/更新 PRD 前就在对话里问产品（带你的建议）**，拿到决定写进正文。PRD 末尾不留一列待确认让产品自己看；只有真外部待定（接口链接/上线时间/待运营回填）才留、且极简。

## 1. 元原则：为「会误判的 LLM 审查器」而写（写清楚，但别写多）

18 条里过半篇幅是"禁止误判"规则 → 下游是**易把正常分支读成矛盾**的 LLM 审查器。心法不是"写全"，是**写到审查器无法误读**。三手法：

**手法A — 不同输入域分开、点名写。** `0` / `null` / 空 / 非法 / 未返回 分开定义并点出语义：
> ✅ "值=0：命中限额，展示受限文案；值为 null/空/未返回/非法：判为上游异常，降级默认展示并记日志。"
> ❌ "拿不到值就降级。"（0 和空被合并 → 判 boundary 不清）

**手法B — 正常链路与异常兜底分层，标触发条件不同。**
> ✅ "**正常链路**：price 必传并透传；**异常兜底**：上游未返回 price 时不下单、返回 PRICE_UNAVAILABLE 并记日志。"

**手法C — 依赖层错误 与 业务层结果 分层。**
> ✅ "依赖接口可能 500/超时；业务侧捕获后降级为内置默认继续返回。"

**适度原则（防冗长）**：只对**真实多取值且处理不同**的字段分输入域；不可能出现的取值一句收口。别为分域而分域把 PRD 撑肿——冗长本身伤可读性。

## 2. 五个 P0 阻塞项（重点防守）

| P0 检查 | 抓什么 | 通过写法 | P0 出处 |
|---|---|---|---|
| **developer_confusion** | 研发/QA 推不出唯一实现或唯一验收 | 每分支"触发条件+唯一结果"；每验收映射"输入X→输出Y" | 源 check 明写 P0 |
| **internal_consistency** | 两处对**同一规则**互斥定义 | 同一字段/阈值/行为全文只定义一次，或写"以 §X 为准" | 源 check 明写 P0 |
| **implementation_ambiguity** | 同一句可实现成两种互斥方案 | 关键行为给触发条件+规则+输出；禁模糊词无规则 | 仅 `hard_mutual_exclusion`（同触发条件互斥）时 P0，`boundary_ambiguity`/`single_unclear` 最多 P1 |
| **core_feature_specificity** | 功能只有口号 | 每核心功能 ≥2 句具体（做什么/什么条件/给谁什么结果） | kit 从严升格（源 check 未标 P0） |
| **crypto_fund_idempotency** | 涉资金没幂等 | 重复请求/回调/消费的去重键与处理 | kit 从严升格（源 check 未标 P0） |

> 记忆钩子：**"具体、可推、不歧义、不打架、不重复扣钱"**。
>
> **硬互斥封顶（冲 🟢 必看）**：确认 1 个 `hard_mutual_exclusion` 综合分封顶 79（🟢 无缘），2 个及以上封顶 74；`internal_consistency` 命中的互斥**同样计数**——想 ≥80 必须硬互斥清零，不是修成 P1 就完事。
>
> **幂等有效性（红线，② kit 加严·资金安全）**：幂等键粒度必须 ≤ 声明的唯一性不变量粒度。`event_id`/`request_id` 只防"同一事件重投"，防不住"每人一次"——若正文写"同一 X 至多一次"（X=user_id/活动ID/订单ID），幂等键要么**包含 X**（如 `活动ID+user_id`），要么另有 **per-X 唯一约束/发放台账**。否则"写了幂等"仍能重复发奖（见 `05 步骤2.5` 的四栏反证）。

## 3. 其余检查，按维度给通过写法

### 完整性（30%）
- **exception_coverage(P1)**：不是"三类各一条即可"，按 **模块×状态矩阵**自查——每个 UI 模块过：有数据 / 字段级空 / 模块级空 / **加载中(loading)** / 请求失败 / 部分缺失。loading 是独立第三态，最易漏。命中 `scenario-rules.md` 的业务态补齐。
- 背景回答"谁/什么问题/影响多大"；关键场景有 As-a/I-want/So-that。

### 可量化性（30%，house 稿失分重灾区 → 重点补）
- **success_metric_quantification(P1)（权威口径，他处以此为准）**：**只需 1 个最直接相关指标**（曝光率/点击率）+ 一个具体目标（如 +5%，低目标 OK）+ 分母/周期。目标值**由产品在对话中拍板**；拍不了就在统计口径/备注里标「初值，上线后由数分校准」（诚实且门禁安全，不触发"待确认"类扣分）。**默认不加护栏、不堆多个指标、不写"待运营回填/待确认"**；仅涉资金/客诉风险的需求可选加 1 条护栏。
- **acceptance_testable / acceptance_derivable(P1)**：验收有可观察行为/阈值/断言，禁自引用。二者**不触发 P0**，最多 P1。
- 已落成模板的「成功指标」表 + 每 US-R「验收标准」，照填。

### 边界清晰度（20%）
- **scope_boundary(P1)**：显式"本期不包含"。
- **target_user_clarity(P1)**：主要用户具体，禁"所有用户"。
- **external_dependency_declaration(P1)**：依赖点名；内部自研可显式声明"无外部依赖"（源 check 允许豁免，别为凑表填占位）。

### 技术可行性（20%）
- 覆盖 §2 五个 P0 + 手法A/B/C。
- **开关/配置/feature-flag**：写明 **必选或可选 + config key + 默认值 + 灰度/回退方式**；禁止只写"建议接 config"（属 single_unclear，研发无法确定必须配置下发还是可硬编码 → P1）。
- **交互闭环 / 生效时机 / 状态迁移**（进入态要有退出态、loading 是第三态、阈值两侧+边界归属、生效是 立即/延迟/定时/跨周期 + 存量处理、状态机每边有行为）属 **第二道门**，权威判据只在 `05 步骤2.5`——那里按 遗漏/矛盾/断点 记，**不并入 18 条打分**；其中**结构性断点**（进入态无退出/缺反向/漏 loading/缺关键"否则"）**默认阻塞发布、可知情放行**，写作时务必闭合。

## 4. 域规则：crypto / 交易所（本团队主场）

命中就必须写：

- **crypto_data_source**：价格/数量/交易对/盘口/余额，以及**收益率/胜率/盈亏(PnL)/最大回撤/杠杆/费率/资金费率等派生业绩指标** → 写明来源系统/接口/字段。**排序/推荐用的派生分值（热度/评分/权重）同样要写来源**，或显式声明口径归属方（如"由 XX 系统定义并返回，本 PRD 不约束口径"）。缺失记 P1。
- **crypto_fund_idempotency**（见 §2，P0）：涉资金 → 幂等/防重。**kit 从严的 is_fund 语义**：任何导致 账户余额/保证金/积分/优惠券/冻结额度 增减，或触发第三方资金/发奖回调的动作（含 充值/提现/扣款/入账/发奖/退款/转账/划转/返佣/结算/兑换/冻结解冻）都按涉资金对待。拿不准默认按涉资金写幂等。
- **crypto_alert_cooldown**：主动外发、可高频的推送/告警/订阅通知 → 冷却/去重/节流。缺失记 P1。前端 toast、表单校验提示、运维监控告警**不算**，别硬写。

> 说明：源 check 文本里没有"crypto 升 P0"这类规则——除 fund_idempotency 按 kit 从严当 P0 外，data_source/alert_cooldown 缺失都是 P1。

## 5. 埋点四检查（tracking_*）：一句话记法

**要么把埋点写清楚，要么显式声明"本需求无需埋点"。** 二选一。

- **requirement_clarity**：每条埋点说清"采集什么行为、分析什么"，定位到页面/元素/动作。
- **feasibility**：只采客户端可观测行为，别用埋点统计服务端状态/后台计算/全站聚合实时量。
- **goal_coverage**：有量化成功指标的，指标要能被某条埋点回收。
- **platform_clarity**：多端逐条标 Web/App 或统一"双端均需实现"。
- **豁免**：显式"本需求无需埋点"即全通过（即使有成功指标也不强制补埋点，四条 tracking 检查都认这条豁免）。

## 6. 场景规则库（附加检查，命中才用）

审查叠加 `scenario-rules.md`。命中就在对应 US-R 补：交易类（美股休市/盘前盘后、行情延迟合规、退市停牌无价、未开户/未实名/受限地区**拦截并引导**）；活动类（三态+倒计时、发奖失败/重复领取/资格不符、分享落地页新老用户差异）；资产类（零余额/隐藏/小额、充提风控/地址校验/网络拥堵）；通用（多端设计缺失注明"无需单独设计"、列表四态、登录/权限差异、超长数值精度千分位截断）。
**交易页模块**逐模块标现货/合约是否展示及差异（单产品线写"仅合约/仅现货"）。
