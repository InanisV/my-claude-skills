# 逻辑内审 —— 让 PRD 逻辑经得住考验（写作侧纪律 + 第二道门自检执行器）

> 门禁高分 ≠ 逻辑没洞。这一份是**产品逻辑自洽性**的深度审查方法，定位有两层：**①写作侧纪律**——落笔时的强制产物（§0.6 逐对象闭环矩阵）+ 写作要点，把该产品拍板的洞在写作时点出来；**②第二道门自检执行器**——`05 步骤2.5` 自检时**逐个加载 `references/checks-logic/` 镜像原文机械枚举跑**（同 `05` 之于 `checks/` 的用法）。目标：**每一条用户可见的交互路径都被定义、自洽、可达、可测**。
> **⚠️ 判据权威源已移到镜像**：`references/checks-logic/`（`00-pipeline.md` 执行总纲 + `L0`/`L1`/`L2`/`L3`/`L4`/`LC` 审查 prompt 逐字镜像自 PRD内审工作流 v3.2·与线上审查器同源）。**本文件的六维是同源浓缩的写作要点，不替代镜像原文当判据**（近似转述会走样，真判定看镜像）。
> **⚠️ 发现缺口 = 给产品的问题，不是让 AI 填的答案。** 内审是把"该产品拍板的洞"点出来让 TA 拍，不是 AI 替 TA 编决策。源稿没有、产品没确认的逻辑，**绝不写成既定需求**——在对话里问产品，或标"（建议，待产品确认）"，或留给研发（见 `01 §0.5`）。

## 0. 范围铁律（先记死）：审产品逻辑，不审实现规格

你审的是 **产品该怎么表现**——什么状态下发生什么、选哪个、何时触发、两条规则一不一致。
你**不审** **工程怎么实现**——接口字段名/类型/路径/出入参/错误码枚举、用什么组件/容器/样式、动效尺寸、缓存策略。

**这些一律不算 C 端 PRD 缺陷，不要报（否则就是噪音、也是过度严格）：**
- "接口契约缺失 / 未定义返回字段 / 字段类型 / 接口路径 / 需补接口文档"
- "用什么弹窗 vs 抽屉 / 按钮挂哪 / 确认框长什么样 / 动效 / 具体尺寸"
- "缺路由 / URL / deeplink 字符串"（跳转**目标语义**要定义，但跳转的 URL 是实现细节）
- 埋点字段、国际化文案本身（这些由 `09/10` 单独处理，不在逻辑审里报）

**唯一例外——真死结才报**：前端明确要用某数据的**值**来决定展示，而 PRD 自己又写明这个值**拿不到**（标了"接口不返回/待大数据确认/无法提供"）。例：前端靠 KOL 标识选 4 个子模板之一，PRD 却写"KOL 标识当前接口未返回"→ 死结。

## 0.6 强制产物：逐对象闭环矩阵（把六维从"凭印象判"变成"填表，空格即缺口"）

> **根因铁律（本文件的核心）**：六维内容再全，只"读完扫一眼"仍会漏——漏的正是该产品拍板的开放决策（回顶怎么触发、邀请码没了怎么办、跳转目标不支持怎么办）。这些在 PRD 字面上是"没写"，扫描时最容易被"看着挺完整"盖过去。**唯一可靠的办法是机械枚举**：结构化内审工作流之所以每次都能挖出来，不是判得比你准，是它**逐个对象走完每一格**。kit 把这份刚性内建——不是多读一遍六维，是**产出一张矩阵**（与 `09 §1` 埋点对象清单同源同理，那条纪律把"漏抽"根治了，本关照搬）。

1. **复用 `09 §1` 的「独立 UI 对象清单」**——一次枚举、两个镜头：`09` 问"这个对象埋不埋点"，本文件问"这个对象逻辑闭不闭环"，别枚举两遍。纯后端/无 UI 需求：把"每个系统行为 / 状态迁移 / 定时任务"当对象行。
2. 对清单里**每个对象、每条跳转**填下面这张矩阵，**逐格填**（列 = 六维的落地问法）：

| 对象 / 跳转 | 状态（空 / loading / 失败 / 字段缺）·A | 闭环（进入→退出/返回定位）·B | 跳转（目标语义 + 目标不支持/无数据时降级）·B/E | 分支（每个"若"的"否则" + 阈值两侧归属）·C | 跨模块（要用的值拿得到？多处口径一致？）·E |
|---|---|---|---|---|---|
| （逐对象一行） | | | | | |

（每格填完再用 **F 边界极值** + **T 虚词/无口径** 各追问一遍。）

3. 🔴 **空格 = 缺口 = 对话里问产品**（不是让你填答案，见本文件开头铁律）。**矩阵有空格却发布 = 漏了一个该产品拍的洞。** 实测：回顶双轨、邀请码降级、跨标的跳转、主按钮是否自动下单——全是这张矩阵里某格空着、落笔时没填，最后靠外部工作流才走到；**填表就能在写作时点出来、当场问产品。**
4. 矩阵是**内部产物、不进 PRD**（和 `09` 对象清单一样，零正文废话）；它只驱动"要问产品哪些、要补哪些分支"。🔴 **但矩阵本身必须作为自检报告的可见附件落地**（`05 步骤2.5` 报告行要写"N 个对象 M 条跳转全格无空缺"）——弱模型最爱静默跳过这关，不产出矩阵不算过第二道门。
5. **平台**：Claude 可对每个对象起并行子 agent 各填一行再汇总；其它平台内联逐行填——**绝不因"文档看着完整"跳过某个对象**（那正是洞的藏身处）。

## 1. 六个维度（矩阵各列的落笔要点；判据以 checks-logic 镜像为准；必须有原文依据才算"覆盖"）

> 判定规则：只有在 PRD 里找到明确写了"这个情况怎么处理"，才算覆盖。找不到就是缺口——**不要因为文档整体看起来完整、或某模块"应该"会处理就默认覆盖了**。

> 🔴 **自检判据一律以 `checks-logic/L1–L4`（前端交互需求 `L4` 一并）镜像原文为准——逐个加载、机械枚举跑，同 `05` 之于 `checks/` 的用法。下面六维是写作落笔时的同源浓缩要点，帮你落地不漏，但不替代镜像原文当判据。**
>
> 🔴 **归属声明收紧（真审查器只认两类，其余裸"沿用现有逻辑"仍被爆缺口）**：归属声明只对 ①**约束归属**（"算法需确保不违反 X 硬性边界"这类收口句，L3 认）②**平台标准原语的值**（登录态/VIP/新用户/KYC/地区，前端调现有服务拿这个值即可，LC 认）有效。**状态兜底 A / 空态 / 上下文接收 B/E / 映射，用裸归属声明关不掉**——必须带上"具体展示什么 / 现有逻辑确已覆盖本上下文"的原文一句，否则等于没写（详见 `checks-logic/00-pipeline.md §三`）。
>
> 🔴 **输入可见面铁律**：进入六维/矩阵判定的逻辑一律落**原生文本或原生表格**，映射写成**显式文本对**（"行为A→template_1"）而非只靠表格列对齐；画板/嵌入表格/多维表格/思维导图/截图/评论里的逻辑一律**回填正文**（审查器读不到，视同没写）；长文别把验收堆最后（尾部超 8 万字截断）。详见 `checks-logic/00-pipeline.md §二`。

### A 状态覆盖
对每个有接口/有数据的关键模块逐项核对：
- 接口失败时前端有没有兜底/降级？（有任意失败兜底即算覆盖，不必区分 5xx/超时/解析失败）
- 加载中(loading)态有没有定义？
- 数据为空态——尤其**本模块依附的列表/容器整个为空**时（卡片挂在列表顶部，列表空了卡片显示在哪/还显不显）？
- 部分字段缺失态？

### F 边界极值
- 列表/集合为空的边界；单元素 / 最小集 / 数量正好等于阈值
- 超长内容：名称、文案、币种 symbol、用户输入 会不会溢出/截断？
- 数值边界：0 / 负数 / 超大
- 重复点击 / 快速连点 / 并发（请求未回又触发一次）
- 弱网 / 断网

### B 交互闭环
- 每个可点元素（按钮/卡片/链接）的**跳转目标语义**是否定义？（报"未定义"前先回概览/需求描述确认那里没写它跳哪）
- 每个"进入某态"是否有对应的"退出/返回态"？
- 跳走之后再回来是什么状态（保留/刷新/重置）？
- 可逆操作（开/关、显/隐）反向是否都定义？

### C 条件分支
- 每组枚举是否穷尽？（把枚举列出来逐个看）
- 每个"若 A 则 X"有没有写"否则"？
- 阈值两侧 + 边界值归属（`≥` 还是 `>`、`=X` 落哪边）写清了吗？
- 登录态 / 未登录态都覆盖了吗？

### E 跨模块自洽（我旧版第二道门最缺的一维）
逐项交叉核对（**报矛盾前先确认两处确实指同一对象/场景，再扫全文有没有一句化解了**——最常见是"先放开后收紧"）：
- **模板/条目数量对得上吗**（需求逻辑表列了 7 个行为，后端只定义 4 个 template_name，前端怎么区分？= 让功能无法实现的"数学错误"）
- **前端依赖的值 vs 该值拿不拿得到**（前端用某字段值决定展示，PRD 又标该字段"不返回/待确认"= 死结）
- **同一概念/数值在不同章节**：叫法、取值、口径是否一致？数字加得起来吗？
- **约束的归属**：一处写"算法决定"、另一处写"前端校验"、又一处写"用户选"→ 谁执行？（三方矛盾）
- **兜底/降级 vs 正常模板**：文案、跳转、字段结构是否一致？不一致有没有说明原因？

### T 可测性
- 有没有"智能/合理/动态/优化/自动/千人千时"这类**没法写成测试断言的虚词**？指出位置、说该换成什么可测规则。
- 有没有隐含某取值/规则、但没给具体值的？（说"随机"没给范围、说"按优先级"没列顺序）
- **机械触发（格式模式无口径，实测研发必问）**：正文出现 `{N}min`/`{N}h`/`MM-DD`、KMBT、百分比精度、滚动窗口（7D/24h/72h）等**分段格式模式**，却没给 分段边界+取整方向+时区/窗口起点、也没引用 `07 §一` house 默认口径 → 记遗漏（研发必问级，默认修——补法最省是一句"按 house 默认口径"）。
- 有没有一句话塞多个判断点、或指代不清（"它/该字段"指哪个）？

## 2. 跨维度死结（单点检查看不出，必须前后串联）
- **可达性链（A+B+C）**：活动上线 → 卡片在条件 Y 下推荐页 X → 页 X 依赖数据 Z → PRD 没保证 Y 成立时 Z 存在 → 用户看到空白页。
- **前置-达成链（F+B）**：签到活动承诺整月徽章，却月中上线、往期不可补签 → 该月徽章根本达不到。
- **上下文接得住吗（B+E）**：卡片按 KOL/多空侧/币种是上下文相关的，跳转目标页有没有定义"怎么接住并用上这个上下文"？没有就报。

## 3. 判定与从严（curator 心法：砍掉 70-80% 噪音）
每条发现问三关，任一"砍"就不报：
1. **scope 关**：是产品逻辑还是实现细节？实现细节 → 砍（见 §0）。
2. **合理默认关**：PRD 没写某情况时，前端能不能用一个显而易见的合理默认继续往下走？能 → 砍（哪怕没写全）；不能（缺必需的东西、只能瞎猜）→ 留。
3. **矛盾关**（矛盾型不走合理默认）：两种读法跑出来的**用户可见行为/数据/奖励**差别大不大？发错那支会不会是线上 bug？差别大 → 留；用户根本看不出差别 → 砍。

**severity（从严，别动辄给高）：**
- **高**：开发拿着没法动工，或上线出事故/资损/白屏/给用户错误承诺。
- **中**：有真缺口但不阻塞主流程，需业务补一个决策（大部分"某情况没定义"属这档）。
- **低**：边角细节。
- 拿不准给中；高留给真阻塞的。

## 4. 怎么用
- **写作时**：每个 US-R 落笔前后，**先产出 §0.6 逐对象闭环矩阵**（复用 `09` 对象清单），再用 §1 六维 + §2 死结 逐格填；空格即缺口。**发现的洞是给产品的问题，不是让你填的答案**——源稿没有、产品没确认的行为，**在对话里问产品定，带上你的建议**（"合约榜返回空你想展示空态还是回退现货？我建议展示空态，因为空是真实数据"）；**拿到产品的决定后写进正文**。**绝不自己编个决策写成既定需求，也绝不在 PRD 末尾堆一列「待确认」让产品自己去翻**——那不是"问"，是把活甩回给产品。只有真正**外部待定**（接口链接、上线时间、待运营回填的数值）才留，且极简。真正"逻辑经得住考验"= 把该产品拍板的洞在对话里点出来、让 TA 当场拍。
- **发布前**：`05 步骤2.5`「第二道门」= 核对 §0.6 矩阵无空格 + **逐个加载 `checks-logic/L1–L4` 镜像原文机械枚举跑**（六维判据即镜像原文，严重度/双钥匙/报告口径见 `checks-logic/00-pipeline.md`）。**这一关不可省、不可用「门禁 18 条自检」或 targeted-grep 替代——门禁按设计只查语义、不查闭环/降级完整性，能看见这些洞的只有本第二道门**（实测：靠门禁自检 + 关键词 grep 迭代多轮，闭环缺口一直不现，直到把稿子喂给外部结构化内审才走到——因为我们从没真跑过这道门）。**高 severity = 结构性断点，默认阻塞发布、可用户知情放行**（对齐 `05` 的放行程序）；中/低 = 建议。
- **范围自律**：本审只对**产品逻辑与可测性**负责；接口字段/组件/埋点字段/i18n 文案不在此报（埋点见 `09`、i18n 见 `10`）。

> **C 维机械触发补充（实测漏网）**：config 数值型参数（插入位/条数/阈值）必须定义"实际数据不足/越界"分支（如 insertIndex > 当前卡片总数时插哪）——缺失记遗漏。
