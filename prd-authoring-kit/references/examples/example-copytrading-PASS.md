# Background & Business Values 背景与价值

# 需求范围与边界 需求范围&风险点

- 带单员详情页「立即跟单」入口与跟单设置弹窗（跟单本金、按比例/固定额、止盈止损）。

## 本期不包含（Out of Scope）

- 不做带单员侧管理台（带单员设置分润比例、查看跟单人明细、主动踢除跟单人）。

- 不做跟单历史订单的独立报表页与导出（仅在现有合约订单列表内可见跟单标记）。
- 不做带单员业绩指标的实时逐秒刷新（30D 指标按 T+1 离线口径，详见 US2-R1）。

# Overall User Scenarios 用户场景总览

用户在带单员详情页发起跟单绑定；绑定成功后，跟单关系进入「监听中」状态。此后由带单员的开/平仓事件驱动系统自动为用户下跟单单，平仓时触发结算，并在关键节点推送通知。

```mermaid
flowchart TD
  A([用户进入带单员详情页]) --> B{是否登录且有合约权限}
  B -- 否 --> B1[拦截并引导：登录/KYC/开通合约]
  B -- 是 --> C[点击「立即跟单」]
  C --> D[弹出跟单设置：本金/比例或固定额/止盈止损]
  D --> E{参数校验通过?}
  E -- 否 --> E1[高亮错误项，不提交]
  E -- 是 --> F{可用余额≥跟单本金?}
  F -- 否 --> F1[提示余额不足，引导划转/充值]
  F -- 是 --> G[创建跟单绑定，状态=监听中]
  G --> H([带单员开仓事件])
  G --> K([带单员平仓事件])
  H --> H1{比例/固定额换算保证金}
  H1 --> H2{保证金充足且未超限额?}
  H2 -- 否 --> H3[本次跳过并推送「跟单失败」]
  H2 -- 是 --> H4[划转保证金+下跟单单，同一事件只生效一次]
  H4 --> H5[推送「跟单下单成功/失败」]
  K --> K1[平仓同步：按持仓比例平掉跟单仓]
  K1 --> K2[结算跟单单盈亏，保证金退回]
  K2 --> K3[推送「平仓结算」通知]
```

#### 需求逻辑：

#### 前端说明

带单员详情页底部提供「立即跟单」CTA；用户点击后弹出跟单设置弹窗，用户填写跟单本金、选择按比例或固定额、设置止盈止损，确认后创建对该带单员的跟单绑定关系。

**1. 「立即跟单」入口按钮**

| 原型 | 元素 | 说明 |
|------|------|------|
| 占位 | 立即跟单 CTA | **展示条件**：用户已登录、已完成 KYC、已开通合约交易，且该带单员当前为「可跟单」状态时，展示可点击的「立即跟单」。<br>**未满足时的分层处理**：① 未登录 → 按钮文案不变但点击拦截，唤起登录；② 已登录未 KYC/未开通合约 → 按钮置为「去开通」，点击跳转开通流程；③ 该带单员已停止带单或被风控下架（不可跟单）→ 按钮置灰不可点，副文案「该带单员暂不可跟单」；④ 当前用户对该带单员**已存在监听中的绑定** → 按钮文案变为「跟单设置」，点击进入 US1-R3 的管理态而非新建。<br>**交互**：满足展示条件时点击 → 弹出跟单设置弹窗（子模块 2）。 |

**2. 跟单设置弹窗**

| 原型 | 元素 | 说明 |
|------|------|------|
| 占位 | 跟单本金输入 | **展示规则**：币种固定为 USDT；输入框默认空，placeholder 展示最小跟单本金（取自配置）。金额精度 2 位小数，千分位分隔。<br>**校验（分输入域写清）**：输入=空 → 提交时高亮「请输入跟单本金」，不提交；输入=0 或低于最小跟单本金 → 提示「最低跟单本金为 X USDT」，不提交；输入 > 账户可用余额 → 提示「可用余额不足」并展示「去划转」，不提交；输入为非数字/负数/超过最大跟单本金等非法值 → 提示「请输入 X~Y 之间的金额」，不提交；输入合法 → 放行。 |
| 占位 | 跟单方式（按比例 / 固定额）单选 | **展示规则**：二选一单选，默认选中「按比例」。<br>**按比例**：用户填写跟单比例（如 10%），表示带单员每次开仓保证金 × 跟单比例作为本次跟单保证金；跟单比例取值域 (0%, 100%]，步长 1%，0%/空/>100% 均判非法并高亮不提交。<br>**固定额**：用户填写每次跟单的固定保证金（USDT），取值域 [单次跟单保证金下限, 单次跟单保证金上限]，越界高亮不提交。<br>**交互**：切换单选时，另一分支输入框置灰清空，仅提交当前选中分支的参数。 |
| 占位 | 止盈止损设置 | **展示规则**：止盈/止损各为一个开关 + 百分比输入，默认均关闭。开启止盈：填写止盈百分比（相对跟单单开仓价的浮盈比例），取值域 (0%, 500%]；开启止损：填写止损百分比，取值域 (0%, 100%]。<br>**校验**：开关开启但百分比为空/0/越界 → 高亮不提交；未开启则该项不参与下单，跟单单不挂止盈止损。<br>**交互**：止盈止损作用于「跟单单」自身，不改变带单员原单；触发止盈/止损平仓属于用户侧独立平仓，不等待带单员平仓。 |
| 占位 | 风险提示与确认 | **展示规则**：弹窗底部固定展示风险提示文案（合约有爆仓风险、跟单不保证盈利），用户需勾选「已阅读并同意《跟单服务协议》」后「确认跟单」按钮方可点击。<br>**交互**：点击「确认跟单」→ 先做前端校验（上述各项），全部通过 → 提交创建绑定（见 US1-R2）。 |

### US1-R2：创建跟单绑定关系

#### 需求逻辑：

#### 前端说明

用户在设置弹窗点击「确认跟单」后，系统创建当前用户与该带单员的跟单绑定关系，持久化跟单参数（本金、比例/固定额、止盈止损），并将关系状态置为「监听中」，作为后续开平仓同步下单的依据。

**1. 绑定创建规则**

| 原型 | 元素 | 说明 |
|------|------|------|
| 占位 | 绑定创建结果 | **展示规则**：创建成功 → 弹窗关闭，toast「跟单已开启」，详情页 CTA 变为「跟单设置」。<br>**唯一性规则**：同一用户 × 同一带单员在「监听中」状态下**至多一条**绑定关系；用户已存在监听中绑定时，创建请求返回「已在跟单」，前端提示并跳转跟单管理页，不新建第二条。<br>**幂等规则**：见后端逻辑。<br>**交互**：创建成功后新参数即刻对后续带单员开仓事件生效；对创建时点带单员**已持有的存量仓位**，本期规则为「不追单」（仅跟绑定之后的新开仓），此规则在弹窗内以副文案明示。 |

#### 后端说明：

**接口信息需求清单**（创建绑定要落哪些信息；字段命名与接口契约由技术方案定）

| 信息 | 说明 |
|------|------|
| 跟单绑定的唯一标识 | 创建成功后返回，前端后续用它定位这条绑定（跟单管理页展示、暂停、关闭都基于它） |
| 绑定归属 | 这条绑定属于哪个用户、跟的是哪位带单员 |
| 跟单方式与参数 | 按比例还是固定额，以及对应的跟单比例或固定保证金；用户设置后持久化，开仓同步照它换算 |
| 止盈止损设置 | 止盈、止损各自是否开启，开启时的百分比；未开启则该笔跟单单不挂止盈止损 |
| 跟单本金 | 用户本次设置的本金金额（USDT，2 位小数） |
| 绑定状态 | 监听中 / 已暂停 / 已关闭三者之一，由合约交易后端维护；跟单管理页据此展示状态标签、开平仓同步据此判断是否响应 |

> 资金幂等说明：创建绑定本身不发生资金划转（划转发生在开仓同步时，见 US1-R4）。为防「确认跟单」被重复点击或请求被重发造成重复绑定，**同一次提交只创建一条绑定**：重复提交返回的仍是已创建的那一条，不新建第二条、不重复占用资金。

#### 兜底逻辑：

| 异常场景 | 触发条件 | 系统行为 | 用户提示 |
|---------|---------|---------|---------|
| 创建绑定接口失败 | HTTP 5xx / 超时 | 弹窗保持打开，参数不丢失，允许重试；重试不会产生重复绑定 | 「开启跟单失败，请重试」 |
| 已存在监听中绑定 | 唯一性冲突 | 不新建，返回已有的那条绑定 | 「您已在跟单该带单员」并跳转管理页 |
| 提交后带单员转为不可跟单 | 创建瞬间该带单员变为不可跟单 | 拒绝创建，不落库 | 「该带单员已停止带单」 |
| 防重标识缺失 | 创建请求缺少可用于判定「是否同一次提交」的标识 | 拒绝该次请求且不落库（不静默补发），前端重新生成后重试 | 前端静默重试，用户无感 |

### US1-R3：跟单管理（查看 / 暂停 / 关闭跟单）

#### 需求逻辑：

#### 前端说明

用户可在跟单管理页查看已绑定的带单员及跟单参数，并可暂停或关闭跟单。关闭跟单后停止响应带单员新的开平仓事件。

**1. 跟单管理列表与操作**

| 原型 | 元素 | 说明 |
|------|------|------|
| 占位 | 跟单关系卡片 | **展示条件**：展示当前用户所有状态为「监听中」或「已暂停」的绑定；已关闭的不在列表展示。<br>**展示规则**：每张卡片展示带单员昵称/头像、跟单方式与参数、当前跟单持仓数与浮动盈亏（来源见后端逻辑）、状态标签（监听中/已暂停）。<br>**交互**：<br>① 暂停：监听中 → 已暂停，暂停期间**不响应带单员新开仓**，但**已持有的跟单仓位仍按原规则跟随带单员平仓**（即只停开、不停平），此规则在二次确认弹窗明示。<br>② 关闭跟单：置为已关闭，二次确认。关闭时若用户仍持有跟单仓位，弹窗提供二选一：「立即市价平掉全部跟单仓」或「保留仓位仅解除绑定（后续该仓位不再自动平）」，用户显式选择，无默认项。 |

### US1-R4：带单员开/平仓同步跟单下单（含保证金划转）

#### 需求逻辑：

#### 前端说明

系统订阅带单员的开/平仓事件。带单员开仓时，对每条监听中的绑定按用户设置的比例/固定额换算跟单保证金，划转保证金并下与带单员同方向的跟单单；带单员平仓时，按持仓比例平掉对应跟单仓。这是纯后端事件驱动逻辑，无前端交互，以下按系统行为描述。

**1. 开仓同步（系统行为）**

| 触发 | 系统行为 |
|------|---------|
| 收到带单员开仓事件（含交易对、方向、开仓保证金、杠杆、开仓价） | ① 查出该带单员所有状态为「监听中」的绑定（已暂停/已关闭跳过）。<br>② 对每条绑定换算本次跟单保证金：按比例 → `跟单保证金 = 带单员开仓保证金 × 跟单比例`；固定额 → `跟单保证金 = 用户设置的固定保证金`。<br>③ 校验：换算保证金 < 交易对最小下单额 → 本次**跳过**该绑定并推送「跟单失败-金额过小」；跟单账户可用余额 < 换算保证金 → 本次**跳过**并推送「跟单失败-余额不足，请补充保证金」；命中持仓限额/风控 → **跳过**并推送「跟单失败-超出限额」。<br>④ 校验通过 → 划转保证金并下同方向单，**同一次开仓事件对同一条绑定只划转一次、只下一次单**；杠杆对齐带单员本次杠杆（超出用户合约档位上限则取上限并记录）。<br>⑤ 下单结果推送「跟单下单成功/失败」（见 US2-R2）。 |

**2. 平仓同步（系统行为）**

| 触发 | 系统行为 |
|------|---------|
| 收到带单员平仓事件（全平或部分平，含平仓比例） | ① 找到该带单员该交易对下各绑定对应的跟单仓位。<br>② 按带单员平仓比例同比例平掉跟单仓（带单员全平→跟单全平；平 50%→跟单平 50%）。<br>③ 平仓成交后触发结算（见 US1-R5），退回可用保证金。<br>④ **同一次平仓事件对同一条绑定只平一次**，重复投递的事件不重复平仓。<br>⑤ 若跟单仓已被用户自身止盈止损/手动提前平掉 → 该绑定本次平仓事件视为**无仓可平**，静默跳过、不报错、不重复退款。 |

#### 后端说明：

**接口信息需求清单**（跟单同步要从带单员开/平仓事件拿到哪些信息；字段命名与接口契约由技术方案定）

| 信息 | 说明 |
|------|------|
| 带单员这次是开仓还是平仓 | 合约交易后端提供，跟单同步由它驱动；同一次开/平仓在系统内可被唯一识别，以保证「同一次事件对同一条绑定只处理一次」 |
| 带单员本次开仓保证金 | 「按比例」跟单时的换算基数，USDT 2 位小数 |
| 带单员本次杠杆 | 跟单单杠杆对齐它；超出用户合约档位上限则取上限 |
| 交易对 | 跟单单下在同一交易对上（如 BTCUSDT） |
| 开/平仓方向 | 看多 / 看跌；跟单单与带单员同方向 |
| 本次平仓比例 | 平仓事件提供，跟单仓按同比例平（全平/部分平） |
| 标记价 | 行情/撮合服务提供，用于跟单仓浮动盈亏与结算计算，2 位小数 |

> 资金幂等（US1-R4 重点）：<br>1. **划转保证金**与**下跟单单**统一按「同一次带单员事件 × 同一条绑定」判重，至多划转一次、下单一次。<br>2. 保证金划转与下单在同一事务/补偿链路内：若划转成功但下单失败，回滚（退回已划转保证金）并记账，避免资金被占用却无对应仓位。<br>3. 平仓退保证金同样只生效一次，重复投递的平仓事件不重复退款。

#### 兜底逻辑：

| 异常场景 | 触发条件 | 系统行为 | 用户提示 |
|---------|---------|---------|---------|
| 换算保证金过小 | 换算值 < 交易对最小下单额 | 跳过该绑定本次开仓，记录跳过原因 | 推送「跟单失败-金额过小」 |
| 余额不足 | 跟单账户可用 < 换算保证金 | 跳过该绑定本次开仓，不划转不下单 | 推送「跟单失败-余额不足，请补充保证金」 |
| 超持仓限额/风控拦截 | 命中限额或风控规则 | 跳过本次开仓 | 推送「跟单失败-超出限额」 |
| 划转成功但下单失败 | 撮合返回失败/超时 | 回滚已划转保证金（补偿），记账告警 | 推送「跟单失败-下单未成功，保证金已退回」 |
| 事件重复投递 | 同一次开/平仓事件被重复消费 | 判定为已处理，直接丢弃，不重复划转/下单/平仓 | 无（用户无感） |
| 事件关键信息缺失/非法 | 带单员开仓保证金、交易对或方向为空/非法 | 判为脏事件，不下单，进死信队列告警，人工核查 | 无（用户无感，避免错单） |
| 无仓可平 | 平仓事件时该绑定跟单仓已被用户提前平掉 | 静默跳过，不报错、不重复退款 | 无 |

### US1-R5：带单员平仓触发跟单结算

#### 需求逻辑：

#### 前端说明

带单员平仓且跟单仓平仓成交后，系统对该笔跟单单结算，计算已实现盈亏、退回保证金到用户合约可用余额，并触发结算通知。纯后端逻辑，按系统行为描述。

**1. 结算（系统行为）**

| 触发 | 系统行为 |
|------|---------|
| 跟单仓平仓成交回报到达 | ① 按成交均价计算本笔跟单单已实现盈亏：`已实现盈亏 = (平仓价 - 开仓价) × 数量 × 方向系数 - 手续费`。<br>② 将（本金保证金 ± 盈亏 - 手续费）退回用户合约可用余额。<br>③ 生成一条跟单结算记录（含带单员、交易对、方向、开平价、盈亏、手续费）。<br>④ **同一笔平仓成交只入账一次**，已结算的重复回报直接丢弃。<br>⑤ 结算完成推送「平仓结算」通知（见 US2-R2）。 |

#### 后端说明：

**接口信息需求清单**（结算要哪些信息；字段命名与接口契约由技术方案定）

| 信息 | 说明 |
|------|------|
| 本笔跟单单已实现盈亏 | 合约交易后端按成交均价与手续费计算（成交价来自撮合成交回报）；USDT 2 位小数，可为负，展示带正负号并跟随涨跌色 |
| 本笔手续费 | 撮合成交回报提供，USDT 2 位小数 |
| 退回可用余额的金额 | = 占用保证金 + 已实现盈亏（盈亏已扣手续费）；下限 0，穿仓走爆仓逻辑另计 |
| 结算记录内容 | 带单员、交易对、方向、开仓价与平仓价、盈亏、手续费——用户在结算记录里能看到这几项 |

> 资金幂等（US1-R5 重点）：**同一笔平仓成交只结算入账一次**——重复的成交回报、重复消费、入账超时后的重试，都只让用户可用余额增加一次，退回金额只到账一次。穿仓（退回金额算下来为负）不向用户可用余额扣负，转爆仓/风险准备金处理链路，不在本 PRD 展开。

#### 兜底逻辑：

| 异常场景 | 触发条件 | 系统行为 | 用户提示 |
|---------|---------|---------|---------|
| 结算入账重复 | 同一笔平仓成交的结算重复到达 | 判定为已入账，丢弃，不重复入账 | 无（用户无感） |
| 成交回报关键信息缺失/非法 | 成交价或手续费为空/非法 | 暂缓结算，转异常队列人工核对，金额留空待核对后入账 | 无（延迟到账，客服可查） |
| 退款到账失败 | 资金系统入账接口 5xx/超时 | 结算记录标记「入账待重试」，重试直到成功，且只入账一次 | 无（最终一致） |
| 穿仓 | 退回金额算下来为负 | 转爆仓处理，可用余额不扣负 | 结算记录标注「已爆仓」 |

#### 前端说明

**1. 三项业绩指标**

|------|------|------|

| 占位 | 30D 最大回撤 | **展示规则**：百分比，2 位小数，固定以负向/红色语义展示（如 -23.45%），值域 [0,100]，越大代表回撤越深。<br>**分输入域**：=0 → 「0.00%」（近 30 日无回撤）；未返回/为空 → 「--」；非法 → 「--」+日志。 |

### US2-R2：跟单事件推送通知（下单成功/失败、平仓结算）

#### 需求逻辑：

#### 前端说明

在三类关键节点通过站内信 + Push 通知用户：① 跟单下单成功；② 跟单下单失败（含各失败情形）；③ 带单员平仓触发结算完成。纯后端触发 + 前端落地，按系统行为描述。

**1. 三类通知（系统行为）**

| 触发 | 系统行为 |
|------|---------|
| 跟单开仓下单成功（US1-R4 ④成功） | 发「跟单下单成功」通知：含带单员昵称、交易对、方向、跟单保证金、开仓价。落地跳转该跟单仓详情。 |
| 跟单开仓下单失败（US1-R4 各跳过/失败分支） | 发「跟单下单失败」通知：含带单员昵称、交易对，以及本次失败对应的文案（四种情形见子模块 2）。落地跳转跟单管理页。 |
| 平仓结算完成（US1-R5 ⑤） | 发「平仓结算」通知：含带单员昵称、交易对、已实现盈亏（带正负色）、退回金额。落地跳转结算记录。 |

**2. 错误码表：失败情形与用户看到的文案**（与 US1-R4 的跳过/失败分支一一对应；用户文案已同步进 §Localisation）

| 错误码 | 触发场景 | 用户文案与动作 |
|-------|---------|---------------|
| AMOUNT_TOO_SMALL | 换算出的跟单保证金低于交易对最小下单额 | 推送「跟单失败-金额过小」，本次不下单、不划转，点击落地跟单管理页 |
| INSUFFICIENT_BALANCE | 跟单账户可用余额不足以支付本次跟单保证金 | 推送「跟单失败-余额不足，请补充保证金」，本次不下单、不划转，点击落地跟单管理页 |
| EXCEED_LIMIT | 命中持仓限额或风控拦截 | 推送「跟单失败-超出限额」，本次不下单，点击落地跟单管理页 |
| ORDER_FAILED_REFUNDED | 保证金已划转但跟单单下单未成功 | 推送「跟单失败-下单未成功，保证金已退回」，保证金已回到可用余额，点击落地跟单管理页 |

**3. 推送冷却与去重（系统行为）**

| 规则 | 说明 |
|------|------|
| 去重 | 同一次跟单事件对同一条绑定的同一类通知**只推一条**，重复事件不重复推送（与下单/结算的「只生效一次」口径对齐）。 |
| 冷却/聚合 | 同一用户在活跃行情下可能因带单员高频开平仓收到大量通知。规则：**同一带单员 × 同一类通知，60 秒内多条合并为 1 条聚合推送**（如「BTCUSDT 等 3 笔跟单已下单」），聚合窗口内后续到达顺延累计；不同类通知（成功/失败/结算）不互相合并，各自独立冷却。 |
| 通道 | 站内信必达（可在消息中心回看）；Push 受系统通知开关控制，关闭时仅站内信，不重试 Push。 |

#### 后端说明：

**接口信息需求清单**（通知要哪些信息；字段命名与接口契约由技术方案定）

| 信息 | 说明 |
|------|------|
| 通知类型 | 「跟单下单成功」/「跟单下单失败」/「平仓结算」三者之一，决定通知文案模板与点击落地页 |
| 带单员昵称与交易对 | 三类通知正文都要展示 |
| 跟单保证金与开仓价 | 「跟单下单成功」通知正文展示 |
| 本次失败情形 | 「跟单下单失败」通知按情形取子模块 2 表里的对应文案 |
| 已实现盈亏与退回金额 | 「平仓结算」通知正文展示，盈亏带正负号与涨跌色（来自 US1-R5 结算结果） |

> 推送冷却（US2-R2 重点）：<br>1. **去重**：同一次跟单事件对同一条绑定的同一类通知只推一次。<br>2. **冷却聚合**：同带单员 × 同一类通知，60 秒滚动窗口内多条合并为 1 条聚合推送，避免高频行情下通知轰炸。<br>3. 三类通知独立冷却，互不合并（失败通知不能被成功通知冷却吞掉）。

#### 兜底逻辑：

| 异常场景 | 触发条件 | 系统行为 | 用户提示 |
|---------|---------|---------|---------|
| Push 通道失败 | Push 网关 5xx/超时 | 站内信仍写入（必达），Push 不无限重试（最多 1 次），记录失败 | 用户在消息中心可见站内信 |
| 用户关闭系统通知 | 系统级 Push 开关关闭 | 仅站内信，不下发 Push，不报错 | 站内信可回看 |
| 重复事件 | 同一次事件的同类通知重复触发 | 判定为已推送，不重复推送 | 无 |
| 高频轰炸 | 60s 内同带单员同类型多条 | 合并为 1 条聚合推送 | 聚合文案「等 N 笔」 |
| 通知内容缺失 | 昵称/金额等为空 | 缺失处以「--」占位，通知仍发出，不因单项缺失而不推 | 对应处「--」 |

# 验收标准

> 本章节按 US-R 一一对应汇总各功能点的验收断言（内容与原分散小节一致），另设「性能验收」收纳非功能需求相关断言。

## US1-R1 功能验收

- [ ] 当用户已登录、已开通合约、带单员处于可跟单状态时，详情页展示可点击「立即跟单」，点击 1 次在 1s 内弹出跟单设置弹窗。
- [ ] 当带单员为不可跟单，或「是否可跟单」为空 / 非法任一情况时，「立即跟单」均为不可点击态，且不会弹出跟单设置弹窗。
- [ ] 当跟单本金输入为空 / 0 / 低于最小跟单本金 / 超过最大跟单本金 / 超过可用余额 / 非数字时，分别展示对应错误文案且**不提交**创建绑定请求。
- [ ] 当选「按比例」且跟单比例 ∈ (0%,100%]、或选「固定额」且固定保证金 ∈ [单次跟单保证金下限, 上限] 时才允许提交；越界项高亮且不提交。
- [ ] 当未勾选跟单服务协议时，「确认跟单」按钮不可点击。
- [ ] 当详情页配置接口失败时，Web 与 App 均展示重试入口，且此时无法进入跟单设置。

## US1-R2 功能验收

- [ ] 当用户提交合法参数时，系统创建一条状态为「监听中」的绑定并返回该绑定标识，弹窗关闭并 toast「跟单已开启」。
- [ ] 当同一次「确认跟单」被重复提交（重复点击/网络重发）时，仅存在 1 条绑定关系，且返回的是同一条绑定，不重复占用资金。
- [ ] 当该用户对同一带单员已有监听中的绑定时，再次提交不新建第二条，提示「您已在跟单该带单员」。
- [ ] 当创建请求缺少防重标识时，该请求被后端拒绝且不落库。
- [ ] 当创建接口超时后用户重试时，不产生重复绑定。

## US1-R3 功能验收

- [ ] 当用户有监听中/已暂停的绑定时，管理页展示对应卡片，含带单员信息、参数、持仓数与浮动盈亏；已关闭的不展示。
- [ ] 当用户暂停某绑定时，该绑定状态变为「已暂停」，此后带单员新开仓不再产生该用户跟单单，但已有跟单仓仍随带单员平仓而平。
- [ ] 当用户关闭跟单且持有跟单仓时，必须显式二选一「立即平掉」或「保留仓位解绑」，无默认选项。
- [ ] 当关闭跟单的平仓请求重复触发（重复点击/重试）时，跟单仓只被平一次、保证金只退一次。
- [ ] 当跟单浮动盈亏缺失或非法时，仅该数值处显示「--」，卡片其余信息正常展示。

## US1-R4 功能验收

- [ ] 当带单员开仓且某绑定为「按比例」时，系统按「带单员开仓保证金 × 跟单比例」下同方向跟单单；为「固定额」时按用户设置的固定保证金下单。
- [ ] 当同一次开仓事件对同一条绑定被重复消费时，保证金只划转一次、跟单单只下一次。
- [ ] 当换算保证金 < 交易对最小下单额 / 余额不足 / 超限额时，系统跳过本次开仓且不划转资金，并分别推送对应失败文案。
- [ ] 当保证金划转成功但下单失败时，系统在同一补偿链路内退回已划转保证金，不留下无仓位的占用资金。
- [ ] 当带单员部分平仓（如 50%）时，对应跟单仓按同比例平仓；带单员全平时跟单全平。
- [ ] 当平仓事件到达但跟单仓已被用户提前平掉时，系统静默跳过且不重复退款。
- [ ] 当事件关键信息（交易对/方向/带单员开仓保证金）为空/非法时，系统不下单并将事件转入死信告警。

## US1-R5 功能验收

- [ ] 当跟单仓平仓成交时，系统按成交均价计算已实现盈亏并退回（保证金+盈亏-手续费）到用户合约可用余额。
- [ ] 当同一笔平仓成交的结算重复到达时，退回金额只入账一次。
- [ ] 当成交价或手续费为空/非法时，系统不入账、转异常队列，金额留空待人工核对。
- [ ] 当入账接口超时后重试时，用户可用余额只增加一次（无重复到账）。
- [ ] 当发生穿仓（退回金额算下来为负）时，用户可用余额不被扣为负数。

## US2-R1 功能验收

- [ ] 当三项指标均正常返回时，卡片展示 30D 胜率（含 0% 情形）、收益率（带正负号与站点涨跌色）、最大回撤，并标注「数据更新至 T-1」。
- [ ] 当某项指标为 0 时展示「0%/0.00%」而非「--」；当未返回/为空/非法时展示「--」。
- [ ] 当统计接口整体失败时，三项均「--」但卡片其余元素（含跟单按钮）仍可用。
- [ ] 当收益率为超长值时，卡片内千分位+截断展示，且可通过详情查看完整值。

## US2-R2 功能验收

- [ ] 当跟单开仓下单成功时，用户收到「跟单下单成功」通知（站内信必达，Push 视开关），点击落地跟单仓详情。
- [ ] 当开仓因金额过小/余额不足/超限额/下单失败退款而未成时，用户收到子模块 2 表中对应情形的失败文案。
- [ ] 当平仓结算完成时，用户收到含已实现盈亏与退回金额的「平仓结算」通知。
- [ ] 当同一次事件的同类通知重复触发时，用户只收到 1 条该通知。
- [ ] 当 60 秒内同一带单员同一类型产生多条通知时，合并为 1 条聚合推送；成功/失败/结算三类不互相合并。
- [ ] 当用户关闭系统 Push 时，仍能在消息中心回看对应站内信，且系统不报错。

## 性能验收

- [ ] 从带单员开/平仓事件落地到系统为跟单用户完成下单，P95 < 800ms（正常时段，不含撮合排队与网络 RTT）。
- [ ] 详情页/统计/管理列表核心读接口 P99 < 300ms（单节点，不含网络 RTT）。
- [ ] 跟单管理页首屏 FCP < 2s（P95）。
- [ ] 开/平仓事件端到端不丢不重（至少一次投递 + 幂等消费），重复率对用户资金影响为 0。

| 带单员业绩为 T+1 离线，用户误以为实时 | 中 | 中 | 卡片显式标注「数据更新至 T-1」 |
