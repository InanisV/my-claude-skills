# L3 跨模块自洽（审查prompt逐字镜像）

> 来源节点：`LLM_3 跨模块自洽`（id 1900000000011）· 模型 gpt-5 · temperature 0 · enable_thinking true。
> 覆盖维度：跨模块自洽 E（含范围校准铁律 + 死结判定）。
> 变量占位：`{{#1900000000007.doc_text_clean#}}` = PRD 全文；`{{#1900000000008.text#}}` = L0 结构地图（可见面见 `00-pipeline.md`）。

## 审查prompt（逐字）

```
【范围校准：这是偏 C 端的产品 PRD】审的是前端展示/交互/状态逻辑，不是后端接口规格。后端接口的字段名/类型/路径/出入参/schema 由后端和联调阶段定义，C 端 PRD 不写到这个程度是正常的，不是缺陷。
- 【绝对不要报】"接口契约缺失""未定义返回字段/字段类型/接口路径/出入参""需补充接口文档""后端需明确 XX 字段枚举值/格式规范"——这些都不是 C 端 PRD 的缺陷。PRD 只说"调用相关接口"没列字段，正常，不报。
- 【只有真死结才报】前端明确要用某个数据的【值】来决定展示，而 PRD 自己又写明这个数据【拿不到】(标了"接口不返回该字段/该字段待大数据确认补充/无法提供")。例：前端靠 KOL 标识的值选 4 个子模板之一，PRD 却写"KOL 标识当前接口未返回"——这才是死结。注意：只是文案待确认(数据本身假设拿得到)不算死结，最多低优先级。
- 【其余只报前端 UX 逻辑缺口】状态/交互/边界/跳转/分支没定义。口诀：问题是"后端接口该写多细"→不报；"用户在前端会撞上一个没定义的情况"→报。

你在核对一份 PRD 的跨模块自洽性——找互相打架或对不上的地方。逐项做下面的交叉核对，每一对都要认真比。

【逐项交叉核对】
- 后端契约的每个字段（接口返回啥）vs 前端怎么用它：有没有前端依赖某字段、但后端把该字段标了"不返回 / 待确认 / 待补充"的？（这是最常见的死结）
- 需求逻辑表里的条目/模板 vs 后端模板定义：数量对得上吗？字段对得上吗？（例：表里列了7个模板，后端只定义4个 template_name，前端怎么区分？）
- 每条"硬性约束 / 不可做的事" vs 谁来执行：约束写在A处，但执行方（算法侧 / 前端侧）说不清？（注意：若 PRD 已写"算法需确保不违反这些硬性边界"这类收口句，约束就有归属了，不是矛盾，别报。）
- 兜底/降级 vs 对应的正常模板：文案、跳转、字段结构是否一致？不一致有没有说明原因？
- 同一概念/数值在不同章节：叫法、取值、口径是否一致？数字加得起来吗？

【判定规则】报"矛盾"前做两件事：①确认两处确实指同一对象/同一场景（两处都说"前N个"但指不同列表不算矛盾）；②扫全文有没有一句把它化解了——最常见是"先放开后收紧"：前面说"完全自主/不约束"，同节或后面某句又补"但需满足/不得违反 X 边界"，这就收住了，不是矛盾。例：1.3 说"弹什么完全由算法自主"，但同节末句"算法侧需确保不违反 1.2 硬性边界"已收口，这种不报。只看前半段就报，是最常见的假矛盾。

【PRD 全文】
{{#1900000000007.doc_text_clean#}}

【结构地图（定位用）】
{{#1900000000008.text#}}

【severity 从严，别动辄给高】
- 高：开发拿着没法动工，或上线出事故/资损/白屏/给用户错误承诺。
- 中：有真缺口但不阻塞主流程，需要业务补一个决策。大部分"某情况没定义"属于这一档。
- 低：细枝末节、边角。
拿不准就给中。高要留给真阻塞的，不要因为是个缺口就判高。标高前自检两条：①没有任何合理默认可兜；②发错会资损/白屏/错误承诺/开发无法动工。两条都占才给高，缺一条给中。

【合并同根因，别拆碎】同一个根本问题不要拆成多条上报。例：接口调用失败、返回错误码、字段格式异常其实都是"接口/字段异常处理没定义清楚"，合并成一条，problem 里把涉及的几种情况点到。

只输出 JSON，problem/fix 各一句话（problem 说清哪两处怎么打架，fix 给统一方向）：
{"findings":[{"dimension":"E","severity":"高/中/低","module":"位置","problem":"...","fix":"..."}]}
没矛盾就 {"findings":[]}。
```

## 输出格式（逐字）

仅输出 JSON，problem/fix 各一句话（problem 说清哪两处怎么打架，fix 给统一方向）：`{"findings":[{"dimension":"E","severity":"高/中/低","module":"位置","problem":"...","fix":"..."}]}`，没矛盾就 `{"findings":[]}`。
