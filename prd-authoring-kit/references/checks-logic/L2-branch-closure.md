# L2 分支&闭环（审查prompt逐字镜像）

> 来源节点：`LLM_2 分支&闭环`（id 1900000000010）· 模型 gpt-5 · temperature 0 · enable_thinking true。
> 覆盖维度：交互闭环 B + 条件分支 C + 跳转交叉。
> 变量占位：`{{#1900000000007.doc_text_clean#}}` = PRD 全文；`{{#1900000000008.text#}}` = L0 结构地图（可见面见 `00-pipeline.md`）。

## 审查prompt（逐字）

```
你在核对一份 PRD 的交互闭环和条件分支。逐项对照清单检查，只输出有问题的项。

【判定规则】只有找到明确定义才算覆盖、跳过；找不到就报。不要默认"应该会处理"。

【交互闭环 B】逐项核对：
- 每个可点元素（按钮、卡片、链接）的跳转目标是否都定义了？（同一元素的跳转目标常写在顶部概览/需求描述而非本节，报某元素"跳转未定义"前先回概览确认那里没写它跳哪）
- 每个"进入某态"是否有对应的"退出/返回态"？
- 跳走之后再回来，是什么状态？
- 可逆操作（开/关、显/隐）反向是否都定义？

【跳转接得住吗·第二遍交叉】光看"有没有写跳哪"不够，把"推荐/触发条件"和"跳转目标"连起来看：
- 卡片/元素是上下文相关的吗（按 KOL、按多空侧、按币种或状态变体）？若是，PRD 有没有定义目标页怎么接收并用上这个上下文？没有就报（如特朗普卡片跳"AI策略单弹窗"，弹窗带不带这个 KOL 没说）。
- 跳转的落地依赖某数据/条件存在吗（如"跳该币智能K线计划页"依赖该币有 K线数据）？PRD 有没有保证它一定存在、或定义不存在时怎么办？没有→可能落到空页面，报（尤其主文已承诺内容、却可能落空时）。
- 有没有某种被推荐的情况，跳过去会撞上空 / 不存在的状态？

【条件分支 C】逐项核对：
- 每组枚举是否穷尽？（把枚举列出来，逐个看有没有处理）
- 每个关键条件"若A则X"有没有写"否则"？
- 阈值两侧 + 边界值归属（≥还是>）写清了吗？
- 登录态/未登录态都覆盖了吗？

【PRD 全文】
{{#1900000000007.doc_text_clean#}}

【结构地图（定位用）】
{{#1900000000008.text#}}

【severity 从严，别动辄给高】
- 高：开发拿着没法动工，或上线出事故/资损/白屏/给用户错误承诺。
- 中：有真缺口但不阻塞主流程，需要业务补一个决策。大部分"某情况没定义"属于这一档。
- 低：细枝末节、边角。
拿不准就给中。高要留给真阻塞的，不要因为是个缺口就判高。标高前自检两条：①没有任何合理默认可兜；②发错会资损/白屏/错误承诺/开发无法动工。两条都占才给高，缺一条给中。

【合并同根因，别拆碎】同一个根本问题不要拆成多条上报。例：接口调用失败、返回错误码、字段格式异常其实都是"接口/字段异常处理没定义清楚"，合并成一条，problem 里把涉及的几种情况点到。

只输出 JSON，problem/fix 各一句话：
{"findings":[{"dimension":"B或C","severity":"高/中/低","module":"位置","problem":"...","fix":"..."}]}
没问题就 {"findings":[]}。
```

## 输出格式（逐字）

仅输出 JSON，problem/fix 各一句话：`{"findings":[{"dimension":"B或C","severity":"高/中/低","module":"位置","problem":"...","fix":"..."}]}`，没问题就 `{"findings":[]}`。
