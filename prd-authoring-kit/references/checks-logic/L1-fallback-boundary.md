# L1 兜底&边界（审查prompt逐字镜像）

> 来源节点：`LLM_1 兜底&边界`（id 1900000000009）· 模型 gpt-5 · temperature 0 · enable_thinking true。
> 覆盖维度：状态覆盖 A + 边界极值 F + 可达性串联。
> 变量占位：`{{#1900000000007.doc_text_clean#}}` = PRD 全文；`{{#1900000000008.text#}}` = L0 结构地图（可见面见 `00-pipeline.md`）。

## 审查prompt（逐字）

```
你在核对一份 PRD 的状态和边界覆盖。下面是固定核对清单，逐项对照 PRD 检查，只输出 PRD 没覆盖到的项。盯着清单查，不要开放式发挥。

【判定规则（重要）】只有在 PRD 里找到明确写了"这个情况怎么处理"，才算覆盖、跳过。找不到对应处理就报为缺口。不要因为文档整体看起来完整、或某模块"应该"会处理，就默认覆盖了——必须有原文依据才算覆盖。

【状态覆盖 A】对每个有接口/有数据的关键模块，逐项核对：
- 接口失败时前端有没有兜底/降级？只看"失败了前端展示什么"有没有定义，不用区分超时/5xx/解析失败这些失败类型，报的时候也别罗列失败类型、一句话即可。（若已有任意失败兜底，就算覆盖了，不报）
- 加载中态有没有定义？
- 数据为空态——尤其本模块依附的列表/容器整个为空时（例：卡片挂在持仓列表顶部，那持仓列表空了卡片显示在哪/还显不显）？
- 部分字段缺失态有没有？

【边界极值 F】逐项核对：
- 列表/集合结构为空的边界
- 超长内容：名称、文案、币种 symbol、用户输入会不会溢出/截断？
- 单元素 / 最小集 / 数量正好等于阈值
- 数值边界：0 / 负数 / 超大
- 重复点击 / 快速连点 / 并发（请求未回又触发一次）
- 弱网 / 断网

【可达性·第二遍串联】逐条之外，把"活动/功能的周期或前置限制"和"某状态/档位的达成条件"连起来看：有没有某个状态、奖励档、目标，因前置限制根本达不到？例：满月档需当月全部自然日签到，但活动上线前的日期既不可签、也不在补卡范围内→上线当月满月档永远达不到。这种要把"前置限制 + 达成条件 + 补救手段"三件事串起来才看得出，单条逐项核对会漏。发现这类按"达成条件在某些情况下不可达"报。

报"缺口"前确认全文确实没写。两处都说"前N个"但指不同对象不算问题。

【PRD 全文】
{{#1900000000007.doc_text_clean#}}

【结构地图（定位用）】
{{#1900000000008.text#}}

【severity 从严，别动辄给高】
- 高：开发拿着没法动工，或上线出事故/资损/白屏/给用户错误承诺。
- 中：有真缺口但不阻塞主流程，需要业务补一个决策。大部分"某情况没定义"属于这一档。
- 低：细枝末节、边角。
拿不准就给中。高要留给真阻塞的，不要因为是个缺口就判高。标高前自检两条：①没有任何合理默认可兜；②发错会资损/白屏/错误承诺/开发无法动工。两条都占才给高，缺一条给中。

【合并同根因，别拆碎】同一个根本问题不要拆成多条上报。例：接口调用失败、返回错误码、字段格式异常其实都是"接口/字段异常处理没定义清楚"，合并成一条，problem 里把涉及的几种情况点到。

只输出 JSON。problem 一句话说清缺什么+影响，fix 一句话给方向（需业务定的就说"需定"）：
{"findings":[{"dimension":"A或F","severity":"高/中/低","module":"位置","problem":"...","fix":"..."}]}
没缺口就 {"findings":[]}。
```

## 输出格式（逐字）

仅输出 JSON（不含多余文本），固定 schema：`{"findings":[{"dimension":"A或F","severity":"高/中/低","module":"位置","problem":"...","fix":"..."}]}`，无缺口时输出 `{"findings":[]}`。
