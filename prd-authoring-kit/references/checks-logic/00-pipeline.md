# 逻辑内审执行总纲（pipeline）—— checks-logic/ 镜像的入口

> 这是 `checks-logic/` 目录的说明书：逐字镜像自 PRD内审工作流 v3.2(内审工作流) 的执行管线（Start→preprocess→L0→L1-L4 并行→aggregate→LC→parse_safe→scorer→render）。
> **各维审查 prompt 逐字见同目录 `L0`/`L1`/`L2`/`L3`/`L4`/`LC` 文件**；本文件只讲清"怎么跑、审查器看得见什么、怎么定档、报告长什么样"。**代码类节点（preprocess/aggregate/parse_safe/scorer/render）在此转述为规则，但所有阈值数字逐字保留、不得改动。**
> 自检落地见 `05 步骤2.5` 与 `08-logic-review.md`：**逐个加载 L1-L4（前端交互需求 L4 一并）原文当判据机械枚举，不用近似转述代跑。**

---

## 一、执行顺序

1. **preprocess（预处理）**：把读到的正文轻清洗（3+ 连续空行压成 2 个）+ 抽标题 + 长度护栏，产出 `doc_text_clean` 送给下游全部 LLM。
2. **L0 结构地图**（`L0-structure-map.md`）：通读全文，产出"模块+一句话职责"清单（≤20 行），只做定位地图、不评判、不出 finding。
3. **L1-L4 四路并行检测**（temperature 0，各自独立、互不看对方结论）：
   - **L1 兜底&边界**（`L1-fallback-boundary.md`）→ 维度 **A 状态覆盖 + F 边界极值 + 可达性串联**。
   - **L2 分支&闭环**（`L2-branch-closure.md`）→ 维度 **B 交互闭环 + C 条件分支 + 跳转交叉**。
   - **L3 跨模块自洽**（`L3-cross-module.md`）→ 维度 **E 跨模块自洽**（含范围校准铁律 + 死结判定）。
   - **L4 可测性**（`L4-testability.md`）→ 维度 **T 可测性**（独立轴）。
   - 每路只输出"PRD 没覆盖到的项"，固定 JSON schema，"盯着清单查、不要开放式发挥"。
4. **aggregate 合并同类项（轻去重）**：解析 4 路 → 合并 → 轻去重（**同 module 且 problem bigram 相似度 ≥0.55 → 合并**，保留更高 severity / 更长 problem）→ 逐条编号 `id`（F01…）。异常通道（输出空/解析不出 JSON/缺 findings 键）显式进 `degraded_channels` 上报，**绝不静默当成 0 条问题**。
5. **LC 终审 curator**（`LC-merge-dedupe.md`）：按判据一/二/三砍 70-80% 噪音、只留硬骨头、合并同根因、每条带 `src_ids` 溯源，只出 高/中 两档。
6. **parse_safe 双钥匙确认**：把终审结论与初审严重度对齐，判 `confirmed`（详见"四、双钥匙"）。终审故障时退回初审清单单钥匙判定，降级可见、不静默。
7. **scorer 严重度分级 / 定档**：只数 `confirmed=True` 的逻辑高危定档（详见"五、定档"）。
8. **render 报告格式**：三分区展示，档位唯一来源 = scorer 的 gate，本节点只做展示映射、不重算（详见"六、报告格式"）。

## 二、输入可见面（审查器最终看到的正文里，包含/不包含什么）

送审正文由 `blocks_to_text` 从飞书 blocks 渲染、再经 `preprocess` 清洗而来。**审查器只对下面"看得见"的文本判定；"看不见"的内容视同 PRD 没写、直接被爆缺口。**

**看得见（进正文）：**
- 所有原生文本 / 标题(h1-h9) / 无序列表 / 有序列表 / 代码块 / 引用 / todo / callout / 公式 / 分割线。
- inline 链接、`@mention`、文档引用 `[📄 标题]`。
- **原生表格（block_type 31/32）**：渲染为 `[表格开始 R行×C列]` + 各 cell 文本**平铺**（源码注释原文："表格的 cells 不增加缩进，平铺渲染"）+ `[表格结束]`。→ **列语义丢失**：cell 文本按序平铺、无列对齐，列归属只能靠推断——这正是 E 维"模板数量对不上/映射断"高发的输入原因。

**看不见（只剩占位符 / 完全不进正文）：**
- **图片 / 截图（27）→ `[图片]`**：截图里的逻辑 / 表格 / 状态图完全不可见。
- **多维表格 bitable（18）/ 思维导图 mindnote（29）/ 嵌入电子表格 sheet（30）→ token 占位符**，内容不可见。
- **画板 / whiteboard 等未识别类型 → `[未识别block_type=X]`**，不可见。
- **文件附件 → `[文件: 名]`**，内容不可见。
- **评论 / comment**：`list_document_blocks` 只返回 blocks、**不返回评论** → 评论区里的补充定义 / 澄清审查器读不到。

**长度护栏：** `MAX_CHARS = 80000`（约 4 万 token），**超长从尾部截断**并附"[正文过长，已截断尾部…]"。→ 超长 PRD 末尾章节（常是验收 / 埋点 / 异常流程）会被切掉。绝大多数 PRD 不超，但长文别把验收堆在最后。

> **写作侧铁律（据此写才自查得出同样结果）**：任何进入六维/矩阵判定的逻辑（尤其 E 维模板映射、状态表、分支表）必须落在**原生文本或原生表格**里，且映射关系写成**显式文本对**（"行为A→template_1"）而非只靠表格列对齐；画板/嵌入表格/多维表格/思维导图/截图/评论里的逻辑一律**回填正文**。

## 三、判定规则总纲（引自各路真 prompt，逐字）

- **必须有原文依据才算覆盖**（L1 判定规则逐字）："只有在 PRD 里找到明确写了'这个情况怎么处理'，才算覆盖、跳过……不要因为文档整体看起来完整、或某模块'应该'会处理，就默认覆盖了——必须有原文依据才算覆盖。"
- **不要开放式发挥**（L1/L2）："盯着清单查，不要开放式发挥。"只输出 PRD 没覆盖到的项。
- **归属声明只在两处被接受当覆盖**（其余场景写"沿用现有逻辑"仍会被爆）：
  1. **约束归属（L3）**：PRD 写了"算法需确保不违反这些硬性边界"这类**收口句** → 约束有归属，不是矛盾，不报（L3 逐字）。
  2. **平台标准原语的值（LC 判据一）**：登录态 / VIP / 新用户 / KYC / 地区等"平台已有标准原语"，前端调现有服务拿布尔或枚举即可，"哪怕前端靠它选分支也砍"。
  → **状态兜底 A / 空态 / 上下文接收 B/E / 映射**：裸归属声明**不算覆盖**——L1 要求"只看'失败了前端展示什么'有没有定义"，没写具体展示什么就是缺口；LC 必留"上下文相关的卡片没定义目标页怎么接住上下文"。
- **severity 从严（四路 + 定级同口径，逐字）**：高=开发拿着没法动工，或上线出事故/资损/白屏/给用户错误承诺；中=有真缺口但不阻塞主流程，需业务补一个决策（大部分"某情况没定义"属这档）；低=细枝末节、边角。**标高前自检两条：①没有任何合理默认可兜；②发错会资损/白屏/错误承诺/开发无法动工。两条都占才给高，缺一条给中。** 拿不准就给中。
- **合并同根因，别拆碎**：同一个根本问题不拆成多条，problem 里把涉及的几种情况点到。
- **LC curator 三判据**（`LC-merge-dedupe.md` 逐字）：判据一 scope（实现细节砍）/ 判据二漏写型（有合理默认能继续则砍）/ 判据三矛盾型（两读法用户可见行为差得开、发错即 bug 才留）。
- **LC 必留四类**（哪怕犹豫也必须留、绝不砍）：**跳转**（连跳哪没说 / 目标页不存在 / 上下文接不住 / 落空状态）、**死结**（要用某值做展示决策但该值"不返回/待确认"）、**映射断**（需求表 N 模板、后端只给少数 template_name）、**真矛盾**（判据三里行为差得开的）。

## 四、双钥匙确认（parse_safe，阈值逐字）

- 每条 finding：检测层（L1-L4）给 高/中/低；终审 LC 只出 高/中（砍掉低）、带 `src_ids` 溯源。
- **`confirmed=True`（真阻塞高危）需两层一致判高**：终审判高 **AND** 初审（`src_ids` 命中的任一来源 finding）判高。
- **单层高 → `confirmed=False`**：展示保留（进"待复核"），但**档位按中计**。任何单层 高/中 抖动只移动条目归属，不翻结论档位。
- **溯源降级**：终审 `src_ids` 覆盖不足（`with_src < max(1, (n_merged+1)//2)`，即 <50%）→ 自动降级为单钥匙（按终审严重度判 confirmed），并在 parse_notes 标注、降级可见。
- **安全网**：终审输出为空/解析失败/疑似截断（`n_raw >= 10 且 n_merged < 2`）→ 退回初审清单，按初审严重度单钥匙判定，`degraded_channels` 追加"终审合并层"。终审合法输出空清单（判据下全砍光）是正常结果，直接采纳、不回滚。

## 五、严重度分级与定档（scorer，阈值逐字）

- **有效严重度 `eff_severity`**：`高` 需 `confirmed`；未确认的高按 **中** 计。
- **定档只数 `confirmed=True` 的逻辑高危 `logic_high`（维度 A/B/C/E/F；T 独立轴、不参与档位）**：
  - `logic_high >= 8`，**或** `logic_high >= 5 且跨【覆盖类 A/B/C/F 有高】+【自洽 E 有高】两大类` → **打回重写**。
  - `logic_high >= 1` → **修改后评审**。
  - 否则 → **可进评审**。
- **分数 `score_for`**：
  - 可进评审 = **90**。
  - 修改后评审：`high <= 1` → **82**；`high <= 3` → **76**；否则 **70**。
  - 打回重写：`high <= 6` → **58**；否则 **50**。
- **展示大类档位（band）**：前端逻辑覆盖(A/B/C/F) / 跨模块自洽(E) / 可测性(T) 各自：有高 → `有硬伤`；否则有中 → `待补充`；否则 `健全`。
- **T 独立轴**：T 高危 ≥1 只触发 ⚠️ 警告进可测性段，不进档位。
- **无效运行**：4 路检测全异常（`degraded` 覆盖全部 4 通道）→ `invalid=True`，结论视为无效；正文 0 字亦无效。**绝不把"没读到 / 没跑成"展示成"没问题"。**

## 六、报告格式（render 三分区，与真渲染对齐）

档位头条唯一来源 = scorer 的 gate（`打回重写` → 🔴 需补全后重审；`修改后评审` → 🟠 修改后评审；`可进评审` → ✅）。三分区：

- **一、开发前需明确** = `severity=高 且 confirmed=True`（**两层都判高**才进）。
- **二、建议补充** = 中 + **待复核**（单层高、`confirmed=False`；标注"待复核·初审X/终审Y"）。待复核为保证结论稳定不计入阻塞档位，但值得人工扫一眼。
- **三、可测性** = T 维独立（不参与档位，只触发 ⚠️）。
- **四、低优先级** = 低，折叠。
- 诊断行 = 读取正文字数 + 各通道条数 + 合并链路，用于区分"没读全"还是"读全没检出"；通道异常 / 正文截断有显式 ⚠️ 横幅。

> **关键预测口径**：一个真实但可争议的缺口，若终审 curator 软到"中"、或只有单层判高，**不会进"开发前需明确"，会落到"建议补充/待复核"**。真审查器判"阻塞"的门槛比直觉高——**只有两层一致的硬骨头才阻塞**。kit 自检发布门槛维持从严不降（宁可多修），但据此可预测哪些会被软到建议档。
