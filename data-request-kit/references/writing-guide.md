# 四段怎么写（标题 / 背景 / 目标 / 描述）

## 数分拿到单子第一眼找什么

对象 → 口径 → 周期与拆分 → 指标 → 用途。缺一样就会来问一轮。需求池里不少单子三段全贴同一个文档链接也能过审，但数分得点开文档再找这五样；把五样写在单子里、文档作附链接，对双方都省事。

## 标题

对象 + 动作 + 范围，一眼能在需求池列表里认出来，30 字以内。
- 好：「首页Featured榜单「AI策略」tab表现数据回收」「首页二屏Smart Picks曝光点击表现数据回收」「行情页AI精选榜单AB数据回收」
- 差：「数据需求」「帮忙拉个数」「AI相关数据」「XX 需求（补）」
- 用产品内叫法并保留英文原名（Featured / Smart Picks / feed_reco / top_strategies）——数分对埋点时靠这个，翻译成中文反而对不上。

## 背景（为什么现在要）

三句话：谁在什么场景需要（写角色即可：设计侧 / 运营 / 老板汇报）；触发事件（新功能上线两周 / 评估首页排布 / Q 末汇报）；已经确认的事实（"与数分确认 X 不在 AI 归因口径内"）。
只写已确认的。推断（"所以应该改底表"）不进背景，进确认轮。

## 目标（拿去做什么决定）

表单自己的提示语：「需要体现需求的目标，定义数据产出的意义以及需要数分提供的策略建议方案及后续可能的业务落地动作」。
句式：`拿到 ___，明确 ___；用于判断 ___，支撑 ___`。
- 好：「拿到 AI 策略榜单 tab 从曝光到创建策略再到交易转化的全链路数据，明确入口效率与单策略差异；用于判断该 tab 是否值得保留/前置/扩大曝光，支撑首页榜单区排布调整」
- 差：「看看效果」「了解一下」「回收数据」——数分不知道该算到哪一层，也不知道给到什么粒度才够。

## 描述（数分可以直接开工的清单）

```
统计周期：近30天（按日拆分），分iOS/Android
统计对象：<页面 → 模块 → tab，带英文原名>
1. <漏斗第一层：曝光人数/次数、点击人数、点击率>
2. <模块内粒度：拆到卡片 / 单策略 / 单入口>
3. <转化层：创建/下单、EFTT 转化率、归因交易额、归因交易人数>
4. <用户结构：新老 / 分端 / 分国家 —— 只写真的会用的>
备注：埋点若缺失或口径不全请先同步；关联单 rec…；已有产出链接
```

- 指标按漏斗从上到下排，数分一次写完 SQL。
- 明确排除的东西也写出来（"不含归因交易额"），省一轮追问。
- 有关联单（对比的另一半、上游底表变更）写 record_id，数分能串起来。
- 不确定埋点在不在：写"若缺失请先同步，我们补埋点"，别替数分下结论。

## 各类型的模式

| 类型 | 描述里多写什么 | 常见交付形态 / 目标分类 |
|---|---|---|
| 取数 | 上面的模板即可 | 表格 / 短期分析 |
| 分析 | 末尾加 1–3 个"要回答的问题"；目标里写清决策 | 报告（含落地建议）或表格 / 短期分析或探索性分析 |
| 看板 | 监测频率、要覆盖的维度切片、谁看、上线时间 | 看板 / 定期监控 |
| 数分表变更 | 哪张表或口径 → 改成什么 → 为什么（哪个功能上线未纳入）→ 下游谁用；附数分的原话或确认 | 表格 / 长期专项 |
| 补单 | 背景写"数据已由 X 于 M/D 产出，本单为补提"；描述附产出链接；类型按实际做了的事 | 与实际一致；预期交付时间贴近今天 |

目标分类 / 交付形态的映射只是常见组合，不是规则——最终以用户选的为准。

## 正例（需求池实录，2026-08-27）

**取数 · 新单**
- 标题：首页Featured榜单「AI策略」tab表现数据回收
- 背景：APP首页Featured榜单区新增了「AI Strategy」子tab（与Spot / Futures / Top Traders并列），榜单卡片展示策略的7D胜率、7D ROI，并带「Create Now」创建入口。UIUX侧在评估首页榜单区模块排布时需要该tab的实际表现数据，目前产品和设计侧都没有现成数据。
- 目标：拿到AI策略榜单tab从曝光到创建策略再到交易转化的全链路数据，明确该入口的真实使用效率以及单个策略之间的表现差异；用于判断AI策略tab在首页榜单区是否值得保留/前置/扩大曝光，支撑首页榜单区的排布调整和后续AI策略入口优化。
- 描述：统计周期近30天按日、分端；对象写到 tab；1 曝光/点击/进入率 → 2 卡片 CTR 拆到单策略 → 3 Create Now 点击率、创建人数、创建率 → 4 EFTT、归因交易额/人数 → 5 新老用户；备注埋点缺失先同步。
- 为什么好：标题带原名；背景写清角色和"没有现成数据"这个触发；目标写决策；描述是漏斗清单，粒度（单策略）和排除项都明确。

**取数 · 补单**
- 标题：首页二屏Smart Picks曝光点击表现数据回收
- 背景：设计侧在评估APP首页模块排布时需要Smart Picks的表现数据。与Flash确认后，Smart Picks无法纳入AI归因交易额口径，因此本次只看曝光/点击侧表现；数据Flash已在8/27 AI周会文档中产出，本单为补提。
- 描述：动态卡片（曝光/点击/点击率 + 按点击内容下钻）、策略卡片拆 feed_reco / top_strategies；归因说明写明"本单不含归因交易额"；附周会文档链接。
- 为什么好：把"纳入不了"当事实写、把后果写成排除项，没有顺手推出"要改底表"；补单三要素（谁产出、何时、链接）齐全。

## 反例

- 三段复制同一句话，或三段都是同一个链接。
- 「看看效果」「拉一下数据」「AI 相关」。
- 对比需求只写 A 不写 B；或 A、B 数据可得性不同却按同口径要。
- 把"应该"当事实写进背景（"Smart Picks 需要纳入归因" ← 实际是纳入不了）。
- 预期交付时间按"一周"惯性填，无视这是补单。
- 描述里写实现细节（"聚合字段 xxx"）而不是业务口径——那是数分的事。

## 语气

短句、编号、中文为主；字段值里不要放 markdown 标题和表格（Base 文本字段只认换行和简单 markdown）；给数分的话直接说。
