# 从材料里把需求抽出来

## 来源 → 命令

| 来源 | 怎么拿 |
|---|---|
| 和某人的单聊 | `python3 scripts/dr.py chat <姓名> --since YYYY-MM-DD`（重名会列候选，改用 ou_ / oc_） |
| 群聊 | `lark-cli im +chat-search --query <群名> --as user` 拿 oc_，再 `dr.py chat oc_…` |
| 聊天里的截图 | 脚本会在图片消息下打印下载命令；下载后用 Read 看图。截图常常就是"对象"本身：页面、tab 名、卡片、指标名都在图里，先看图再读文字 |
| 飞书文档 / 周会纪要 / wiki | `lark-cli docs +fetch --doc <url> --doc-format markdown --as user`；大文档先 `--scope outline`，再 `--keyword 关键词` 定位 |
| 需求池先例 | `python3 scripts/dr.py precedent [--keyword X] [--full]` |
| 姓名 → open_id / 单聊 id | `python3 scripts/dr.py user <姓名>` |
| 当前用户（默认发起人） | `python3 scripts/dr.py whoami` |

跨会话搜消息（`im +messages-search`）和搜文档（`drive +search`）通常没有 scope，不要为此发起授权——定向拉单聊、让用户给链接就够。表单网页要登录，浏览器（含真 Chrome）不是选项，也不要让用户去登。

小坑：`+messages-resources-download --output` 指到子目录会报 internal 错，先下到当前目录再 mv；需求池记录的分享链接（`…/record/xxx`）`drive +inspect` 不认，用截图里的标题或 `+record-list --filter-json '需求标题 == …'` 定位；wiki 节点若是电子表格，`docs +fetch` 会报 Unsupported document type 'sheet'，改走 `wiki +node-get` 拿 obj_token → `sheets +csv-get`。

用户给了时间范围（"最近三天"）时：结论只对范围内负责；但把范围前后几天也拉出来，只用来解释指代（"那个单子"指哪张），不用来生成新需求。

## 读聊天的方法

1. **先找触发句**：「你有这个数据吗」「我要提一下」「给我提个单子」「补个单子」「跟 X 一起对比一下」。触发句前后 10 条通常就是全部上下文。
2. **认角色**：需求方（要数据的人，说"表现""效果""对比"）、数分（说"底表""口径""纳入""归因"）、用户本人。需求方的原话决定对象和指标；数分的原话决定可得性与类型。
3. **按时间线读**，注意同一时段可能并行两件事（和设计聊榜单、和数分聊归因），"这个"的指代跟着时间线走；分不清就问。
4. **短句、无标点、表情不是决定**：「这个纳入不了」可能是结论也可能是反问；「好」「OK」可能是"知道了"而不是"同意"。当线索用，进确认轮。
5. **抽七要素表**，每格标来源（谁、几点说的）：

| 要素 | 例 |
|---|---|
| 对象 | 首页 Featured 榜单 → AI Strategy tab（截图 17:21） |
| 指标 | "表现数据"（Gary 17:22）→ 层级待问 |
| 周期 / 拆分 | 未提 → 推断近 30 天按日分端，进确认轮 |
| 对比对象 | "跟智选一起对比"（Gary 17:22）→ 智选指哪个模块待问 |
| 明确排除 | "纳入不了"（用户 17:37）→ 含义待问 |
| 期限 | 未提 → 问 |
| 已有产出 | 周会文档里已有一段（Flash）→ 补单 |

6. **截图里的信息优先级高于文字**：文字说"这个榜单"，图里写的是 "AI Strategy"；用图里的原名。

## 时间语义

- 今天 = 系统日期；先算出今天星期几，再翻译相对日期。
- 「下周五」= 下一个自然周的周五，不是最近的周五（周四说"下周五"是 8 天后）；「周五前」= 本周五；「两周」= +14 天落到工作日。
- 草稿表、确认轮、汇报里把日期和星期都写出来，用户一眼能核。
- 补单：数据已交付，预期交付时间贴近今天（问一句"数据已经给了，交付时间填今天还是按原定？"）。

## 先例怎么用

- 发起人历史 → 业务线 / 对接人 / 优先级的**候选**默认值。它们是"这个人过去怎么填"，不是"这次该怎么填"；进确认轮，一句话确认即可。
- 同主题历史单：被取消 / 暂停 / 评审不通过的那条比已交付的更有信息量——大概率是口径没拉通或重复。这次要么先跟数分对口径，要么在描述里把上次没写清的写清，并在汇报里提醒用户。
- 别照抄别人的三段：需求池里很多单子三段是同一个链接，能过审不等于好写法。

## 什么时候停下来问（一轮问完）

对比对象不明；"表现"要到哪一层；数分说的"纳入 / 底表"这次成不成立；补单还是新单；相对日期；对接人；聊天里同时有两件事分不清。
问法：每题 2–4 个具体选项，第一个是你的推荐并说明理由；把已经能确定的先做成草稿表放在问题前面，用户看着表答。
