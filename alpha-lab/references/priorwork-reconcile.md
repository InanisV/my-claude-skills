# Prior-Work Reconciliation — 认知阶梯的第 5 级（向内/向旁求）

原阶梯（向外求 → 结构性 why → 完备性批判 → 对问题本身魔鬼代言）都是**向外**。第 5 级向**内/旁**：撞墙时（或宣布一堵墙**之前**），把目标和**用户自己的 prior work / sibling 仓**对账。答案、现实的 DD 线、或一条干净正交腿，可能早就在那里。

## 何时爬这一级

- 你要宣布"X 不可达"——先查：用户的旧仓/旧冠军是不是做到过类似的，怎么做到的？
- 你的组合 Sharpe 卡住——sibling 仓有没有你缺的**不同结构**的腿？
- headline 和别人的 prior 数字对不上——差距在哪（杠杆？DD 预算？成本？腿质量？）？

## 三件事对账

1. **目标本身**：可行性文档里，这个目标是不是**已经被分析并主动放弃**过？
   > 本 session：1000%@DD40 竟是用户自己 alpha 仓 `docs/03_realism_analysis.md` 里**已判定"Calmar 25 需 Sharpe 15-20、无公开先例、过分激进"并改成 DD55** 的那个角。整个僵局是在追一个自己团队早否决的角。

2. **机理差距**：为什么旧仓做到 805% 而当前只 207%？逐项拆：
   > 杠杆（旧仓 lev3-4 vs 当前未杠杆）+ DD 预算（旧仓接受 p95 44-50% vs 当前卡 40 硬线）+ 成本模型（旧仓扁平 vs 当前按换手）+ 腿质量（旧仓有高 Sharpe 方向性腿）。**结论：1000% 可达但落 DD~50-55，不是 40。**

3. **移植 + 审泄漏**：把 sibling 仓的腿当收益流拉进来测正交性和贡献——**顺便用 `leakage-audit-mlrl.md` 审它们**。
   > 本 session 就这样抓到 PPO 腿泄漏（真-OOS 1.75→0.07）。移植的腿还要查**部署断点**：它是不是依赖另一个仓的信号 live 可得？（见 `deployable-discipline.md`）

## 收敛才是诚实终点

多个**独立**视角（手工穷尽 + 并行 workflow + 公式 + 新数据 + prior-work 对账）指向**同一堵墙** = earned convergence，是结论不是放弃。但对账常不只确认墙——它还给出**建设性**方向（本 session：正交『结构』洞察 + DD 线该放到 55 + 一条干净可移植的方向性腿）。
