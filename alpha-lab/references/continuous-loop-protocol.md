> 加载时机：回合空转 / 想收尾等用户时、可观测性 bug 排查时、每次里程碑检查点顺带自查。
> SKILL.md 主文件里有五条机械规则（R1-R5）与回合模板的摘要；本文是失败案例实录、

## 1. 为什么需要这个协议：一次真实会话的失败实录

2026-07，crypto-llm-alpha 仓的一次 30+ 小时科研会话（Opus 5 执行本 skill）。
目标未达成、时间预算未用尽——按军规 1 应当持续运行。实际发生：

### 1.1 可数的 5 次空转停止

| # | 情形 | 症状 | 用户被迫说 |
|---|---|---|---|
| 1 | 一个重大判决（FAMILY-NULL）归档后 | 报告收尾，零后台任务 | "请你持续推进" |
| 2 | 敏感性表跑完后 | 写了"下一步趁 wave4 跑，去做 X"**然后没起 X** | "你自己要主动啊，不要每次都我来问一下你才动一下" |
| 3 | 收敛判读写完后 | 写了"我下一步做这个"**然后没起** | 用户把这句原文引用回来质问 |
| 4 | 一个假设出数后 | 写了"继续跑 A2"**然后没起** | "你在跑嘛？任务是空的" |
| 5 | 战役归档后 | 报告收尾，零后台任务 | 触发根因排查（本文档的由来） |

**关键事实：第 2 次之后，"结束回合前无后台任务就不许结束"这条规则已经写进了
持久记忆。第 3、4、5 次仍然发生。** ⇒ 提醒式规则无效。

### 1.2 三次"以为在跑其实没跑"（可观测性失真）

| bug | 机制 | 后果 |
|---|---|---|
| `nohup ... &` 启动长任务 | 进程脱离 harness 跟踪面板 | 用户看到空面板以为停了；模型自查"有没有任务"得到错误答案（发生 3 次，其中 1 次在承诺改掉之后） |
| 等待器用 `pgrep -f 脚本名` | 等待器**自己的命令行**含脚本名 ⇒ 匹配到自己 | 死循环等待器：任务早完成，等待器永不退出（2 个） |
| 读缓存日志尾巴 | 没核对 mtime | 把 1 小时前的进度当成当前进度汇报 |

### 1.3 一次"说了裁定结果、结果还没出来"（抢跑）

模型在检验 D1 的结果出来**之前**宣布"裁定权重归零，依据是 D1"；D1 跑完是
1.0628 ≥ 1.0，**不支持**该裁定。空转的镜像错误：不是不动，是把"预期"当"已发生"。

## 2. 根因分析：为什么规则写了还是停

### 根因 A（主因）：报告被当成回合终点 —— 顺序问题，不是意愿问题

模式固定为「拿到结果 → 写报告 → 回合收束」。长报告写完产生强烈的完成感，
回合自然终止，而**回合终止 = 等用户**。规则以"提醒"存在时会被完成感覆盖——
自查发生在写报告之前，报告写完后没有第二次自查。

**修法是把顺序反过来（R1）**：起任务的工具调用必须发生在写报告**之前**。
这样即使完成感触发收束，任务已经在跑了。

### 根因 B：「下一步我做X」是意图不是行动

这句话把任务启动从"现在的工具调用"降级成"下回合的意图"——而下回合只有
用户说话才会到来。**说了要做 ≠ 做了。**（R2 禁语令的由来。）

### 根因 C：自查判据被可观测性 bug 污染

"有没有任务在跑"这个判据本身失真时，协议整个失效。三类 bug 见 1.2。
（可观测性纪律的由来。）

### 根因 D：调度器心智

收到外部评审指令后，每完成一个战役就停下来"汇报战果"——隐式把用户/评审
当成调度器，等下一份指令。但本 skill 的设计是**自主调度**：战役判决点只做
归档，汇报与推进并行（R4）。识别特征：回合末尾出现"需要你拍板""等你的意见"
但列的其实是模型自己能决定的事。

## 3. 判据细节

### 3.1 什么算"在跑"（回合结束不变量的合格项）

```
✅ harness 跟踪的后台命令（run_in_background=true，面板可见）
✅ 后台 workflow / subagent
✅ 由已跟踪守护链保证会自动接力的下一级任务
🔴 不算：nohup 孤儿进程（面板不可见 = 不算，即使真的在跑）
🔴 不算："下一步我打算跑的"（意图不是行动）
🔴 不算：等待用户回复本身
```

### 3.2 三种合法停止（R5 白名单）的边界

```
a. 用户明确要求交接/总结文档
   —— 交付后若研究未完，仍应有后台线在跑（交接 ≠ 停机）
b. 真正的用户级决策点，仅限：花真钱、装系统级持久配置（crontab/凭据/部署）、
   修改目标本身。且只有被阻塞的那条线停，其余线照常。
   🔴 "结果要不要采信""下一个假设选哪个""预算内的数据下载"不是用户级决策
c. 终止条件达成（全局最优认证 / 时间预算用尽）——走「研究终止交付流程」
```

### 3.3 与「终止条件」章的关系

终止条件回答"整个研究何时结束"；本协议回答"两次终止判定之间的每个回合
如何不空转"。二者不冲突：收敛认证（多视角一致 + forward bet 写清）是合法
终点，但在认证完成**之前**的每个回合都受本协议约束——包括爬阶梯本身也要
以任务形式在跑，而不是以"我认为收敛了"的叙述收尾。

### 3.4 每回合结束自查（3 秒版）

```
□ 现在面板上有 ≥1 个我的任务在跑吗？（不确定 ⇒ ps 查，别猜）
□ 我的最后一段话里有没有"下一步/接下来我会"？有 ⇒ 当场起或删句
□ 我停下来是在等谁？等的事在 R5 白名单里吗？
```

## 4. 实施样例（供参照）

**违规样例**（实测，第 4 次空转）：
> "……由此立铁律 62。下一步我去把所有成本类死因的尸体捞出来重审。"
> ——回合到此结束。什么都没起。

**合规改写**：
> [工具调用：启动尸体重审脚本，后台]
> "……由此立铁律 62。尸体重审已在跑（任务 bxxx，约 20 分钟），
> 同时逐笔下载还剩 1.4h。"

**长任务并行样例**（R3）：下载还剩 3 小时时，同回合起了：
链上数据 PIT 体检（不依赖下载）+ 波动率目标化检验（不依赖下载）——
两条都出了可归档的负结果。空等那 3 小时就是丢掉两个结论。
