# MEXC 产品方案图 Skill

## 核心理念：图是讲故事的工具，不是排版练习

一张好的方案图 = **用最少的视觉元素，让老板扫一眼就知道我们要做什么、为什么这么做**。
老板看图的心理是"你们有没有想过"，不是"你们做了几个功能"。

布局是手段。每一个元素存在的理由只有一个：**回答老板脑子里的下一个问题**。

---

## Step 0：先定成品形态（决定后面所有取舍）

三种形态，先选一个。选错形态，后面怎么打磨都救不回来。

| 形态 | 什么时候用 | 尺寸 | 信号 |
|------|-----------|------|------|
| **方案页（默认）** | 给 E 哥 / 老板们看的产品方案，手里有原型帧（Claude Design、Figma 截图） | 1920×1080 单屏，2 倍 PNG | "老板扫一眼要知道要做什么、为什么"、"不要长条形的"、"一个页面讲清楚" |
| 自读型长图 | 发群里/文档里被独立阅读的框架图、架构图、复盘图，没有原型可放 | 820 宽竖版，4-6 个 section | 内容以概念、结构、数据为主 |
| 伴讲型长图 | 会上有人拿着口播的背景板 | 820 宽竖版，≤3 个区块 | "不要整那么复杂，几句话讲完那种" |
| 数据与行动项页 | 发群同步数据，顺带把问题和解法一起讲 | 1920×1080 | "同步一下数据"、"数据图"、"行动项也要放上去" |
| 双线规划页 | 产品、运营两条线的长期规划，发群给老板看 | 1920×1080 | "长期规划"、"双线"、"规划图"、"内容是主线" |

**方案页的判据**：受众是老板 + 讲的是产品 + 有界面可以放 → 方案页。

**数据图和规划图常常同一天连发**：先发数据图（现状 + 三个问题怎么解），一分钟内跟规划图（长期两条线）。
近期行动项只放数据图，规划图只讲长期，堆在一张上会被判"过于杂乱"。两张图共用一套视觉语法，骨架见 `references/data-and-plan-pages.md`。

方案页内部再分三种，骨架不同，别混用（详见 Step 2 末尾"三种方案页"）：
- 单方案页：讲一个方案怎么走，入口 → 页面 → 交易一条线
- 决策页：两个方案让老板或群里投票选，对称呈现
- 系统页：讲一套体系或路线图，用矩阵不用流水线
2026-09 广场 1.5 和 FOMO 两张图的教训：长图改了七版都不对，换成单屏方案页两版就过。
长图适合讲"体系"，老板看"产品"要的是一屏之内看到入口、页面、价值。

**受众已知的东西不配拥有区块**：内行的本行常识、内部人尽皆知的口径，删除或降成一行小字。
老板熟悉项目背景时，不要背景页，最多右上角三个胶囊带过（现状 › 用户 › 所以）。

## Step 1：先理故事线，再想布局

### 一根主线

拿到内容先写出一句话：这张图要老板记住的唯一一句。写不出来就还没想清楚。
- 广场 1.5 定稿：每个合约标的一个圈子，两个入口进来，看懂、下单
- 学 FOMO 定稿：让真实交易变成内容，交易动态卡

五个功能并列没有主线，老板的结论是"堆功能"。多个功能必须挂在一根主线下面，
按用户路径（进来 → 看到什么 → 做什么 → 回哪里）或生命周期（开仓 → 平仓 → 累积）串起来。

### 1-3-9 叙事结构（长图用）

```
1 — 一句话：这个方案是什么、解决什么问题
├── 3 — 三个支撑论点（为什么可行 / 为什么现在做 / 凭什么我们做）
│   ├── 9 — 每个论点下 2-3 个具体论据（数据、机制、案例）
```

老板看图的心理路径：这是什么 → 跟我有什么关系 → 具体怎么做 → 做了会怎样 → 风险成本 → 那就做吧。
不是每张图都覆盖全部，按场景裁剪。

### 实事求是原则

- 有数据就用数据，没数据标"预估 / 待验证"，不编 KPI
- 承认不确定性是加分项："AB 测试两周后用数据定"比"方案 A 一定更好"可信
- 老板认识的数字才放（问卷 65%）；装饰性的数字（竞品 50 万用户、融资轮次）老板一句"没必要"就删

## Step 2：方案页的固定骨架（照着填）

完整 CSS、坐标计算、SVG 箭头、量框脚本见 `references/proposal-page.md`。
两个通过验收的成品见 `examples/`，新图从它们改。

```
┌ 顶部 ────────────────────────────────────────────── 右上角 ┐
│ 标签 · 一句话标题（结论，可带一个金色关键词）     现状 › 用户 › 所以 │
│ 副标题一行：形态 · 参考谁 · 覆盖范围                          │
├──────────────────────────────────────────────────────────┤
│ [原型帧 A]  ──黄箭头──▶  [原型帧 B 核心页]  ◀──黄箭头──  [原型帧 C] │
│  入口一                    绿框 = 交易/回流       入口二（推荐）   │
│  框①                        框②③④                 框⑤          │
│ ① 黄字价值                ② 黄字价值            ⑤ 黄字价值      │
│   灰字一句                ③ 黄字价值              ✓ 一句优势     │
│                           ④ 绿字价值（交易）                      │
├──────────────────────────────────────────────────────────┤
│ 左下一行：覆盖规则 / 底线            右下一行：原型说明、数据示例   │
└──────────────────────────────────────────────────────────┘
```

**规则：**
1. **三张整帧**，390:844 原比例，宽 320-340px，占满中间。不裁切、不套手机壳做局部放大，裁切会让老板误解页面结构（Yoki 原话）
2. **入口在两边，目的页在中间**，或按生命周期从左到右。老板要一眼看出"从哪进、点哪、到哪、怎么回去"
3. **聚光灯 + 编号 + 箭头**：要讲的元素不用粗框圈，用遮罩把帧里其余部分压暗四成，要讲的区域保持原亮度，边上只留 1.5px 细线（黄 = 内容，绿 = 交易/回流），角上圆形编号；跳转用 SVG 贝塞尔箭头从元素边缘连到目标页边缘，箭头上一个胶囊标签"点 X → Y"；交易回流用绿色虚线。3px 粗框的版本被老板视角判为"图上全是框"，已弃用
4. **框必须按量出来的坐标画**，不能估。估的框歪一个字，老板第一眼就看到（Tom 原话"圈得不准"）。量法见 reference
5. **每帧下面是价值清单**：编号 + 黄色 18px 大字价值（≤ 12 字，用户得到什么）+ 灰色 14px 一句（为什么/业务得到什么）。老板扫一眼看到的必须是价值，不是功能名
6. **只给一个推荐方案**，标"推荐"，旁边写它的优势。不摆三个方案让老板挑（Yoki 定的规矩：他不同意会自己说）
7. **文字总量**：标题一句、副标题一句、右上三个胶囊、每帧 2-3 条价值、左下一行。超过就删，先删说明再删价值，价值最后动。给老板的版本只留黄字价值，灰色小字全删（"老板不会去读这些字"）；四字概括比一句话强（"清晰简洁""找板块最方便"）
9. **结构性新增要标出来**：这一版比上一版多了什么结构（底部导航、搜索页），帧标签上打金色"新增"，副标题第一句点明，不然老板感知不到
10. **老板看的图，不写老板的动机**：行标签写"结果"不写"战功"，卡片写"每个热点都能回看"不写"都有战绩"；他要的是感受到有战功，不是看到这两个字
11. **参考截图只放老板认的那个**：老板点名要学的（FOMO）放真机图当佐证，"≈"接我们的帧；他不认识也不吃的（小红书）文字带过，不放图
8. **不出现的东西**：功能名不带价值、竞品用户数这类装饰数字、压在截图上的说明文字、投票之类临时被砍的模块

### 竞品学习页（"向 X 学什么"）

老板点名要学某个产品时（FOMO），这张页的主线不是"它有什么我们也有什么"，
而是"它证明了什么机制，我们凭什么做得更硬"。

- 竞品放**左侧一小列**，2 张真机截图，标"它这样做"，一条箭头写"学机制，不抄界面"指向我们的帧
- 我们的帧占主体，按生命周期排（开仓后 → 平仓后 → 累积成记录），每帧价值清单照常
- 明确不学的东西一行带过（分享卡、联盟这类），这是判断力的证据
- **不要做"FOMO 这样 / 我们这样"逐功能配对**：五列十图并排，老板的原话是"无脑照抄"
- 老板没点名的参考产品（同花顺、东方财富）只在副标题里文字带过，不放截图

### 三种方案页的骨架

**决策页（两个方案让人选，含群投票）**
- 一行放完：[参考截图] ≈ [方案 A 帧] → [共同的目的页，缩小] ← [方案 B 帧]，同一件事只画一次
- A 和 B 同样大小、同样边框，各配自己的参考和各自的优缺点，字数对齐；倾向用一个胶囊标（"我们倾向"/"备选"），描述本身不偏不倚，引导靠结构（参考放两边、已定的事摆在"已定"区）
- 优缺点两优两缺互为镜像：A 的优点就是 B 的缺点，反过来也一样。每条必须是形态本身带来的，**加个设计就能补掉的不算**（"没封面"加张卡就补上，不算 B 的缺点；"只能置顶一个"轮播能解决，不算 A 的缺点）
- 群投票版上面加一条"已定"区：把已经定了的页面缩小排一行，一句"这三页两个方案都一样，要投的只有 X"，吃瓜的人不读字也知道在投什么
- 图上不写"回复 A 或 B"这类投票机制，投票用组件发
- 老板在手机上看：单行版比两行版好，两张相近的图合成一张，"老板没心思看两张相近的图"

**CEO 版一图流（B 结构：现状 · 问题 · 解法 + 背后 + 价值）**
- 方案本身怎么立住见 exec-proposal；这里只管画法。定稿源文件 examples/ceo-onepager_B_广场热点方案.html
- 结构：小字引子接读者起点 → 标题（用户动机 + 事实 + 承诺）→ 三块并排（他要的在做 / 发现：大数 + 柱状图 + 红 0 + 三图标两轴 / 提议：三帧三步 + 时间线）→ 下半张系统 → 底部四句价值
- 下半张的画法：**故事线做主线，架构做脚注**。四个大步，每步一句情节（关键半句金色），脚下一行小字写"信号层 · 4 个模块"加灰色小标签带分期圆点；右上角"23 个模块 · 3 期"。被打回的画法：文字框分层（流水账）、圆形图标分层（"一圈一圈的"）、按用户诉求分列（像问卷）、用户诉求做架构表头（两套东西硬挤）
- 紧凑三条：画布装不下就压字号不压内容；正文最小 14px，标签 15 到 16，关键数字 23 到 84；四段之间只留一条分隔线
- 图标网格必须固定列数，空位留白；行内图标数量不齐就是"乱"的直接原因
- 方向不明时先出三张草稿级方向图（一句话一张图 / 三栏 / 产品发布页）让人选，选定后只在一张上打磨

**系统页 / 路线图页（讲一套体系，不是一个功能）**
- 骨架是矩阵不是流水线：列 = 阶段（热点前发现 / 热点中承接 / 热点后沉淀，或 leader 给的几期），行 = 系统 / AI / 用户 / 结果。同一套框架套在每个阶段上，体系化才看得见
- AI 单独一行，全金色，每格一个图标加两三个字；老板一眼看到 AI 在每一段都有活
- 用户行放界面帧，结果行放大字卡，顶上一条虚线箭头从最后一列绕回第一列写闭环
- 图标代替文字：每格 = 图标 + 两三个字 + 一行小字，不写句子
- **先分清"规划"和"功能怎么做"**：leader 给的是产品要变成什么的几个阶段，就按她的阶段做列，每列回答同一组问题（变成什么、内容从哪来、用户能干什么、转化在哪）；把现在这个功能的运转逻辑画得再体系化，也只是第一阶段的说明书，会被打回"这只是你现在整理数据的逻辑"
- 沉淀/复盘那一列要过风险关：回顾写给谁看、点名早发现的人算不算平台背书、用户跟着亏了谁负责。社区产品的沉淀不是量化复盘，也不能拿个人背书当信任

## Step 3：写字的纪律

### 标题

一句话，结论型，可带一个 `<em>` 金色关键词。好的标题老板能转述给别人：
"每个合约标的一个圈子：两个入口进来，看懂、下单"。
差的标题是描述："广场 1.5 方案"。

### 价值怎么写

每条价值回答"用户得到什么"，第二行回答"为什么/我们得到什么"：

| 差（功能名） | 好（价值） |
|------|------|
| AI 摘要 | 10 秒看懂在聊什么 / AI 读圈内帖子生成，留住只看不发的人 |
| 交易按钮 | 看完直接下单 / 一步回 K 线页开仓，内容到交易 |
| K 线页入口栏 | 看盘时就看到大家在聊什么 / 入口带摘要和人数，广场流量扩到 K 线页 |
| 交易动态卡 | 真实交易变成内容 / 开仓即自动生成标准卡，成交后状态更新 |

### 2026-10-27 之后加的六条（广场数据图、规划图各改了十几版得出的）

1. **副标题写场景，不写 slogan**。Yoki 原话："交易即内容，你的副标题就写几个场景产生内容：下单发，平仓发，高光时刻发，系统提示发。"标题可以有格局，标题下面那句必须落到场景。"种子用户、种子 KOL"也要写成具体来源："先请品牌、预测市场、SEO 现成的 KOL 发帖"。有了场景句，标签就不再挂。
2. **一句话能说清的，就不要整一堆描述**（Yoki 群里的规矩）。每格一句，说明句、证据句都删。
3. **只讲率**。绝对值小的数字不上图（Yoki："这个数字不好看是吧，那就只讲率，不过绝对值还是蛮小的"）。访问人数只写 +34%，点击只写百分比，图表上的人数刻度和标注一起去掉，柱子只看趋势。
4. **行动项是"问题 → 解法 → 进展"，功能名不是行动项**（Tom："这里你说的其实是功能，为了解决什么问题没讲清楚"）。卡住的项写真实原因，"后端仅 1 人，在做更高优需求"比"需要后端排期支持"有用，老板能看出需求已经就绪、卡在人力。
5. **没上线的功能名不出现**。"按话题集中发帖"会让老板以为话题已经有了，写成动作："运营指定热点，AI 账号集中发帖"。
6. **指标要配产品，不让参考指标当 KPI**。浏览型产品（广场）的点击率只作参考，图上标"参考"小标，不进标题，说明句写"广场以浏览为主，刷帖不一定点进详情"；真正要看的是发帖、讨论、停留时长。否则点击率掉一点老板就慌。

### 禁用

- 三字格、四字格并列口号（"能看、能聊、能买"可以当标题尾巴，不能当价值清单）
- 实现路径：H5 还是原生、排期分批、复用逻辑，老板不关心，问了再讲
- 长破折号、markdown 加粗、→ 当正文符号（箭头只在 SVG 里）
- 红线词：画饼、演示版、汇报版、回应老板、专门给你做的、v15 之类版本号（见 ego-messenger）

## Step 3.5：配色与高亮（2026-10-27 定，优先级高于 design-tokens 里的旧规则）

Yoki 在增长产品组群里的三条（她说大部分 AI 生图的毛病是花里胡哨、五颜六色）：
1. 尽量用低饱和度颜色
2. 颜色控制在 3 种以内，先给自己设限才可能控制住
3. 重点内容框出来，一张图要让读者一眼就被重点吸引

同一天在广场两张图上打磨出来的五条：
4. **老板图不用黄色当强调色**。Yoki 看到金色加 MEXC 蓝的第一反应是"黄色抹茶蓝嘛，看起来像币安"。强调色只用品牌蓝 #2B6AFF；需要第二种语义色时，用低饱和暗红（实底 #B84A57、线条 #E07582）只给"问题 / 卡点 / 需要支持"；绿色只给好消息，而且很少用。design-tokens 里"标题强调词用金色"的旧规则作废。
5. **高亮是实色块或描边框加白字，不是彩色字**。深底上蓝字亮度只有 0.30，白字 0.84，彩色的"高亮"反而比周围的字更暗，往后退（Tom："高亮效果不太明显"）。以前金色能用是因为它亮度 0.53 又是暖色。标题关键词放进实色块，重点卡加粗描边加淡色底，大数字白色加实色圆标。
6. **"花花绿绿"看的是上色的块数，不是色相数**。三种颜色也能花：十几个色块就花。数一遍，只给回答老板问题的那几处上色。数据图定稿只有：标题一个蓝块、好消息卡蓝框、参考指标卡灰框、卡点一处暗红。
7. **也不能全灰**。纯灰加一个强调色会"像有重要人物去世"（Tom 原话）。底色保留品牌蓝的暗调，大面积（图表柱子）降饱和，让实色高亮块成为全图最亮的蓝。
8. **一对图共用一套语法**。同一天连发的数据图和规划图，标题块、卡片框、编号圆标、流程胶囊、箭头用同一套样式；发前把两张叠在一起看一遍。

**高亮落在哪**：先列老板看这张图会问的问题，高亮只落在回答这些问题的元素上。广场数据图的清单：是不是放量带来的（指标卡说明句）、点击率为什么降（三个问题）、什么时候能好（上线日期蓝实底）、卡在哪（暗红）、除了点击率还看什么（指标胶囊）、下次什么时候看（右上角胶囊）。

## Step 4：原型帧怎么来

- **实物优先**：有 Claude Design / Figma 的帧就用帧，不手绘。手绘只在帧不存在时做，且要按同一套样式（黑底、44px 头像、深灰胶囊、蓝色悬浮钮）
- Claude Design 导出的 HTML 依赖 `support.js`，含 `<sc-for>` `<sc-if>` 模板，直接截图会出现 `{{ b.name }}` 和空白 K 线。先按 reference 里的方法把模板展开成静态 HTML 再截
- 一帧一截：用帧上方的标签文字定位 `following-sibling::div[1]`，`element.screenshot()`
- 帧里被砍掉的模块（投票条、看多比）要在静态 HTML 里删掉再截，不要用图片抠
- 量框：同一份静态 HTML 里用 Playwright 取元素 `bounding_box()`，换算成帧内百分比，框和箭头都用这组数
- 设计师的 Figma 导出图：一张大图里几帧并排，用暗色像素游程找每帧的 x 范围、竖向扫描找 y 范围再裁；帧边缘的蓝色连线点和评论光标（"yevi l"）按颜色阈值找到后抹黑；同一设计的帧尺寸一致，框的百分比可以复用
- 截图上量不到 DOM 的，叠一张 5% 网格线再读坐标，读完先渲染一次看框有没有压字

## Step 5：改稿循环

方案页几乎不可能一版过。2026-09 广场两张图各改了十轮以上，规律如下：

1. **每一条反馈先当成一个类**，扫全图同类全改，不是只改被点名那一处。改一处再犯一处比第一次犯更伤
2. **双清单**：反馈里"要加什么"和"明确不要什么"各列一张，交稿前逐条对。漏删比漏加更伤（今日看法被要求去掉，图里、列表里、价值清单里三处都要清）
3. **领导的会议纪要要看文字记录，不看 AI 总结**。总结会把"像空儿那个 demo，一边原型一边写价值"压成"图示展示规范"，把"不要长条形、单独整一页"压没。对不上号的指令，附近往往就是最容易执行错的指令
4. **站在老板视角自问五轮再交**：他扫一眼看到的第一个词是什么、他会不会觉得在堆功能、他能不能转述、他会问哪里、哪里像抄的
5. 用户的排版建议是建议不是指令。目标是老板满意，方向对了就按目标优化，别每收一条建议就推倒重来
6. **惯性陷阱**：反馈说"和我们讨论的不是一个事"时，要换骨架，不是把同一张图再打磨一遍。连续三版都在同一个结构上加东西（前中后、矩阵、闭环箭头），形式越来越精致，骨架没换，这就是 leader 说的"AI 进入惯性了"。判据：这一版的第一行标题换了吗？没换就先别动画布
7. **发群的图先回到这条消息的目的，不被老板最新一条消息带偏**。10/27 的 v3 把老板前一晚说的"话题"做成了标题"先做话题"，和公开说过的优先级（Web 端是开发重点，话题设计先行）直接冲突，Tom："你太注重老板的消息了，我们是有优先级的。"目的是让老板看到内容有长期规划，老板的新问题进正文，不进标题。
8. **一张图一个用途，连发时分工**。近期行动项放数据图，规划图只讲长期；规划图上堆了四项行动清单，Yoki 判"过于杂乱"，挪走之后两张都干净了。
9. **双线要同等分量**。运营的规划曾被画成产品三步下面的一行，Tom："这是一个职场问题，要双线。"运营有自己的阶段名、场景句、小图，和产品一行对一行。
10. **技术自检每版都跑**：`scripts/check_layout.py` 查溢出、图标居中、文字被裁。图标跑到圆圈左上角这个坑同一天踩了两次，都是一条 `.xx span{display:block}` 之类的宽规则把放图标的 span 也压成了 block，肉眼在缩略图上看不出来，量能量出来。
11. **每条优缺点都要自己再想一轮**：用户说的缺点里有站不住的（"离开推荐流"是筛选的本意），自己写的也有（"没封面没数据"加张卡就补上）。按"形态本身带来、设计绕不过去"这条标准逐条筛，别用户说什么改什么

## 议题页（跨团队工作坊 / 脑暴会，2026-11-03 加）

场景：主产品在公开场合（E 哥、Jackie 都在）出一个让别人讨论的议题，不是汇报方案。图的主角是三道题，不是我们的功能。来源：2026-11 产品创新工作坊广场议题，八版之后 Yoki 只改词没改结构。

骨架（1920×1080 单屏）：
- 标题：一句判断句，老板当期的词放蓝色实底块。例："从交易工具，到[交易者的聚集地]"，副标题"MEXC Social Trading 的下一步"。
- 左上（宽）：角色或竞争的变化。"过去"和"正在变成"两个方框加箭头，右框蓝描边，里面三个动词 chip（来看、来聊、来交易）。框下一行行业事实加判断句。
- 右上（窄）：自家产品的位置句做标题（"广场：Social Trading 的关键载体"），下面三个势能数（上线日期、两个增长率），再一行"已在推进：X、Y，现场不展开"。
- 中间：一条蓝色目标带，一句话加三个动词。
- 底部：三道题做三张大卡，题目 32px，题首可以加老板的词当标签（第一入口 / 传播链路 / 经营动机）。

规矩：
- 只放日期和增长率，绝对值一律不放，暗红问题色不用。老板看议题页读的是姿态，一个难看的数就把"出题人"读成"求助的人"。
- 已有规划只写名字，不写做法；不写"空白""缺口"这类词，空白用题目表达。
- 不出现"小组能带来什么"这种派活的块，分工写在题目的指向里。
- 三道题要同一条线（入口 → 链路 → 动机，或社交 → 关系 → 交易），每题对着自己规划的一层。

样例：examples/topic-page_工作坊议题_交易社区.html。
