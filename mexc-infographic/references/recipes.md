# 成品配方：三类图照着出，一次到位

这份文件记录的是「最后被接受的那一版长什么样」。首稿直接按成品出，不要从长版本往下砍。
每个配方给：读者动作、区块骨架、每格写法、字数预算、首稿最常被打回的点。组件 CSS 见 `templates.md`。

---

## 配方 A · 决策图（投票、候选对比、各方意见汇总）

读者动作：从几个候选里选一个，或对一个默认方案点头。
图的任务：把事实摆平，让读者三十秒看出分歧在哪、我们建议什么。

### 骨架（固定三段，顺序不变）

```
Hero      标题一句：把分歧本身写出来，「品牌选 A，内部选 B，用户选 C」
          副标题一句：时间约束 加 不变项 加「事实全部查证，明细另附」
01 各方意见   表格，一方一行：相关方 | 倾向（可带备选）| 原话要点
02 候选      一行一个候选：✓ 一个亮点 | ✗ 一个硬伤，建议项整行高亮
03 建议      三行排序：名字 加 一句理由；区块右上角写下一步（法务核、翻译开工）
Footer    一行来源：记录日期、样本条数、查证日期、「明细版另附」
```

### 每格怎么写

- 原话要点：用他的原话或最近的转述，两层意见两层都写，不加他没说的话，不替他补事实。
- 亮点和硬伤各一句，事实不评价。硬伤里的撞名要分级并写产品全名：`同品类同名：X`、`异品类同名：Y`、`站内同名：Z`。
- 支持信号（谁提名、谁推荐、几票）不是亮点，写进 01 的倾向格或原话格，不进 02。
- 用户样本要带口径：条数、来源方式、噪音，例如「有奖征集，看方向不看绝对值」。
- 建议理由一句话，只写决定性的那一条。备选也要给理由，不写「其余不推荐」。

### 字数预算

- 每格一句，25 字以内。
- 全图正文 300 字以内（表头、名字、数字不算）。
- 没有段落。解释、分歧分析、方法说明一律进明细版。

### 版本

同一批事实出三版，文件名带受众和日期，旧版保留：

| 版本 | 给谁 | 差别 |
|------|------|------|
| 主管版 | 要表态的主管 | 只有候选事实矩阵（行是维度，列是候选，每格一句），没有建议，没有支持信号 |
| 决策者版 | 最后拍板的人 | 本配方的三段 |
| 明细版 | 追问时的附件 | 依据、口径、每条事实的来源 |

受众里同时有主管和拍板人时，首稿直接出主管版和决策者版两张，不要等着被要。

### 首稿最常被打回的点

1. 听起来像事实的形容词没有出处：「阻力小」「风险高」「用户认知成熟」。写之前问自己是谁说的、哪条记录、怎么查的。
2. 把用户没给的流程当事实写进去：谁定中文名、投票怎么计分、截止日期。用户没说的写成占位或不写。
3. 自己的判断混进事实区。建议只在 03，其它地方没有「我认为」。
4. 优点列和缺点列条数不一样，读者会数条数。每个候选只给一亮点一硬伤。
5. 同一维度两把尺子：对 A 说同名是硬伤，对 B 说同名可接受。
6. 相关方的话被加工：多补一句、少写一层、把带表情的玩笑写成正式候选。
7. 标题过度概括：「三路输入都指向 A」在只有一路指向 A 的时候。
8. 建议跟着最新一条输入摆。新输入先放回全局，五个动作走完再改：列标准、逐个打分、核对每一方到底说了什么、算选错的代价、用最强反方压一遍。改一次可以，改三次没人信。
9. 图里写「请拍板」「关键决策项」。图给建议和默认路径，请拍板是消息里的事。
10. 外部参考（多模型评估等）没标「参考，不是投票」，或把缺列的截图算进了总分。

## 配方 B · 老板伴讲图（方案、原型、节奏）

读者动作：会上听讲，眼睛扫图，不读字。
图的任务：当讲话人的背景板，每块一眼一句。

### 骨架（≤3 块，没有底栏）

```
Hero      方案名 加 一句话，不超过 15 字
块 1      它长什么样：真机截图或原型截图，叠编号圆标 ①②③，图下同编号一行说明
块 2      怎么接 / 几种做法：三帧截图并排，建议的那帧加金框和「先上」标签
块 3      节奏：一行胶囊条，「1.0 已有 · 1.5 下一版 · 2.0 后续」
```

### 每块怎么写

- 图是主体，字是图注。每块正文不超过两行。
- 有截图就不手绘。用户给的截图优先，占位图只在实物不存在时用。
- 「接下来」用图不用字：三帧并排，标先后，胜过三段文字。
- 有几种做法时并列呈现，标一个建议，不写「请选择」。
- 老板提过的关注点（某个玩法、某个分 tab 的建议）必须在图上出现，哪怕只是一个标签。

### 首稿最常被打回的点

1. 字太多。老板说过一次「文字太多」就是长期约束，首稿就按图注密度出。
2. 两个题目挤在一张图。竞品研究和自家方案永远是两张图。
3. 用手绘示意代替现成截图。
4. 节奏写成段落，应该是一行胶囊。
5. 有底栏。伴讲型不要底栏，话由讲的人说。

## 配方 C · 借鉴图（向竞品或先例学什么）

读者动作：先看清别人做了什么，再看我们接哪一层。
图的任务：让被学的对象自己说话，我们的部分只标落位。

### 骨架

```
Hero      「向 X 学什么」加 一句它是什么，带一两个公开数据（用户数、融资）
块 1      它的机制：真机截图占版面主体，旁边三层结构或飞轮，每层一句
块 2      可借鉴点：每点一行，标落位标签「已有 / 下一版 / 后续」
块 3      我们的承接：三步，每步注明对应它的哪一层，用截图或原型帧
Footer    一行来源：调研报告、公开报道
```

### 每块怎么写

- 不做「它做 X，我们做 X」的左右并排，那读起来是照抄。用「它的机制」加「我们接哪层」。
- 结论优先用调研报告自己的结论，图只负责让它可见。
- 向成熟产品学的，直接写学的是谁。这是回答老板期待的方式。
- 被学的产品要比我们的部分显眼，它是主角。

## 配方 D · 用户声音图（回帖、评论、征集结果）

读者动作：看用户站哪边，和我们的候选对得上对不上。
图的任务：三段答完，不放与当前决策无关的发现。

### 骨架

```
01 排行榜   横向条形，前十，长尾一行灰字，绿色标出我们的候选
02 用户想要什么   三到四个主题，每个主题两句原声加 @ 用户名
03 对照我们的候选   每个候选一格：条数 加 一句用户怎么说；撞名事实做黄色 callout
Footer    来源、条数、抓取日期、噪音口径（带 UID 条数、复制文案组数）
```

- 不放 Hero 和 KPI 卡，老板时间有限，只给重点。
- 与当前决策无关的意外发现不进图，写在聊天里。
- 有奖征集的样本必须写「看方向不看绝对值」，帖子已提示的词少有人重复也要说明。
- 数字要能复核：抓取时间、总数、口径变化时注明「x 月 x 日口径」。

## 配方 E · 投票明细图（按选项看角色分布）

三个环形图并排，中间是票数，环上是角色占比，下面按角色列名字，颜色按角色统一。
底部一句「个人投票，不代表部门意见」。不写职位，只写方向和名字。

## 配方 F · 外部参考图（多模型评估）

```
Hero      「N 个模型独立评估：x 个选 A，y 个选 B」加 一句方法：同一 prompt，只给事实，不含意见
01 首选    每个被选中的候选一张卡：名字、票数、哪些模型
02 总分    表格，列是模型，行是候选，最后一列均分，每列最高分标绿；缺列的模型不计
03 取舍    两个色块：选 A 的模型反方一致说什么，选 B 的模型反方一致说什么
Footer    日期、模型清单、「参考，不是投票」
```
